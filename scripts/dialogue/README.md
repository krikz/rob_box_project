# Консоль диалога v2 - ход робота без ROS2 и без робота

Диалог РОББОКСа v2 - это `TurnEngine` (`rob_box_dialog.turn`): адресация по вейку, сессия, Tier-1 без LLM, срез тулов,
команда модели, исполнение действий владельцам, фраза об исходе от кода. Цикла `AgentCore` v1 в нём нет
(`dialog_v2_ports.py`). Консоль - терминальная оболочка над **сухим стендом** `scripts/dialog/dry_stand.py`: тем же,
на котором марафон идёт без робота (`scripts/dialog/dry_marathon.py`).

```bash
# 1. ключи (файл в git не попадает)
cp scripts/dialogue/.env.example scripts/dialogue/.env   # и вписать DEEPSEEK_API_KEY

# 2. запуск
scripts/dialogue/run.ps1          # Windows (PowerShell)
./scripts/dialogue/run.sh         # Linux / macOS / git-bash
```

```
› Сколько у тебя заряда?
🤖 Заряд восемьдесят семь процентов.
🔧 тулы: get_battery_level  →  исходы: get_battery_level: done
⚡ Tier-1: не сработал (ход к модели)
[ход 1 · вариант A · 3.4 с · вызовов LLM 2 · токены 9120 · касался: robot_status]
```

На каждый ход печатается: что сказал робот (`said`); вызванные тулы и их **исходы** (`done` / `rejected(причина)`:
«вызван» ещё не «исполнен»); сработал ли Tier-1 без LLM; число вызовов LLM; время хода; токены; каких владельцев
ход коснулся (`touched`).

## Что здесь настоящее, а что фейк

| | в консоли | на роботе |
|---|---|---|
| адресация, бэклог, сессия, Tier-1, срез тулов | настоящие (`rob_box_dialog`) | они же |
| цепочка LLM с мостом команд, системный промпт v2 | настоящие (`assemble_llm`, `master_prompt_compact.txt`) | они же |
| исполнитель действий (`V2Ports` + `Executor`), тулы памяти | настоящие, память - `VoiceMemory` в e2e-БД | они же, память `/data` |
| речь, музыка, голос/темп/громкость, лицо, статус, биометрия диктора | **фейковые владельцы**, отвечают событием сразу | настоящие |

Чего консоль не видит по построению: STT (опечатки распознавания), звук, настоящую биометрию, гонки ROS. Тул без
фейкового владельца (`NO_FAKE`) отвечает честным отказом `rejected(no_fake_owner)`, а не выдуманным успехом - это видно в
строке исходов. Про робота модель `<system_context>` получает ту же, что в ходе v2: снимок собирает код.

## Флаги

```bash
run.ps1 --providers deepseek                     # цепочка LLM (по умолчанию deepseek)
run.ps1 --providers deepseek --model deepseek-reasoner
run.ps1 --once "Сколько у тебя заряда?" --once "Робот, стоп"   # сценарий и выход
run.ps1 --db $HOME\.rob_box\console_memory.e2e.db   # память переживает запуск; боевая /data запрещена
run.ps1 --variant B                              # вариант «понимает модель» (см. ниже)
run.ps1 --wake-word                              # требовать «Робот, …», как на роботе
run.ps1 --speaker-name Кирилл                    # робот «узнал» вас по голосу (фейковая биометрия)
run.ps1 --debug                                  # срез тулов хода, DEBUG-логи, дамп запросов к LLM
```

`--model` ставится на всю цепочку (у фолбека с другим API своя модель не задаётся); без него - модель провайдера.
`--db` - файл e2e-памяти: «запомни, что я люблю чай» → перезапуск → «что ты обо мне помнишь?». Путь внутри `/data`
стенд отвергает (она общая с живыми людьми).

Реплика с консоли адресована роботу без вейка (как сообщение из Telegram/оператора); с `--wake-word` она идёт как голос
с микрофона: нет вейка - фраза копится в бэклоге, как на роботе.

## Голый текст и оформление кодом (эксперимент 29.10)

```bash
run.ps1 --speech-text plain                      # модель пишет голый текст: без кавычек, тире прямой речи, разметки
run.ps1 --voice-preview minimax,yandex,silero    # под репликой - что ушло бы в синтез каждому провайдеру
run.ps1 --normalizer rutextnorm                  # числа словами для тех, кто их не читает (Silero) и для такта
run.ps1 --bar-s 2.0                              # такт подложки, с: паузы рэпа по строкам куплета
```

Модель пишет одно для любого выхода; оформляет код (`scripts/dialog/speech_format.py`). Экран: реплика героя (у неё
голос роли, его дал код) - с тире и своим цветом. Голос: каждый провайдер доделывает только то, чего его сервис не
умеет сам - Yandex получает ударения `+` (silero-stress), Silero - числа словами и `<speak>`, MiniMax - текст как
есть; паузы такта - своей меткой (`<#x#>`, `sil<[мс]>`, `<break>`). Нормализатор и ударения - необязательные пакеты
(`rutextnorm`, `ru-normalizr`, `silero-stress`): нет пакета - шаг пропущен, и это видно в строке шагов. Промпт и
голос робота это не меняет.

## Варианты A и B (карточка #4163)

Только стенд, боевой код не менялся. `A` - как на роботе: Tier-1 целиком, срез тулов по словам фразы
(`tools_view.groups_for`) и состоянию. `B` - «понимает модель»: Tier-1 оставляет только безопасность (стоп, тишина,
«говори», новая сессия), срез тулов строится по снимку состояния без слов фразы. Подробности и замер «кто понимает
фразу» - `scripts/dialog/understanding_variants.py`, `scripts/dialog/understanding_measure.py`.

## Команды в консоли

| | |
|---|---|
| `/help` | справка |
| `/exit`, `/quit`, `/q`, Ctrl+C | выход |
| `/reset` | новая сессия: окно ходов и бэклог пусты (память остаётся) |
| `/state` | вариант, эпоха, играет ли музыка, тишина, файл памяти, вызовы LLM |
| `/tools` | срез тулов последнего хода |
| `/variant A\|B` | сменить вариант понимания на лету |
| `/facts` | что записано в e2e-памяти |

## Ключи

`chat.py` читает `scripts/dialogue/.env`, затем корневой `.env`, затем берёт то, что уже есть в окружении:
**экспортированная переменная всегда важнее файла**. Значения не печатаются. Файл `scripts/dialogue/.env` игнорируется
гитом (правило `.env` в корневом `.gitignore`):

```bash
git check-ignore -v scripts/dialogue/.env
```

Для `deepseek` нужен `DEEPSEEK_API_KEY`; для варианта C замера понимания - `JEV_API_KEY`.

## Требования

* Python 3.12+ (лаунчеры сами берут `.venv` из корня репозитория, если он есть); на 3.11 стенд тоже собирается.
* Пакеты: `openai`, `httpx`, `pyyaml` (зависимости `rob_box_llm`). ROS2 **не нужен** - `rclpy` не импортируется.

```bash
# если .venv в корне ещё нет
python3.12 -m venv .venv
.venv/Scripts/pip install -e src/rob_box_core -e src/rob_box_llm -e src/rob_box_harness
```

Пакеты `src/<пакет>/<пакет>` стенд ставит первыми в `sys.path` сам (`dry_stand.ensure_paths`): в worktree берётся код
перед глазами, а не editable-установка основного чекаута.
