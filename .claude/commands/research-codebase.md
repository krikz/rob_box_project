# Research Codebase

Ты — Research Lead для проекта **Rob Box** (автономный ровер, ROS 2 Humble + Zenoh).

## Твоя роль
Провести исследование кодовой базы по задаче ниже и создать документ с фактами.

**КРИТИЧНО:** ты ТОЛЬКО описываешь факты того, что есть. Никаких мнений, советов и рекомендаций по рефакторингу — только то, что СЕЙЧАС существует в коде.

## Аргументы
Принимается одно из двух:
- **ID задачи из tasks.json**: `TASK-035` — агент сам читает description и acceptance_criteria
- **Свободное описание**: текст задачи напрямую

$ARGUMENTS

## Если передан TASK-ID
Перед исследованием прочитай из `tasks.json`:
1. `description` — постановка задачи
2. `acceptance_criteria` — условия приёмки (определяют что искать)
3. `notes` — что уже реализовано (не ищи заново)
4. `dependencies` — проверь статус, не работай на незавершённых зависимостях

## Стек проекта
- **Python** (ROS 2 nodes, black 120, isort, flake8)
- **ROS 2 Humble** — nodes, topics, services, actions
- **Docker Compose** — сервисы на Main Pi (10.1.1.10) и Vision Pi (10.1.1.11)
- **Zenoh DDS** — middleware вместо стандартного RMW
- **Исходники:** `src/` — ROS 2 пакеты, `docker/` — Docker образы

## Процесс исследования

Запусти ПАРАЛЛЕЛЬНО субагентов (используй `Task` tool), каждый занимается своим направлением:

### Субагент 1: Архитектурный исследователь
Изучает общую архитектуру: какие пакеты/ноды/топики/сервисы задействованы в этой задаче.
Читает: `src/*/package.xml`, `src/*/setup.py`, ключевые `__init__.py`

### Субагент 2: Кодовый исследователь  
Ищет конкретные функции, классы, методы, относящиеся к задаче.
Читает конкретные `.py` файлы (не весь проект!). Находит точные строки, сигнатуры, зависимости.

### Субагент 3: Конфигурационный исследователь
Изучает конфиги, Docker Compose, переменные окружения, YAML, JSON5 параметры — всё что связано с задачей.
Читает: `docker/*/config/`, `docker/*/docker-compose*.yml`, `src/*/config/`

### Субагент 4: Тестовый исследователь
Находит существующие тесты, моки, фикстуры, CI конфиги, относящиеся к задаче.
Читает: `src/*/test/`, `.github/workflows/`, `local_test/`

## Правила для субагентов
- Используй более слабые модели если возможно (claude-3-5-haiku)
- Каждый субагент должен вернуть только ФАКТЫ: что нашёл, где находится (файл + строки), как это устроено
- НЕ предлагать изменений
- НЕ анализировать качество кода

## Выходной документ

После завершения всех субагентов создай файл:
`docs/research/$(date +%Y-%m-%d)-<краткое-название-задачи>-research.md`

### Структура документа:
```markdown
# Research: <название задачи>
**Дата:** YYYY-MM-DD  
**Задача:** <оригинальная задача>

## 1. Задействованные компоненты
- ROS 2 пакеты: ...
- Docker сервисы: ...
- Конфиги: ...

## 2. Ключевые файлы
| Файл | Строки | Что делает |
|------|--------|-----------|
| `src/.../node.py` | 45-120 | ... |

## 3. Архитектура текущего решения
(только факты: как сейчас устроено то, что относится к задаче)

## 4. Интерфейсы и контракты
(ROS 2 топики, сервисы, Docker env vars, YAML параметры)

## 5. Существующие тесты
(что покрыто, где лежит)

## 6. Зависимости и ограничения
(что зависит от чего, что нельзя сломать)
```

**ВАЖНО:** Не делай коммит, не меняй код — только создай research документ.
