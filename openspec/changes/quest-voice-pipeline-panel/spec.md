# quest-voice-pipeline-panel — 3D-панель голосового пайплайна на мостике

> Spec delta (ADR-0039): ADDED Requirements для панели голосового
> пайплайна оператора в WebXR-клиенте (W6-2, `dialogue-mode-spec` §3.6).
> Заменяет DOM-оверлей `ui/voice_presets_panel.ts` (AV-28 §P7).

## Purpose

На капитанском мостике оператор видит и настраивает свой голосовой путь:

```
мой голос → STT → LLM → TTS → динамик
```

Каждую ступень можно выключить или настроить, не снимая шлем: быстрый
доступ грипами остаётся (правый grip = рация, левый = робот-голос), а
тумблеры панели настраивают путь левого грипа (решение Шифу по Q9).

## ADDED Requirements

### Requirement: панель пайплайна — 3D-объект сцены, не DOM

Панель голосового пайплайна MUST рендериться в 3D-сцене мостика
(canvas-текстура на Plane-меше + отдельные меши-кнопки на слое указателя),
а не HTML-оверлеем. Единственный HTML/DOM-интерфейс клиента — форма
ввода PIN; после ввода PIN оператор попадает в VR-окружение, где все
панели расположены на мостике.

#### Scenario: вход через PIN → панель видна в VR

- GIVEN оператор ввёл корректный PIN и вошёл в immersive-vr
- WHEN оператор смотрит на правую часть мостика (+105°)
- THEN видна 3D-панель голосового пайплайна с цепочкой
  `голос → STT → LLM → TTS → динамик` и настройками ступеней
- AND на панели нет и не было DOM-оверлея с чипами пресетов

### Requirement: панель показывает всю цепочку пайплайна

Панель MUST визуально отражать все ступени пайплайна: `голос → STT →
LLM → TTS → динамик`. Состояние каждой ступени (`ВКЛ` / `ВЫКЛ` / `…`)
отображается на панели.

#### Scenario: ступени подсвечены по состоянию

- GIVEN панель видна и `voice_mode_ack` подтвердил `ttts_proxy`
- THEN STT показан как `ВКЛ`, LLM — как `ВЫКЛ`, TTS — голосом сервера
- AND до первого `voice_mode_ack` ступени показаны как `…` (неизвестно)

### Requirement: тумблеры ступеней шлют `voice_mode`

Тумблер STT/LLM MUST отправлять `voice_mode` с корректным wire-режимом:

- STT выкл → `passthrough` (рация);
- STT вкл + LLM выкл → `ttts_proxy` (STT→TTS дословно);
- STT вкл + LLM вкл → `llm_formalize` (стиль + язык вывода).

Подтверждение приходит `voice_mode_ack`; до него панель показывает
оптимистичное состояние клиента.

#### Scenario: оператор выключает STT

- GIVEN `voice_mode_ack` подтвердил `ttts_proxy` (STT вкл, LLM выкл)
- WHEN оператор кликает тумблер STT
- THEN клиент отправляет `voice_mode {mode:"passthrough"}`
- AND панель показывает STT `ВЫКЛ` до прихода `voice_mode_ack`

### Requirement: стиль речи и язык вывода меняются через `set_voice`

Секция «Стиль речи» MUST показывать шесть чипов пресетов
(`technical/street/caveman/business/philosopher/lenin`) и переключатель
языка (`ru/en`). Клик MUST отправлять `set_voice {preset?, language?}`
(маршрут AV-28 §P7 через супервизор), оптимистично обновляя панель до
`voice_set_ack`; `voice_set_nack` откатывает выбор. Текущий выбор
отображается короткой меткой `ST:PRESET@LANG` (чистая функция `renderHud`).

#### Scenario: смена стиля речи

- GIVEN панель получила `voice_presets` со списком пресетов и дефолтами
- WHEN оператор кликает чип «Ленин»
- THEN клиент отправляет `set_voice {preset:"lenin", language:<текущий>}`
- AND метка HUD меняется на `ST:LENIN` (или `ST:LENIN@RU`) до ack

#### Scenario: сервер отклонил стиль

- GIVEN оператор кликнул чип, клиент отправил `set_voice`
- WHEN сервер отвечает `voice_set_nack {reason:"invalid_voice_preset"}`
- THEN панель откатывает подсветку к последнему подтверждённому значению
- AND оператор видит ошибку «Не удалось сменить голос»

### Requirement: выбор голоса TTS открывает 3D-меню TTS picker

Кнопка ступени TTS MUST открывать существующее 3D-меню TTS picker
(AV-27) и показывать активный голос сервера (из `voice_list` /
`voice_set_ack`), не выдумывая значение до ответа сервера.

#### Scenario: открытие TTS picker с панели

- GIVEN панель видна и голос сервера — `alena`
- WHEN оператор кликает кнопку «ГОЛОС»
- THEN открывается 3D-меню TTS picker
- AND кнопка до этого показывала `ГОЛОС: alena`

## Out of scope

- Живая телеметрия ступеней (§3.7): статус «ждёт/работает/готово/ошибка»
  и задержки требуют новых wire-событий — отдельная карточка.
- Реальное применение `voice_mode` на `dialogue_node` вне `monitor`
  режима супервизора (W3-1/W3-2).
