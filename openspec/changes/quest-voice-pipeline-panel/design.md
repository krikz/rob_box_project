# Design: quest-voice-pipeline-panel

## Context

AV-28 §P7 сдал выбор стиля речи и языка как DOM-оверлей в нижнем-левом
углу экрана. Это противоречит целевой архитектуре мостика: в HTML должен
остаться только ввод PIN, всё остальное — 3D-панели в VR-окружении.
В immersive-vr DOM-оверлей не виден, поэтому голос из очков настроить
нельзя. На мостике уже была заготовка `styleStub` («Стиль: скоро») в
3D-панели режимов — её нужно было довести до полноценной панели
пайплайна (W6-2, `dialogue-mode-spec` §3.6).

## Goals / Non-Goals

- Goal: голосовой пайплайн виден и настраивается в 3D-сцене лучом
  контроллера; в HTML — только PIN.
- Goal: переиспользовать существующие паттерны сцены
  (`supervisor_panel.ts` — canvas + hitTest + меши-кнопки на слое
  указателя) и существующий wire-контракт (`set_voice`, `voice_mode`).
- Non-goal: живая телеметрия ступеней (§3.7) — нет wire-событий.
- Non-goal: серверные изменения — `rob_box_quest` не трогаем.

## Decisions

1. **Отдельная всегда видимая 3D-панель** `voice_pipeline_panel.ts`,
   симметричная панели режимов (−105°) справа (+105°, радиус 2.4 м).
   Не вкладываем в панель режимов: она и так плотная, а пайплайн —
   самостоятельная сущность.
2. **Один canvas + hitTest + прозрачные меши-кнопки** (как
   `supervisor_panel.ts`), а не отдельные тайлы (как `tts_picker_menu.ts`):
   раскладка детерминированная, чистая логика тестируется без WebGL.
3. **Тумблеры STT/LLM → `voice_mode`**, маппинг wire→тumbler один в один
   с `WIRE_TO_VOICE_INPUT_MODE` (`quest_node.py`): `passthrough` /
   `ttts_proxy` / `llm_formalize`. `off`/неизвестно → «…».
4. **Стиль/язык → `set_voice`** (AV-28 §P7). Серверный диспетчер уже
   различает AV-28 (preset ∈ whitelist стилей или language) и AV-27
   (voice_id). На клиенте ack парсится по whitelist'у `PRESET_ORDER`,
   чтобы AV-27 ack с `preset:"standard"` не затирал стиль.
5. **Кнопка TTS открывает TTS picker** (AV-27), голос берётся из
   `voice_list.active_voice` / `voice_set_ack` — клиент значение не
   выдумывает (ADR-0018).

## Risks / Trade-offs

- Оптимистичное состояние тумблеров до `voice_mode_ack` может разойтись
  с сервером — ack синхронизирует; до ack ступени честно показывают «…».
- Реальный эффект `voice_mode` ограничен режимом супервизора (monitor не
  применяет) — это W3-1/W3-2, не панель.
- Панель всегда видима и может перегружать поле зрения; оставили видимой,
  чтобы не прятать точку входа (в VR нет клавиатуры).
