# Phase 03.3 Context: MiMo-Code Patterns Adoption

## Problem Statement

MiMo v2.5 Pro has known issues: duplicate tool calls, empty responses, think-only outputs, and context overflow under long conversations. We already implemented **Layer 1 doom-loop protection** (hard block after N identical calls). But MiMo-Code has **additional resilience patterns** we should adopt.

## Source: Xiaomi MiMo-Code Repository

URL: https://github.com/XiaomiMiMo/MiMo-Code  
TypeScript agent framework by Xiaomi, battle-tested with their own MiMo models.

## Patterns to Port (4 total)

### Pattern 1: `classifyAssistantStep()` — Response Classification
**Source:** `packages/opencode/src/session/classify.ts` (lines 22-92)  
**Purpose:** Classify LLM response into actionable categories instead of binary "empty/not-empty"

```typescript
// Decision tree (priority order):
// 1. Pending client tool call → continue
// 2. No finish yet → continue
// 3. tool-calls finish → continue
// 4. Stale assistant → continue
// 5. Error finish → failed
// 6. Structured/summary → final
// 7. content-filter → filtered
// 8. Has usable text → final (or degraded if other finish)
// 9. Reasoning only → think-only
// 10. Empty → invalid
```

**Python port plan:**
- Pure function: `def _classify_response(result) -> str`
- Returns: "final" | "continue" | "think-only" | "invalid" | "failed"
- Integrate into `_agent_run()` after `Runner.run()` returns
- Use classification to decide: speak, retry with nudge, or fallback

### Pattern 2: `pressureLevel()` — Context Pressure Monitoring
**Source:** `packages/opencode/src/session/overflow.ts` (lines 0-53)  
**Purpose:** Monitor context window fill level and take graduated action

```typescript
// Levels:
// < 50%  → 0 (comfortable)
// < 70%  → 1 (warming up)
// < 85%  → 2 (high — inject memory flush nudge)
// >= 85%  → 3 (critical)
```

**Python port plan:**
- Estimate token count from message lengths (rough: 1 token ≈ 4 chars for English, 2 chars for Russian)
- Track `_context_pressure` level before each `_agent_run()`
- At level ≥ 2: inject system-reminder into conversation asking LLM to save important info to memory
- At level ≥ 3: trigger aggressive pruning (Pattern 4)

### Pattern 3: System-Reminder Injection
**Source:** `packages/opencode/src/session/prompt.ts` (lines 2311-2357)  
**Purpose:** Gentle LLM nudges via injected messages (softer than hard blocks)

Five injection types:
1. **Memory flush** (pressure ≥ 2): "Context filling up, save important learnings to memory now"
2. **Repeated step** (same tool ≥ 3x): "Your last N steps have been identical, try a different approach"
3. **Goal not satisfied** (LLM tries to stop early): "Your goal is not yet satisfied, keep working"
4. **Invalid output** (think-only/empty): "Produce a real response for the user"
5. **Max steps** (turn limit): "Give a final text-only response"

**Python port plan:**
- Inject as `{"role": "system", "content": "<system-reminder>...</system-reminder>"}` into input_list
- Memory flush: injected BEFORE `Runner.run()` when pressure ≥ 2
- Repeated step: injected WHEN doom-loop threshold-1 detected (soft warning before hard block)
- Invalid output: injected on retry after classify returns "think-only" or "invalid"

### Pattern 4: Progressive History Pruning (Head+Tail)
**Source:** `packages/opencode/src/session/prune.ts`  
**Purpose:** Smart truncation that preserves both command and result

```
Current:  output[:200] + "…[truncated]"           ← loses result context
New:      output[:1500] + "\n…[truncated]\n" + output[-1500:]  ← keeps head+tail
```

Constants from MiMo-Code:
- `SOFT_TRIM_THRESHOLD = 4096` chars → truncate
- Keep head 1536 + tail 1536
- `PRUNE_PROTECTED_TOOLS = ["skill"]` (never pruned)

**Python port plan:**
- Upgrade `_truncate_history_outputs()` to use head+tail when output > 2000 chars
- Keep head 1500 + tail 1500 for long outputs
- Short outputs (< 2000 chars) left unchanged
- Skill tool outputs (handle_music etc.) get larger budget (3000 chars each side)

## Non-Goals (explicitly OUT of scope)

- ❌ Provider-specific branches (no `if model == "mimo"`)
- ❌ Permission system (MiMo-Code's allow/deny/ask — overkill for voice assistant)
- ❌ Checkpoint-based recovery (too complex for short voice conversations)
- ❌ Token-accurate counting (rough estimation is fine)
- ❌ Modifying OpenAI Agents SDK internals

## Risk Assessment

| Risk | Likelihood | Mitigation |
|------|-----------|------------|
| System-reminder injection confuses MiMo | Low | Use standard `<system-reminder>` format MiMo-Code uses |
| Pressure estimation inaccurate | Medium | Log both estimated and actual; tune thresholds |
| Head+tail truncation increases context size | Medium | Monitor token counts; adjust 1500 limit if needed |
| Regression in DJ mode | Low | Test DJ set explicitly in plan 03.3-04 |
