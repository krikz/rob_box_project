## Gray Area Decisions

### 1. Melody Examples / Library Architecture

**Problem**: В `music_skill_prompt.txt` есть огромная секция "KNOWN MELODY LIBRARY" (~80 строк) содержащая ТОЛЬКО Imperial March (Star Wars). Это biasит модель — она генерирует одинаковые треки.

**Decision**:
- ✅ Вынести ВСЕ мелодии из промпта в библиотеку (`TrackLibrary`)
- ✅ Добавить разделение: **presets** (read-only, наши курированные треки) vs **user saves** (сохранённые пользователем)
- ✅ В промпте оставить только инструкцию: "Если пользователь просит конкретный трек — вызови `list_tracks` и `load_track`"
- ✅ Добавить 5-6 разнообразных presets из Strudel/FoxDot паттернов (jazz, techno, ambient, hip-hop, folk, acid)
- ✅ Star Wars остаётся как один из presets, НЕ как единственный пример в промпте

**Architecture**:
```
TrackLibrary (SQLite)
├── presets/        ← type='preset', read-only for LLM
│   ├── star_wars_march
│   ├── jazz_groove_96bpm
│   ├── acid_techno_136bpm
│   ├── ambient_dreamy_88bpm
│   ├── hiphop_boom_bap
│   └── folk_fiddle_reel
└── user_saves/     ← type='user', read-write
    └── (any user-saved tracks)
```

**Source for presets**: Strudel patterns from `terryds/awesome-strudel` (https://github.com/terryds/awesome-strudel) — адаптировать к Renardo синтаксису.

### 2. MiMo Prompt Strategy

**Problem**: MiMo v2.5 Pro генерирует одинаковые треки из-за bias в промптах.

**Decision**:
- ✅ Промпты — основной инструмент (гибко, быстро итерируем)
- ✅ Код — как safety net (только для critical bugs)
- ✅ Убрать Star Wars bias из промпта (~80 строк → в библиотеку)
- ✅ Добавить `frequency_penalty=0.3` / `presence_penalty=0.2` в MiMo API calls для борьбы с повторением
- ✅ Рандомизировать Scale/Root/BPM в DJ transitions через промпт-инструкции

**MiMo API Findings**:
- `tool_choice`: только `auto` — confirmed (https://mimo.mi.com/docs/en-US/api/chat/openai-api)
- `finish_reason`: `stop`, `length`, `tool_calls`, `content_filter`, `repetition_truncation`
- `frequency_penalty`: [-2.0, 2.0] — penalizes repeated tokens
- `presence_penalty`: [-2.0, 2.0] — encourages new topics
- `thinking`: default `enabled` for mimo-v2.5-pro, мы ставим `disabled`

### 3. DJ_AUTO Retry Policy

**Problem**: MiMo иногда возвращает пустой ответ при DJ transition. `set_dj_mode` никогда не вызывается.

**Decision**:
- ✅ Детектить пустой ответ через `finish_reason` + проверка `content` и `tool_calls`
- ✅ Retry 1 раз с тем же промптом
- ✅ Если 2-й раз пусто — fallback: продолжить текущий трек без transition
- ✅ Логировать retry события для диагностики

**Implementation** (code-level safety net):
```python
# In dialogue_node.py — music tool call handler
if not response.content and not response.tool_calls:
    # Empty MiMo response — retry once
    logger.warning("MiMo empty response on music call, retrying...")
    response = await retry_music_call(original_messages)
    if not response.content and not response.tool_calls:
        logger.error("MiMo empty response after retry, skipping transition")
        return "continue_current_track"
```

### 4. UAT Scoring Thresholds

**Problem**: ROADMAP определяет ≥70% weighted average = pass. Нужны ли per-criteria minimums?

**Decision**:
- ✅ НЕТ жёстких per-criteria порогов
- ✅ Пользователь решает после просмотра UAT-оценок
- ✅ Просто presents scores → user decides: pass / iterate / fail

**UAT Framework** (7 criteria, weighted):
| # | Criterion | Weight | Description |
|---|-----------|--------|-------------|
| 1 | Musical Quality | 25% | Does the music sound good? Varied? Interesting? |
| 2 | Constraint Compliance | 20% | Follows Renardo rules (amp, layers, samples) |
| 3 | DJ Routing | 15% | Correct use of set_dj_mode, transitions |
| 4 | MC Quality | 15% | Compositor speaks naturally, not too much |
| 5 | Theme Adherence | 10% | Matches requested mood/theme |
| 6 | search_samples Usage | 10% | Uses search_samples for unknown letters |
| 7 | Tool Call Correctness | 5% | Correct parameters, no hallucinations |

### 5. Iteration Exit Criteria

**Problem**: Max 2 итерации. Когда останавливаемся раньше?

**Decision**:
- ✅ Пользователь решает после каждой итерации
- ✅ Показываем UAT-оценки → user decides: достаточно / ещё итерация
- ✅ Max 2 итерации — hard limit
