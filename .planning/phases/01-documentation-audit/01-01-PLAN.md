#### Task 01-01-06: Переписать TROUBLESHOOTING.md — убрать устаревший RTAB-Map кейс, добавить актуальные

**Type**: edit  
**Autonomous**: true  
**Files modified**:
- `docs/guides/TROUBLESHOOTING.md`

**Description**:

В файле `docs/guides/TROUBLESHOOTING.md`:

1. **Найти и удалить/обновить** основной кейс "RTAB-Map не получает данные от камеры (OAK-D)". Этот кейс неактуален — RTAB-Map сейчас работает в LiDAR-only режиме (`depth:=false`). Заменить на:
   ```
   ### RTAB-Map: нет данных от LiDAR
   
   **Симптомы**: `/scan` топик не публикуется, rtabmap не строит карту.
   
   **Причины и решения**:
   1. LiDAR не подключён физически или неправильный USB-порт
   2. Контейнер `lslidar` не запущен: `docker logs lslidar`
   3. Сеть: убедиться что `network_mode: host` в docker-compose
   4. Проверить: `ros2 topic hz /scan` — должен быть ~10 Hz
   ```

2. **Добавить кейс "Zenoh: нет связи между Pi"**:
   ```
   ### Zenoh: Vision Pi не видит Main Pi топики
   
   **Симптомы**: `ros2 topic list` на Vision Pi не показывает топики Main Pi.
   
   **Причины и решения**:
   1. `docker logs zenoh-router-vision` — искать ошибки подключения
   2. Убедиться что Main Pi zenoh-router запущен: `docker ps | grep zenoh-router`
   3. Проверить конфиг: `ZENOH_CONFIG=/config/zenoh_session_config.json5`
   4. Сеть: пинг `10.1.1.10` с Vision Pi должен проходить
   5. Дополнительно: `docs/fixes/ZENOH_FIX_SUMMARY_2025-11-10.md`
   ```

3. **Добавить кейс "VESC: timeout / нет ответа"**:
   ```
   ### VESC: контроллер не отвечает (timeout)
   
   **Симптомы**: `ros2-control` контейнер unhealthy, `/cmd_vel` не отрабатывается.
   
   **Причины и решения**:
   1. VESC не подключён или неверный `/dev/ttyACM*` порт
   2. `docker logs ros2-control` — искать "VESC timeout" или "connection refused"
   3. Проверить устройство: `ls /dev/ttyACM*` на Main Pi
   4. VESC firmware: убедиться что прошит корректно (команда: `vesc_tool`)
   5. Перезапустить: `docker compose restart ros2-control`
   ```

4. **Добавить кейс "Perception: контейнер unhealthy"**:
   ```
   ### Perception: health_monitor показывает ошибки
   
   **Симптомы**: `docker ps` показывает `perception` unhealthy.
   
   **Причины и решения**:
   1. `docker logs perception` — найти последние ошибки
   2. Часто причина: нет Zenoh соединения с Vision Pi (решить Zenoh кейс выше)
   3. Перезапустить: `docker compose restart perception`
   ```

**Verification**:
