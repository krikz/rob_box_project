    СТРУКТУРА СКРИПТА (разделы в порядке):

    1. КОНСТАНТЫ:
    - REPO = "krikz/rob_box_project"
    - MILESTONE_MAP = {"M1": N1, "M2": N2, "M3": N3} — реальные числа из milestone-numbers.md (не API запрос)
    - CATEGORY_LABEL_MAP — маппинг category из tasks.json → GitHub label:
      bugfix → "bug", bug → "bug", stub → "type:stub", improvement → "enhancement",
      functional → "type:functional", infrastructure → "type:infrastructure",
      testing → "type:testing", documentation → "documentation", security → "type:security"
    - PRIORITY_LABEL_MAP — маппинг priority → GitHub label:
      critical → "critical", high → "priority:high", medium → "priority:medium", low → "priority:low"
    - TECH_DEBT_CATEGORY_MAP — маппинг TD ID prefix → label:
      "BG" → "bug", "TD" → "type:tech-debt", "SEC" → "type:security",

    - COMMON_LABELS = ["ai-generated", "source:gsd"]

    2. ФУНКЦИЯ check_idempotency(issue_id: str) → int | None:
    Запустить: `gh issue list --search "{issue_id} in:title" --repo {REPO} --json number --jq '.[0].number // empty'`
    Если возвращает непустую строку — вернуть int(число). Иначе — вернуть None.
    Использовать subprocess.run с capture_output=True, text=True.

    3. ФУНКЦИЯ format_issue_body(source: str, original_id: str, description: str, acceptance_criteria: list[str] | None = None, file_refs: str | None = None) → str:
    Формирует Markdown body по GH-1 template из CONTEXT.md:
    ```
    ## Description
    {description}

    ## Acceptance Criteria
    {checklist — каждый элемент списка как "- [ ] {item}"}

    ## File References
    {file_refs если есть, иначе пропустить секцию}

    ## Source
    Migrated from: {source}
    Original ID: {original_id}

    ---
    > ⚠️ _This issue was created by AI (GSD workflow). Label: `ai-generated`_
    ```

    4. ФУНКЦИЯ create_issue(title: str, body: str, labels: list[str], milestone: int | None = None) → int:
    Запустить gh issue create с флагами:
    `gh issue create --title "{title}" --body "{body}" --label "{','.join(labels)}" [--milestone N] --repo {REPO} --json number --jq '.number'`
    Использовать tempfile для body (записать в tmp файл, передать как --body-file). НЕ передавать body напрямую в shell — избегать shell injection.
    Вернуть номер созданного Issue (int).

    5. ФУНКЦИЯ migrate_tasks_json() → dict[str, int]:
    Читает tasks.json. Для каждой задачи:
    a) check_idempotency(task['id']) — если Issue уже существует, пропустить, записать в маппинг
    b) Формировать title: "[{task['id']}] {task.get('description', task.get('title', ''))[:80]}"
       Для TASK-051 и TASK-052: использовать title поле из tasks.json если есть
    c) Собрать labels: [CATEGORY_LABEL_MAP[category], PRIORITY_LABEL_MAP[priority]] + COMMON_LABELS
       + milestone:MX label (если есть поле milestone в задаче)
       + "status:in-progress" если status == "in-progress"
    d) Формировать body через format_issue_body: source="tasks.json", original_id=task['id'],
       description=task['description'], acceptance_criteria=task.get('acceptance_criteria', []),
       file_refs=f"{task['file']}:{task['line']}" если поля есть
    e) Добавить раздел "## Dependencies" в body если task['dependencies'] не пуст
    f) Добавить notes в ## Description если task['notes'] присутствует
    g) Получить milestone_number = MILESTONE_MAP.get(task.get('milestone', ''))
    h) create_issue(title, body, labels, milestone_number) → issue_number
    i) Если task['status'] == 'done': gh issue close {issue_number} --repo {REPO}
    j) Сохранить в маппинг: {task['id']: issue_number}
    Вернуть маппинг.

    6. ФУНКЦИЯ migrate_tech_debt(task_id_to_issue: dict[str, int]) → None:
    Читает TECH_DEBT.md как text. Для каждого пункта который НЕ в SKIP_TASK_IDS и имеет disposition != "accept":
    - Пункты BG-1..BG-6 (covered by tasks): добавить comment к существующему Issue:
      `gh issue comment {issue_number} --body "Cross-reference: {td_id} — {td_description}" --repo {REPO}`
    - Остальные пункты: создать новый Issue с:
      title: "[{td_id}] {description[:80]}"
      labels: [TECH_DEBT_CATEGORY_MAP[prefix], priority_label] + COMMON_LABELS + milestone_label
      body: format_issue_body(source="TECH_DEBT.md", original_id=td_id, ...)

    ВАЖНО — SEC-1 (Hardcoded SSH password в CI/CD): тело Issue должно описывать ПРОБЛЕМУ (hardcoded credentials в CI/CD workflow файлах), но НЕ включать реальный пароль. Описание: "CI/CD workflows contain hardcoded SSH credentials. See docs/deployment/ for affected files."

    7. ФУНКЦИЯ save_stub_mapping(task_map: dict[str, int]) → None:
    Записать JSON файл scripts/stub_mapping.json:
    {"TASK-051": task_map.get("TASK-051"), "TASK-052": task_map.get("TASK-052")}
    Использовать json.dump с indent=2.

    8. MAIN:
    Порядок вызовов:
    a) task_map = migrate_tasks_json()
    b) migrate_tech_debt(task_map)
    c) save_stub_mapping(task_map)
    d) Вывести в stdout: "Migration complete. Issues created: {count}. stub_mapping.json written."
    e) Вывести маппинг TASK-051 и TASK-052 issue numbers для Task 3.

    ERROR HANDLING: subprocess.CalledProcessError → вывести stderr + exit(1).
    Не использовать os.system(), только subprocess.run(check=True).
    Не использовать shell=True для пользовательских данных — все аргументы как list.
    Для body использовать tempfile.NamedTemporaryFile и --body-file флаг.
