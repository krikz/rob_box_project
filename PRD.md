## 1. Обзор и цели

### 1.1. Описание продукта

**РОББОКС** — автономный колёсный робот для использования внутри помещений, построенный на ROS 2 Humble + Zenoh DDS.  
Платформа является **многоцелевой образовательной/демонстрационной системой**, на которой реализуются бизнес-сценарии:

| Сценарий | Описание |
|----------|----------|
| **Робот-гид** | Сопровождение людей, рассказ о локациях, навигация к точкам интереса |
| **Патрулирование** | Автономный обход маршрутов по расписанию или триггеру |
| **Почтовый курьер** | Доставка предметов из точки A в точку B по заказу |
| **Кастомный процесс** | Расширяемый движок сценариев для новых бизнес-процессов |

### 1.2. Ключевые цели

- **Автономность**: робот самостоятельно строит карту, локализуется, планирует маршрут и выполняет задачи
- **Голосовое взаимодействие**: LLM-ассистент с STT/TTS для естественного общения с людьми
- **Визуальная выразительность**: 381 RGB LED-матрица для индикации состояний и эмоций
- **Управляемость**: веб-панель оператора + клиентское приложение для бизнес-процессов
- **Образовательность**: открытая архитектура на ROS 2 для изучения роботехнических систем

### 1.3. Ключевые метрики (MVP)

| Метрика | Target |
|---------|--------|
| Точность навигации до waypoint | ≤ 15 см |
| Время построения карты помещения 100 м² | ≤ 10 мин |
| Время отклика голосового ассистента (STT → TTS) | ≤ 3 сек |
| Uptime системы при патрулировании | ≥ 95% за 4ч |
| Задержка управления через веб-панель | ≤ 200 мс |

## 2. Целевая аудитория

### 2.1. Операторы системы

**Технический оператор** — специалист, запускающий, настраивающий и контролирующий робота.  
- Доступ к веб-панели оператора (full control)
- Управление картой: создание/редактирование waypoints и зон
- Запуск/остановка сценариев
- Просмотр телеметрии, логов, статуса сенсоров

### 2.2. Конечные пользователи (клиенты)

**Конечный пользователь** — персонал, посетитель, сотрудник, взаимодействующий с роботом в рамках бизнес-процесса.  
- Голосовые команды роботу напрямую
- Создание заказа через клиентское веб-приложение (например: "доставь документ в кабинет 205")
- Получение уведомлений о статусе задачи

### 2.3. Разработчики / интеграторы

- Создание новых сценариев (plugins)
- Расширение API бизнес-процессов
- Интеграция новых сенсоров/актуаторов

## 4. Функциональные требования

### 4.1. F-NAV: Автономная навигация и картография

**F-NAV-01: Построение карты (SLAM)**
- Создание 2D и 3D карты помещения с RTAB-Map (OAK-D + LSLIDAR)
- Сохранение карты в файл (`.db`) для повторного использования
- Acceptance criteria:
  - Карта помещения 100 м² строится без артефактов
  - После перезапуска RTAB-Map локализация работает на сохранённой карте
  - Точность: ≤ 10 см drift за 10 мин работы

**F-NAV-02: Локализация на сохранённой карте**
- Загрузка существующей карты при старте
- AMCL/ICP локализация в реальном времени
- Acceptance criteria:
  - Локализация устанавливается за ≤ 30 сек после запуска
  - Потеря локализации → автоматическая переинициализация

**F-NAV-03: Автономное движение к waypoint**
- Nav2 BT Navigator с планировщиком маршрутов
- Дистанция до цели: точность ≤ 15 см, угол ≤ 10°
- Acceptance criteria:
  - Отправка `ros2 action send_goal /navigate_to_pose` выполняется успешно
  - Робот объезжает статичные препятствия
  - При недостижимости цели → статус FAILURE с причиной

**F-NAV-04: Разметка карты (Waypoints & Zones)**
- Интерфейс создания именованных точек (`HOME`, `DOCK`, `LOCATION_A`, etc.)
- Типы точек: `waypoint` | `delivery_zone` | `charging_dock` | `patrol_point`
- Хранение в БД, привязка к карте (map_id + x, y, yaw)
- Acceptance criteria:
  - Оператор добавляет точку через веб-панель кликом на карту
  - Точка сохраняется и доступна при следующем запуске
  - Робот успешно едет к именованной точке через API

**F-NAV-05: Patrol сценарий**
- Циклический обход списка waypoints по расписанию или одиночный проход
- Запуск/остановка через API или веб-панель
- Acceptance criteria:
  - Робот объезжает все точки маршрута в заданном порядке
  - Список маршрута настраивается без перезапуска

---

### 4.2. F-VOICE: Голосовой ассистент

**F-VOICE-01: STT (Speech-to-Text)**
- Распознавание русскоязычной речи через ReSpeaker (6-mic array)
- Offline-first: Vosk (`vosk-model-ru`) — основной
- VAD (Voice Activity Detection) для исключения фоновых шумов
- Acceptance criteria:
  - WER ≤ 25% в условиях офисного шума
  - Время распознавания фразы ≤ 1 сек

**F-VOICE-02: LLM диалог (Multi-provider)**
- Провайдеры (по приоритету fallback):
  1. Qwen (Alibaba Cloud) — основной
  2. DeepSeek — первый fallback
  3. Ollama (локальная LLM) — offline fallback
- Системный промпт: роль робота, текущий сценарий, контекст локации
- Батчинг запросов (timeout 2.5 сек)
- Acceptance criteria:
  - При недоступности провайдера 1 → автоматический переход к провайдеру 2 за ≤ 5 сек
  - Ответ на вопрос "который час?" корректный (time awareness)
  - Контекст диалога сохраняется в пределах сессии (≥ 10 реплик)

**F-VOICE-03: TTS (Text-to-Speech)**
- Silero TTS (offline) для синтеза речи на русском
- Синхронизация chunk'ов (dialogue_id) для исключения перемешивания сессий
- Вывод через USB-динамик (Vision Pi)
- Acceptance criteria:
  - Задержка от получения текста до начала воспроизведения ≤ 500 мс
  - Нет артефактов перемешивания при прерывании диалога

**F-VOICE-04: Wake word / Push-to-talk**
- Активация по ключевому слову (например "Роббокс") или кнопке
- Acceptance criteria:
  - False positive rate ≤ 1 раз в 10 мин в фоновом режиме
  - Реакция на wake word ≤ 1 сек (LED indyкация + звуковой сигнал)

**F-VOICE-05: Интеграция голоса с навигацией**
- Команды: "Поедь к [локация]", "Останови", "Что ты делаешь?"
- NLU для извлечения намерений и сущностей из фраз
- Acceptance criteria:
  - Команда "поедь к столовой" → навигация к waypoint `CAFETERIA`
  - При неизвестной локации → вежливый ответ с просьбой уточнить

### 4.3. F-LED: Визуальная индикация

**F-LED-01: Система состояний**

| Состояние | Анимация | Описание |
|-----------|----------|----------|
| `IDLE` | Медленное дыхание синий | Ожидание команд |
| `NAVIGATING` | Бегущие огни зелёный | Движение к цели |
| `LISTENING` | Пульсация белый | Ожидает голосовой команды |
| `THINKING` | Вращение жёлтый | Обработка запроса LLM |
| `SPEAKING` | Waveform бирюза | Воспроизведение TTS |
| `ERROR` | Мигание красный | Ошибка, требует внимания |
| `CHARGING` | Заполнение зелёный снизу вверх | Зарядка на докстанции |
| `DELIVERING` | Пульсация оранжевый | Выполнение доставки |

- Acceptance criteria:
  - Смена анимации за ≤ 50 мс при изменении состояния
  - Приоритеты: `ERROR` > `SPEAKING` > `THINKING` > всё остальное

### 4.4. F-OPS: Веб-панель оператора

**F-OPS-01: Дашборд состояния**
- Reалтайм карта с позицией робота (WebSocket → Foxglove-like viewer или leaflet.js + ROS bridge)
- Статусы всех сервисов (ROS nodes health)
- Телеметрия: заряд батареи, температура CPU/GPU, состояние сенсоров
- Acceptance criteria:
  - Обновление позиции на карте ≤ 200 мс
  - Панель работает в Chrome/Firefox без плагинов

**F-OPS-02: Ручное управление (телеоп)**
- Геймпад / drag-to-drive / WASD кнопки → `/cmd_vel`
- Стриминг видео с OAK-D камеры (MJPEG/WebRTC, ≤ 5 FPS для мобильного)
- Acceptance criteria:
  - Задержка управления (нажатие кнопки → движение робота) ≤ 200 мс при WiFi
  - Emergency stop кнопка останавливает робота за ≤ 100 мс

**F-OPS-03: Управление картой**
- Визуализация occupancy grid + 3D point cloud
- Добавление / редактирование / удаление waypoints на карте
- Назначение маршрутов патрулирования
- Acceptance criteria:
  - Добавление waypoint кликом на карте сохраняется в БД
  - Список точек отображается как слой поверх карты

**F-OPS-04: Управление сценариями**
- Запуск/остановка сценария (guide / patrol / courier / custom)
- Текущее задание робота (цель, прогресс, статус)
- История выполненных заданий
- Acceptance criteria:
  - Оператор запускает patrol-сценарий нажатием кнопки + выбором маршрута
  - Статус задания обновляется в реалтайм

### 4.5. F-CLIENT: Клиентское веб-приложение

**F-CLIENT-01: Создание заказа на доставку**
- Пользователь выбирает: откуда (точка отправки), куда (точка назначения)
- Опционально: сообщение получателю (голосом на доставке)
- Acceptance criteria:
  - Заказ создаётся за ≤ 5 кликов
  - Статус заказа обновляется в реалтайм (pending → in_progress → delivered)
  - Уведомление получателю при прибытии робота

**F-CLIENT-02: Отслеживание статуса**
- Реалтайм трекинг позиции робота на упрощённой карте
- Push-уведомление (браузер) при прибытии

**F-CLIENT-03: Голосовой вызов гида**
- Кнопка "Пригласить гида" → робот едет к пользователю
- Acceptance criteria:
  - Робот прибывает к запрашивающей точке ≤ 3 мин (на 100 м²)

### 4.6. F-SCENARIO: Движок сценариев

**F-SCENARIO-01: Базовый движок задач**
- Задача (Task) = сценарий + параметры + статус + история
- Очередь задач с приоритетами
- State machine: `QUEUED → EXECUTING → COMPLETED | FAILED | CANCELLED`
- Acceptance criteria:
  - Одновременно выполняется максимум 1 задача (остальные в очереди)
  - При аварийной остановке задача переходит в `FAILED` с причиной

**F-SCENARIO-02: Сценарий "Доставка"**
1. Принять задание (pickup_point, delivery_point, optional_message)
2. LED анимация DELIVERING
3. Ехать к pickup_point → ждать загрузки (timeout 60 сек)
4. Ехать к delivery_point → голосовое уведомление получателю
5. Ждать извлечения (timeout 60 сек) → вернуться на HOME
- Acceptance criteria:
  - Полный цикл доставки работает без вмешательства оператора

**F-SCENARIO-03: Сценарий "Патрулирование"**
1. Принять маршрут (список waypoints + repeat=True/False)
2. Обходить точки по порядку, делать паузу на каждой
3. Опционально: LLM комментарий на каждой точке
- Acceptance criteria:
  - Маршрут из 5 точек проходится без ошибок 3 раза подряд

**F-SCENARIO-04: Сценарий "Гид"**
1. Сопровождать пользователя к указанной локации
2. Голосовой рассказ о пунктах по пути (контекст из базы локаций)
3. По прибытии: вернуться на HOME или ждать следующей команды
- Acceptance criteria:
  - Пользователь может запросить гида голосом или через клиент-приложение

## 6. Модель данных

### 6.1. Карта и точки

```sql
-- Карты (RTAB-Map databases)
maps {
  id: UUID PRIMARY KEY
  name: TEXT NOT NULL        -- "office_floor_1"
  file_path: TEXT            -- path to .db file
  created_at: TIMESTAMP
  is_active: BOOLEAN DEFAULT false
}

-- Именованные точки на карте
waypoints {
  id: UUID PRIMARY KEY
  map_id: UUID REFERENCES maps(id)
  name: TEXT NOT NULL        -- "CAFETERIA", "ROOM_205"
  display_name: TEXT         -- "Столовая", "Кабинет 205"
  type: ENUM(waypoint, delivery_zone, charging_dock, patrol_point)
  x: FLOAT                   -- meters in map frame
  y: FLOAT
  yaw: FLOAT                 -- radians
  description: TEXT          -- для LLM контекста гида
  created_at: TIMESTAMP
}

-- Маршруты патрулирования
patrol_routes {
  id: UUID PRIMARY KEY
  name: TEXT
  waypoint_ids: JSON        -- ordered list of waypoint UUIDs
  repeat: BOOLEAN
  dwell_time_sec: INT DEFAULT 5  -- пауза на каждой точке
}
```

### 6.2. Задачи (Tasks)

```sql
tasks {
  id: UUID PRIMARY KEY
  scenario: ENUM(delivery, patrol, guide, custom)
  status: ENUM(queued, executing, completed, failed, cancelled)
  priority: INT DEFAULT 5       -- 1=highest
  params: JSON                  -- сценарно-зависимые параметры
  created_by: TEXT              -- "operator" | "client" | "voice" | "schedule"
  created_at: TIMESTAMP
  started_at: TIMESTAMP
  finished_at: TIMESTAMP
  error_message: TEXT
  progress: JSON               -- {"current_waypoint": "ROOM_205", "step": "delivering"}
}

-- Пример params для delivery:
-- {"pickup": "ROOM_101", "delivery": "ROOM_205", "message": "Документы для Ивана Петровича"}

-- Пример params для patrol:
-- {"route_id": "uuid", "repeat": true}
```

### 6.3. Пользователи

```sql
users {
  id: UUID PRIMARY KEY
  username: TEXT UNIQUE
  role: ENUM(operator, client)
  password_hash: TEXT
  created_at: TIMESTAMP
}
```

## 9. Безопасность

### 9.1. Сетевая

- Task API доступен только в локальной сети (10.1.1.x) или через VPN
- Zenoh ROS 2 трафик только по Ethernet (eth0), не выходит в WiFi
- Облачный Zenoh (`zenoh.robbox.online`) — только для удалённой диагностики, RO-доступ

### 9.2. Аутентификация

- JWT (access token 15 мин + refresh token 7 дней)
- Роли: `operator` (полный доступ) / `client` (только задачи + статус)
- Операции `emergency_stop` и `cmd_vel` — только `operator`

### 9.3. Физическая безопасность

- Emergency stop: программный (API) + аппаратный (физическая кнопка на корпусе)
- Max velocity limit: 0.5 м/с в помещениях (параметр Nav2)
- Obstacle detection timeout: если Nav2 застрял > 30 сек → задача FAILED, робот останавливается

## 11. Риски и способы решения

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Nav2 одометрия нестабильна после смены колёс | Высокая | Критичное | Параллельно тестировать IMU fusion; оставить ручной режим как fallback |
| RTAB-Map теряет локализацию на однородных поверхностях | Средняя | Высокое | Добавить AprilTag маркеры как коррекция; настроить loop closure parameters |
| LLM API недоступен (outage) | Средняя | Среднее | Ollama offline fallback; canned responses для базовых команд |
| WiFi деградация → потеря управления | Средняя | Высокое | E-stop по таймауту heartbeat (5 сек без сигнала → стоп) |
| WebRTC/MJPEG видео задержка | Низкая | Низкое | MJPEG достаточен (5 FPS), WebRTC как улучшение |
| Перегрев RPi5 при SLAM | Средняя | Среднее | Мониторинг температуры + throttling alerts + кулеры |
