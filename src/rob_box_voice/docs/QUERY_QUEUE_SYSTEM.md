# Query Queue System - Система накопления запросов

## 📋 Обзор

**Проблема:** Когда пользователь подряд задаёт много вопросов роботу, они складываются в стек и обрабатываются по очереди, что приводит к неактуальным ответам.

**Решение:** Система накопления запросов (Query Queue System) собирает несколько последовательных вопросов в очередь и обрабатывает их одним пакетным запросом к LLM.

## 🎯 Преимущества

✅ **Актуальность ответов** - робот отвечает на все вопросы сразу, а не по очереди  
✅ **Экономия API запросов** - один запрос вместо нескольких  
✅ **Лучший контекст** - LLM видит все вопросы сразу и может дать более связный ответ  
✅ **Естественный диалог** - пользователь может задавать вопросы не дожидаясь ответа  

## 🔧 Как это работает

### 1. Накопление запросов

Когда приходит запрос от STT:
- Запрос добавляется в очередь `pending_queries`
- Запускается таймер накопления (по умолчанию 2.5 секунды)
- Если LLM уже обрабатывает запрос - новые запросы просто добавляются в очередь

```python
self.pending_queries.append(user_message)
self.last_query_time = time.time()
```

### 2. Проверка и обработка очереди

Когда таймер срабатывает или LLM завершает обработку:
- Проверяется: прошло ли достаточно времени с последнего запроса
- Если да - все накопленные запросы объединяются в один контекст
- Отправляется один запрос к LLM с объединённым контекстом

```python
def _check_and_process_queue(self):
    queries_to_process = self.pending_queries.copy()
    self.pending_queries.clear()
    
    if len(queries_to_process) > 1:
        combined_message = f"У меня несколько вопросов ({len(queries_to_process)} штук), отвечай на них все сразу по порядку:\n"
        for i, query in enumerate(queries_to_process, 1):
            combined_message += f"{i}. {query}\n"
```

### 3. Автоматическая цепочка обработки

После завершения ответа LLM:
- Проверяется очередь - есть ли ещё накопленные запросы
- Если есть - автоматически запускается следующая обработка
- Цикл продолжается пока очередь не опустеет

```python
# После завершения LLM ответа
self.llm_processing = False
if self.pending_queries:
    self._check_and_process_queue()
```

## ⚙️ Конфигурация

### Параметр ROS 2

```yaml
dialogue_node:
  query_accumulation_timeout: 2.5  # секунд для накопления запросов
```

### Настройка в коде

```python
self.declare_parameter("query_accumulation_timeout", 2.5)
self.query_accumulation_timeout = self.get_parameter("query_accumulation_timeout").value
```

### Рекомендуемые значения

- **2.0 секунды** - быстрая реакция, меньше накопления
- **2.5 секунды** (по умолчанию) - баланс между накоплением и скоростью
- **3.0 секунды** - больше накопления, медленнее реакция

## 📊 Примеры использования

### Пример 1: Один запрос

**Пользователь:** "Привет, как дела?"

**Очередь:** `["Привет, как дела?"]`

**Запрос к LLM:** `"Привет, как дела?"`

**Результат:** Обычный ответ на один вопрос

---

### Пример 2: Несколько быстрых запросов

**Пользователь (быстро):**
1. "Сколько времени?"
2. "Какая погода?"
3. "Что ты умеешь?"

**Очередь:** `["Сколько времени?", "Какая погода?", "Что ты умеешь?"]`

**Запрос к LLM:**
```
У меня несколько вопросов (3 штук), отвечай на них все сразу по порядку:
1. Сколько времени?
2. Какая погода?
3. Что ты умеешь?
```

**Результат:** LLM отвечает на все три вопроса в одном streaming ответе

---

### Пример 3: Запросы во время обработки

**Пользователь:**
1. "Расскажи про теорему Пифагора" (LLM начинает отвечать)
2. "А кто её придумал?" (добавляется в очередь)
3. "В каком веке?" (добавляется в очередь)

**Очередь во время обработки:** `["А кто её придумал?", "В каком веке?"]`

**Результат:**
1. LLM отвечает на первый вопрос
2. После завершения автоматически обрабатывает накопленные вопросы:
   ```
   У меня несколько вопросов (2 штук), отвечай на них все сразу по порядку:
   1. А кто её придумал?
   2. В каком веке?
   ```

## 🔒 Особые случаи

### Команда "Замолчи"

При получении команды молчания:
- Очередь запросов **очищается**
- Таймер накопления **останавливается**
- LLM обработка **прерывается**

```python
def _handle_silence_command(self):
    if self.pending_queries:
        cleared_count = len(self.pending_queries)
        self.pending_queries.clear()
        self.get_logger().info(f"Очищено {cleared_count} запросов из очереди")
```

### Ошибка LLM

При ошибке обработки:
- Очередь **сохраняется**
- Через 1 секунду запускается повторная попытка
- Робот пытается обработать накопленные запросы снова

## 🔍 Внутренняя архитектура

### Переменные состояния

```python
self.pending_queries = []           # Очередь запросов
self.query_accumulation_timeout     # Тайм-аут накопления (из конфига)
self.last_query_time                # Timestamp последнего запроса
self.accumulation_timer             # Таймер проверки
self.llm_processing                 # Флаг обработки LLM
```

### Поток обработки

```
STT Callback
    ↓
Добавить в pending_queries
    ↓
LLM занят? ──Yes─→ Ждать
    ↓ No
Запустить таймер накопления
    ↓
Ждать query_accumulation_timeout
    ↓
_check_and_process_queue()
    ↓
Объединить запросы
    ↓
_ask_deepseek_streaming()
    ↓
Получить ответ
    ↓
Есть ещё запросы? ──Yes─→ _check_and_process_queue()
    ↓ No
Готово
```
