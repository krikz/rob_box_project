### Доказательство (raw evidence)

Из лога architect profile после последнего запуска (от `t_cdd9524a` comment-thread):

```
[agent-flow-triage] 2026-10-04T02:46:46+02:00 phase1 G9a intra-tick dedup: 1 skip-marker(s)
  skip=#3354 leader=#3346 title-prefix="deploy issues on develop staging 2026"
```

**Механизм `dedup_intra_filter`** (`scripts/agent_flow/agent-flow-triage.sh:870`):

```python
def title_prefix(t, n):
    s = (t or "").lower()
    tokens = re.findall(r"[\w]+", s, flags=re.UNICODE)
    return " ".join(tokens[:n])
```

`AGENT_FLOW_DEDUP_TITLE_PREFIX_WORDS=6` (default в AF-0032 §2.1). Регекс
`[\w]+` отбрасывает эмодзи 🚨, скобки `()`, длинное тире `—`, дефис в дате.
Результат:

- `#3346` "🚨 Deploy issues on develop (staging) — 2026-10-02" → tokens: `deploy issues on develop staging 2026 10 02` → first 6 = **`deploy issues on develop staging 2026`**
- `#3354` "🚨 Deploy issues on develop (staging) — 2026-10-03" → tokens: `deploy issues on develop staging 2026 10 03` → first 6 = **`deploy issues on develop staging 2026`**

**ИДЕНТИЧНЫ → G9a оставляет #3346 (старейшую) и skip-ает #3354 как «дубль»**.
Это **разные deploy-инциденты** (10-02 vs 10-03), а G9a их ложно объединил.

**DRY-RUN подтверждение** (воспроизведено в `t_38515f1b`): `skip=#3354 leader=#3346 title-prefix="deploy issues on develop staging 2026"`.

### Вторичная проблема (side-effect fail-OPEN)

При skip'е G9a должен оставить **комментарий** в issue с маркером
`agent-flow:dedup-skip` и **label** `agent-flow-dedup-skip` (AF-0032 §2.3).
`gh api issues/.../comments` **падает на записи** (3 ретрая с экспонентой) →
`process_issues_json` возвращает exit 1 → для следующих issues тот же сценарий
(skip без marker). **Маркер в issue #3354 не записан** → нет visible-сигнала
для nightly review кроме «карточки нет».

## Почему это системный класс, а не единичный случай

1. **Каждый день** deploy-bot создаёт issue с шаблоном
   `🚨 Deploy issues on develop (staging) — YYYY-MM-DD` → один и тот же
   title-prefix (6 слов), отличается только дата (8-й токен).
2. **TITLE_PREFIX_WORDS=6** — default, расслабленный до «неприметного»
   (AF-0032 §2.1: «баланс между "поймать дубли" и "не задеть разные issues"»).
   На момент дизайна AF-0032 deploy-bot ещё не делал ежедневные авто-issue'ы
   (15.08–26.08 ретро-серии: #1477/#1478, #1506, #1562/#1563, #1650/#1653/#1655/#1658
   — все про баги, не про deploy-bot-расписание).
3. **Side-effect fail-OPEN** без warning — тихий путь. Маркер не записан,
   тикет не помечен, `agent-flow-error` label не выставлен → даже
   `gh issue list --label agent-flow-error` не находит.
4. **Nightly review** — единственный внешний watchdog, который ловит такие
   случаи (через `kanban.tasks WHERE issue_ref IS NULL ...`). До введения
   nightly review (retro `t_bf8216cb` — 2026-W40) класс багов **вообще не
   ловился**.

**Прогноз без фикса:** 1 пропуск / день, ежедневно.

## Сценарии фикса

### Mitigations (уже в работе)

1. **PR #3385** (devops) — расширить group key в `dedup_intra_filter` через
   `deploy-signature` из body (например, `deploy-fail:develop:staging:2026-10-03`).
   Это даёт группировку **по deploy-инциденту**, а не по title-prefix. CI:
   10 SUCCESS + 1 SKIPPED, MERGEABLE, готов к merge.
2. **PR #3381** (devops, `t_cdd9524a` parent) — альтернативный фикс:
   `YYYY-MM-DD` как атомарный токен в `title_prefix`. CI: in_progress на момент
   parent-completion (см. `t_cdd9524a` comment-thread). ADR-AF-0080 фиксирует
   решение.
3. **PR #3355** (devops, `t_c172f5c9` review — APPROVE) — **фикс первопричины
   deploy-fail'а** (cadvisor product_name ARM + promtail 1.42/1.44 mismatch).
   После merge #3354 закроется автоматически на ближайшем deploy-gate re-run.

### Backfill (уже выполнен)

`★ Backfill procedure §5 runbook` — для #3354 fanout к devops, который вручную
создал kanban-карточку `t_29682500` (assignee=devops, body по шаблону
архивных `t_76bdb45a`/`t_0d6f165b`, deploy-signature
`deploy-fail:develop:staging:2026-10-03`). Карточка завершена **через 51 сек**
другим devops-воркером с verdict `premise-obsolete` (AF-0066): fix уже в
