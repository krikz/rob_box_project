# Смотритель логов: режим «вхолостую» (#4033)

Раз в сутки читает из Loki (`http://10.1.1.249:3100`, только чтение) строки `voice-assistant`, гонит их через детекторы
`scripts/dialog/turn_failures.py` и считает вердикты: «робот глух» (с разбивкой `stt_rejected/stt_error/no_wake`) и
«ход без речи» (с причиной). Ничего не включает на роботе. В сводке только счётчики и коды, текстов реплик нет.
Пустое окно сводка называет «событий нет», а не «0 сбоев».

## Вручную

```bash
python -X utf8 scripts/observability/log_watch.py                  # последние 24 ч, сводка текстом
python -X utf8 scripts/observability/log_watch.py --hours 6 --json /tmp/log_watch.json
python -X utf8 scripts/observability/log_watch.py --lines-file x.log   # без Loki, из выгрузки
```

Нужен доступ к `10.1.1.249:3100` (сеть мастерской). Выгрузка за сутки идёт окнами по 6 ч (иначе Loki отвечает 429)
и занимает минуты. Адрес Loki — `--loki-url` или `LOKI_URL`.

`--send-tg` отправляет текст через `scripts/robot_dev/tgsend.sh` (бот робота). По умолчанию выключен, включать только
по слову товарища Шифу.

## Cron (предложение, не поставлено)

Ставить на машину мастерской, которая всегда включена и видит katana и Sound Pi по ssh-ключу (катана: Loki рядом,
репо там уже клонировано для раннеров). Строка, раз в сутки в 06:00 UTC, на неделю вхолостую (JSON копится, в
Telegram не шлём):

```cron
0 6 * * * cd /opt/rob_box_project && python3 -X utf8 scripts/observability/log_watch.py --json /var/log/log_watch/$(date +\%F).json >/dev/null 2>&1
```

Через неделю: по накопленным JSON решить, какой порог `stt_error >= 2` годится как сигнал, и только тогда добавлять
`--send-tg`.

Границы: смотрит только контейнер `voice-assistant`; события музыки (`mcp_server`) в Loki-запрос не входят, поэтому
пустой STT под играющей музыкой может засчитаться в «глух» (завышение, а не пропуск).
