# Студия канала @robbox_project — как это устроено и как чинить

Студия готовит материал для канала: сама собирает факты, сама пишет текст, сама проверяет его
кодом и присылает Шифу **готовый пост** с кнопками итерации. Публикуется только то, что Шифу одобрил.

Бриф студии (целиком) — [channel-studio-brief.md](../process/channel-studio-brief.md).
Правила ведения канала — [telegram-channel.md](../process/telegram-channel.md).
Карточка — issue #4492.

## 0. Где что лежит

| Что | Где |
|---|---|
Репозиторий | `/home/builder/hermes-share/rob_box_project` (ветка `develop`) |
Скрипты студии | `scripts/telegram/channel_studio.py`, `studio_facts.py`, `studio_text.py` |
Скрипты кронов | `scripts/telegram/studio_{session,poll,publish}.sh` |
Секреты | `docker/studio/.env.secrets` — **0600, в git не попадает** |
Шаблон секретов | `docker/studio/.env.example` — только плейсхолдеры |
Состояние студии | `docker/studio/state.json` — локальное, в git не попадает |
Профиль Hermes | `studio` (`~/.hermes/profiles/studio/`) |

**Секреты в репозиторий не коммитятся.** Корневой `.gitignore` переигноривает `.env` правилом
`!docker/*/.env`, поэтому у студии свой `docker/studio/.gitignore` — он возвращает правило обратно.
Проверка: `git add -An docker/studio/` не должен показывать `.env` или `.env.secrets`.

## 1. Кроны и сервис

Кронов два, оба **no-agent**: агента в контуре нет, модель зовёт сам скрипт (`studio_text.py` → MiniMax).

| Крон | Расписание | Что делает |
|---|---|---|
`studio: сессия анализа` | `0 2 * * *` (UTC) = 03:00 GMT+1 | факты → **готовый пост с графикой** → Шифу кнопками |
`studio: публикация поста` | `0 10 * * 2,4,6` (UTC) = 11:00 GMT+1 | публикует approved-пост в слот |

Расписание считаем в **UTC**: бриф задаёт время Шифу (GMT+1), а 10:00Z — это ровно 11:00 GMT+1.
Пояс в cron не нужен — иначе смена времени сдвигала бы слоты, а слот записан в самой очереди
(`not_before: 10:00Z`).

**Кнопки и сообщения Шифу — не крон, а сервис `studio-watch`** (Шифу 06.11: «нажал кнопку — а оно уходит
курить на пять минут по расписанию»). Это systemd user-service с `Restart=always` и linger (как `ducksidian`
на той же машине): постоянный long-poll `getUpdates` (50 с), на нажатие — сразу `answerCallbackQuery`
«Делаю…», тяжёлая работа — в отдельном потоке, замок `state.json` берётся только на короткую запись.
Почему не контейнер: на builder рядом уже живут user-сервисы, Docker для студии не нужен (Python и Pillow
стоят), а systemd сам поднимает упавший процесс и пишет журнал.

```bash
bash scripts/telegram/studio_install.sh                  # юнит → ~/.config/systemd/user/studio-watch.service
STUDIO_ENABLE_SERVICE=1 bash scripts/telegram/studio_install.sh   # то же + enable --now + restart
loginctl show-user "$USER" | grep Linger                 # должно быть Linger=yes
systemctl --user status studio-watch
journalctl --user -u studio-watch -f                     # журнал нажатий и работ
```

Сервис держит `/tmp/studio-poll.lock`: второй получатель апдейтов (ручной `poll`, старый крон) не стартует —
иначе Telegram отвечает 409 и нажатия теряются.

**Источник истины по расписанию — `docker/studio/cron.json`** (там же список снятых кронов и причина).

```bash
hermes --profile studio cron list
hermes --profile studio cron run <id>      # прогнать сейчас
```

Слоты публикации: вторник, четверг, суббота, 11:00 GMT+1. Между постами не меньше 48 часов —
это проверяет `channel_post.py`, а не модель. Сессия анализа тоже молчит, если с последней
публикации не прошло 48 часов: предлагать идеи раньше бессмысленно — они всё равно не выйдут.

## Свежие материалы: worktree на develop

Клон студии живёт на рабочей ветке, а свежие материалы приезжают в `develop`.
Поэтому факты и медиа читаются из отдельного worktree:

| Что | Где |
|---|---|
| Клон студии | `/home/builder/hermes-share/rob_box_project` (ветка `z-architect/…`) |
| Worktree develop | `/home/builder/hermes-share/rob_box_develop` (detached, `origin/develop`) |
| Переменная | `STUDIO_DEVELOP_WORKTREE` — путь к worktree |

Каждая сессия начинается с `git fetch origin develop`, worktree приводится к
`origin/develop` (`checkout --detach` + `reset --hard` + `clean -fd`).
Worktree **только читается**: он detached, правки студии в него не попадают.

Проверено: `docs/channel/media/locdrift-before-after.png` из #4508 в рабочей
ветке нет, а через worktree виден — и пост собирается с этим материалом.

## Кнопки на черновике

Черновик — **одно сообщение**: медиа (готовый файл из develop или инфографика-таймлайн влитых PR на
подложке из `docs/channel/media/bg/`) + подпись-пост в Telegram HTML (тезис `<b>`, имена `<code>`,
детали в `<blockquote expandable>`, ссылка на PR) + кнопки. Подпись ≤ 1024 знаков — это проверяет код.

| Кнопка | Что делает |
|---|---|
| Короче | Переписать текст короче (модели дан текущий текст), правка подписи на месте (`editMessageCaption`) |
| Проще | Упростить язык, правка на месте |
| Подача | Сменить угол подачи, правка на месте |
| Медиа | Следующий вариант медиа по кругу → `editMessageMedia` в том же сообщении; вариантов нет вовсе — issue «материал для канала: …» |
| Опубликовать | Отдать пост в очередь канала (файл в `docs/channel/queue/`, инфографика — по `media_path`) |
| Отклонить | Отклонить пост; вернуть его в публикацию нельзя |
| *(текст в личку)* | Правка черновика своими словами («убери номера PR»): ответ (reply) на черновик — правка именно его, иначе — последнего черновика на обсуждении; черновика нет — ответ модели без инструментов |

**Индикатор.** На каждое «Короче/Проще/Подача/Медиа» и на черновик сессии студия ведёт одно сообщение,
которое правится на месте (не чаще раза в 1,5 с), и шлёт `sendChatAction` по этапам:

```
Черновик p20261106-129: другое медиа
✓ Беру черновик и факты сессии: своих 1 из 15
✓ Подбираю медиа: вариант 2 из 2
✓ Рисую инфографику: таймлайн влитых PR
✓ Меняю медиа в черновике: p20261106-129-timeline.png
Готово: медиа в черновике заменено
```

Шаги строит код. «Почему так» — поле `why` модели (≤ 300 знаков) в раскрывающейся цитате; его проверяет код
(числа и имена по фактам, без ключей и разметки), не прошло — не показывается, и индикатор говорит почему.
Ошибка — строка «Не вышло на шаге «…»: причина». Второе нажатие, пока идёт первая правка того же черновика, —
честное «Уже делаю прошлую правку».

Переделка идёт **вне блокировки состояния** и вне опроса (поток). `message_id` и `message_kind`
(media/text) сохраняются в состоянии — без них правка на месте не найдёт сообщение.

### Разбор 06.11: кнопка «Медиа» «ушла в себя»

Воспроизведено на моках (старый код e282e0cab): `poll_once` держал `state_transaction` весь long-poll (50 с)
и в `finally` писал старое состояние поверх — черновик, записанный в эти секунды, пропал (в state.json на builder
осталось `"p20261106-129": {}`). Дальше `apply_post_action` создавал пустую запись, переделка отвечала «не найден»,
а её ответ никуда не уходил: Шифу видел только «Смотрю медиа.». Кроме того «Медиа» меняла только текст
(`editMessageText`), а переделка текста звала `studio_text.py` без `--facts` (argparse падал молча). Всё это
закрыто тестами `tests/unit/scripts/test_telegram_studio_buttons.py`.

## 2. Кто владеет ботом

Бот студии — **@robboxcontentbot**, отдельный от бота робота (@krobbox_bot). Это не случайно:
`getUpdates` читает ровно один поток, и если бы студия читала токен робота, пульт робота сломался бы.

Студийного бота обслуживает **только** сервис `studio-watch` (`channel_studio.py watch`). Адаптер Telegram в Hermes знает
свои префиксы (`mp:`, `cp:`, `cl:`, `ea:`, `sc:`) и префикс `studio:` он проглотил бы молча,
поэтому кнопки студии разбирает собственный скрипт, а не Hermes.

Токен бота робота в студии использовать нельзя.

## 3. Конвейер студии

Порядок по решению Шифу (06.11): **сразу готовый пост**. Шифу получает текст и
медиа в том виде, в каком студия их видит, и дальше крутит кнопками
«Короче», «Проще», «Подача», «Медиа» — правка идёт на месте, в том же
сообщении. Кнопки «Опубликовать» и «Отклонить» — решение поста.

Идеи-кандидаты по-прежнему собираются (`studio_text.py`), но Шифу их больше
не получает: он получает готовый пост.

```
studio_facts.py    → факты (код)            ← PR, issue, прогонов, ADR, медиа
  studio_develop.py → worktree на develop      ← свежие факты и материалы
  studio_facts.py   → факты                    ← только из worktree develop
  studio_draft.py   → готовый пост (MiniMax)   ← тема + текст + медиа
  studio_text.py    → текст поста (MiniMax)    ← по выбранному факту
studio_text.py     → проверка идеи (код)    ← источники настоящие, «что показать» и срок есть
channel_studio.py  → Шифу кнопками           ← только то, что прошло проверку
        ↓ «Берём»
studio_text.py     → текст поста (MiniMax)   ← production: текст по согласованной идее
studio_text.py     → проверка поста (код)    ← числа, имена, лимиты, HTML, теги, ключи
channel_studio.py  → Шифу кнопками           ← «Опубликовать» / «Отклонить»
        ↓ «Опубликовать»
queue_post()       → docs/channel/queue/     ← файл со status: approved и not_before
channel_post.py    → канал                   ← по правилу 48 ч, в слот
```

По ADR-0148: **код решает, модель говорит**. Модель не выдумывает факты — у каждого факта есть
источник (PR, issue, run_id, файл), и числа/имена в тексте проверяются против списка фактов.

Нечего показывать → сессия молчит. Шифу не приходит пустых сообщений.

### Состояние и идемпотентность

Состояние студии — `docker/studio/state.json` (в git не попадает). Формат и блокировка —
`scripts/telegram/studio_state.py`:

- `covered` / `rejected` — событие показано или отклонено, больше не предлагается;
- `pending` — событие предложено, но ещё не опубликовано: **оно не теряется**;
- `deferred` — предложено слишком много раз, отложено.

Событие закрывается **только после публикации поста**. «Берём» идею событие не закрывает:
иначе неудавшийся пост съел бы его навсегда. Файл состояния пишется под `flock` — опрос кнопок
и сессия анализа не затирают друг друга.

### Про модель

Текст пишет **MiniMax-M3.1-Flash** с `reasoning_effort: low`. Проверено вживую 06.11.2026:

| Вариант | Результат |
|---|---|
`MiniMax-M3` + `thinking: disabled` | работает, ~11 с |
`MiniMax-M3.1-Flash` + `thinking: disabled` | **HTTP 400** — нельзя выключить |
`MiniMax-M3.1-Flash` + `thinking: adaptive` | content **пустой** — размышления съели max_tokens |
`MiniMax-M3.1-Flash` без указаний | content пустой, `finish_reason=length` |
`MiniMax-M3.1-Flash` + `reasoning_effort: low` | **работает**, ~15 с, 4 идеи |

То есть у Flash «мышление» не отключается, его можно только ограничить. Без `reasoning_effort`
модель тратит весь бюджет токенов на размышления и возвращает пустой ответ.
Правило зашито в `studio_text.thinking_params()` — там же лежит и запрет на `thinking: disabled`
для Flash.

## 4. Кнопки и обсуждение

Кнопки Шифу приходят как `callback_query` с `callback_data` вида `studio:idea:<id>:take`.

| Кнопка | Что делает |
|---|---|
«Берём» | идея → `agreed` |
«Обсудить» | идея → `discuss`, бот просит Шифу написать правки |
«Мимо» | идея → `rejected` |
«Опубликовать» | пост → `approved` (дальше его заберёт публикатор) |
«Отклонить» | пост → `rejected` |

Текстовые сообщения Шифу сохраняются в `state.json` (`messages`) — фаза обсуждения.

## 5. Типовые поломки

**Бот не отвечает на кнопки.** Проверь сервис: `systemctl --user status studio-watch` и
`journalctl --user -u studio-watch -n 50`. В журнале на каждое нажатие — строка
`обработано: studio:post:<id>:<действие> → …`, на каждую работу — `пост <id>: <действие> → готово / не вышло`.

**Ошибка 409 от Telegram.** Два процесса читают один бота. `watch` и `studio_poll.sh` берут один
`flock` (`/tmp/studio-poll.lock`): пока жив сервис, второй опрос не стартует. Ручной `channel_studio.py poll`
этот замок не берёт — при живом сервисе его не запускать.

**Пустой ответ модели.** Размышления съели `max_tokens` — проверь, что в запросе есть
`reasoning_effort`. См. раздел 3.

**Идеи не приходят.** Смотри вывод сессии: `видимых фактов: 0` — показывать нечего, это не поломка.
Если факты есть, но `идей прошли проверку: 0` — модель пишет не по фактам, смотри `problems`
в `docker/studio/run/ideas.json`.

**Секрет утёк.** Токен бота студии перевыпускается у @BotFather; `GH_TOKEN` — в fine-grained
токенах, read-only. Classic-токен `gh` (`ghp_…`) писать может, для студии он лишний.

## 6. Прогон вручную (без кронов)

```bash
cd /home/builder/hermes-share/rob_box_project
set -a; . docker/studio/.env.secrets; set +a

bash scripts/telegram/studio_session.sh          # факты → черновик с графикой и индикатором → Шифу
python3 scripts/telegram/channel_studio.py draft --facts docker/studio/run/facts.json --note тест  # только черновик
python3 scripts/telegram/channel_studio.py state # что в состоянии
python3 scripts/telegram/channel_post.py --transport direct --dry-run  # что уйдёт в канал
```

`--dry-run` ничего не отправляет: показывает, что было бы отправлено.
