# Спайк #3930: потоковый синтез MiniMax T2A v2 — 23.10.2026

Карточка #3930 (эпик #3683, критерий A2 ADR-0150 §14: от конца реплики до первого звука, p50 6.5 с / p95 12 с
при пороге 4 / 8). Вопрос спайка: даёт ли SSE-поток T2A v2 (`stream=true`) первый звук раньше, чем HTTP целиком,
и не ломает ли он склейку кусков, паузы рэпа `<#x#>` (#3901/#3924) и смену голоса.

## Как мерили

- Скрипт спайка (scratchpad, не в репо): прямые запросы с Windows-машины в `https://api.minimax.io/v1/t2a_v2`,
  `speech-02-hd`, `format=pcm`, `language_boost=Russian`, голос `male-qn-qingse` (один прогон —
  `Russian_ReliableMan`). Ключ — только из окружения процесса, в вывод не попадал.
- `t_first_audio` — от отправки запроса до первого декодированного куска звука (HTTP: до ответа целиком).
- **Запросов: 16** (лог `results.jsonl`, 16 строк + счётчик `requests_used: 16`). Потолок брифа — 30.
  Доборов не делал: паузы рэпа и смена голоса уже в этих 16; склейка и паузы разобраны офлайн по сохранённым WAV.
- Сеть — Windows-машина мастерской, не Sound Pi. Абсолютные числа на роботе могут отличаться;
  разница HTTP / поток — свойство API, а не сети.

Вывод: **первый кусок потока приходит за 0.73–1.39 с при любой длине текста** (16 и 205 символов — одинаково
0.95 с), HTTP растёт с длиной (1.42 → 4.63 с). На строке 73 символа из логов хода (2.7 с) выигрыш

16 кГц ReSpeaker, без ресэмпла.

## Куски и склейка

- Куски: первый 11 114 байт = **0.35 с** звука, почти целиком начальная тишина MiniMax (та же 0.30–0.38 с есть
  и в HTTP); второй ~0.77 с приходит через 0.15–0.45 с после первого; дальше по ~1.3 с. Поток идёт в 3–7 раз
  быстрее реального времени (LONG: 16.6 с звука за 2.5 с).
- Все куски чётной длины (PCM s16 не рвётся посреди отсчёта), `odd_chunks = 0` во всех 16 прогонах.
- `exclude_aggregated_audio=false` (прогон 5): склейка кусков **бит-в-бит** равна агрегату в закрывающем
  событии `status=2`. Значит, с `exclude_aggregated_audio=true` агрегат не нужен, а без флага его надо
  выкидывать — иначе фраза прозвучит дважды.
- Скачок отсчёта на стыках кусков (офлайн по WAV): максимум 0.058 полной шкалы против 0.24–0.45 для
  99.9-го перцентиля скачков внутри сигнала, стыков выше перцентиля — 0 из 40 (5 потоков). Щелчков на стыках нет.

## Паузы рэпа `<#x#>`

Тишина (RMS < −40 дБ, ≥ 0.3 с) в RAP: поток — 1.54 с и 1.48 с на местах `<#0.80#>` и `<#0.60#>`;
HTTP — 1.44 с и 1.36 с. Паузы в потоке **есть и той же длины** (±0.1 с — разброс генерации, у двух HTTP-прогонов
одной фразы он такой же). Пауза может попасть внутрь куска или на стык — на склейку это не влияет.

## Смена голоса

`voice_setting.voice_id` в потоке работает так же, как в HTTP (прогон 14, `Russian_ReliableMan`: 0.89 с до
первого куска, 7 кусков, звук другим голосом). Голос — параметр запроса, на реплику; смена между репликами
ничего не требует.

## Резка по предложениям (п. 3 карточки)

Поток делает первый звук независимым от длины текста (0.95 с и для 16, и для 205 символов). Резка «первое
предложение отдельно» сократила бы только HTTP-путь; поверх потока она ничего не даёт, а стоит лишних запросов
и швов интонации между предложениями. В реализации её нет; сплиттер `tts_chunking.split_text` уже есть и
остаётся единственным (для лимитов Yandex/Silero).

## Решение

Поток даёт выигрыш (≈ 1.5–2.5 с на типичной реплике) и не ломает паузы рэпа, склейку и смену голоса —
реализация в `core/tts_stream.py` + `tts_node` (PR по #3930). Предбуфер старта — 0.5 с речи после срезки
начальной тишины: по таймингам кусков это первый звук через ~1.1–1.4 с от запроса.

Оценка A2 (не замер): 6.5 с − ~2 с ≈ 4.5 с p50 — на границе порога 4 с; остаток — LLM-часть (2–3 с), она вне
карточки. **Замер A2 на роботе (`scripts/dialog/turn_metrics.py`, 20 фраз до/после) не сделан — ждёт стенда.**
