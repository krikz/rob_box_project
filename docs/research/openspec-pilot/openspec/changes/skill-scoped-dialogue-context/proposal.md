## Why

Диалоговая LLM робота каждый ход получает **~27 100 токенов статического
префикса** (16 240 — схемы 54 тулов, 10 838 — `master_prompt_compact.txt`),
и весь этот текст стоит на **позиции 0**, перед двадцатью ходами истории.
Инструкция «как пользоваться инструментом» физически удалена от момента,
когда она нужна, и проигрывает свежему few-shot из истории.

Это не гипотеза — репозиторий уже доказал принцип для **состояния** и
уже четыре раза руками применил его к **инструкциям**:

- `dialog_core.py:617` — `<system_context>` перенесён из `messages[1]` в
  хвост, вплотную к текущей реплике, с формулировкой «волатильный
  runtime-стейт должен стоять там, где он и по времени».
- 4 блока `<reminder>` в `_build_dynamic_system_context` переклеивают
  правила, которые **уже есть** в мастер-промпте (`stop_music` #1544,
  `get_current_time` #1777), поближе к текущему ходу — потому что на
  позиции 0 они не срабатывали.
- 5 билдеров retry-промптов в `dialogue_guards.py` вкидывают инструкцию
  «как вызвать этот тул» — но **после** того, как модель уже облажалась.
- `dialog_core.py:681` — «через десять ходов модель читала транскрипт,
  где КАЖДАЯ просьба о музыке отвечена красивой фразой и ни одним тулом,
  и добросовестно продолжала этот few-shot».

Плюс 54 тула лежат в одном плоском пространстве имён без признака режима,
включая **два конфликтующих словаря «трек»** (`list_tracks`/`load_track` —
Renardo; `gen_list_library`/`gen_play_from_library` — mp3). Последний
коммит в develop (`ef73a5fa`) — баг ровно на этой границе.

Этот change формализует то, что команда и так делает по одному инциденту:
доменные инструкции приезжают **свежими, в момент нужды**, а не лежат
на позиции 0 в надежде, что модель их вспомнит.

## What Changes

- **Скилл = профиль контекста**: `{имя, список имён тулов из
  `rob_box_core.tool_catalog`, фрагмент инструкций, условие активации}`.
  Скилл **НЕ переобъявляет контракт тула** — только ссылается на имена из
  каталога. Это жёсткий инвариант: параллельное объявление тулов убило
  предыдущую попытку (Compositor, `e96b912d`).
- **Move A (свежесть)** — фрагмент инструкций активного скилла вклеивается
  системным сообщением/tool-результатом **вплотную к текущему ходу**,
  туда же, где сейчас `dynamic_system`. `tools=` при этом НЕ меняется,
  поэтому кэшируемый префикс провайдера остаётся целым.
- **Move B (диета)** — сужение `tools=` до `core ∪ активный скилл`.
  Вводится **за флагом, выключенным по умолчанию**, и включается только
  после того, как метрики из Move 0 покажут выигрыш. Ломает prefix-cache и
  добавляет класс отказа «роутер промахнулся → LLM не видит тул»
  (регрессия #1403).
- **Move 0 (сначала измерить)** — экспорт `prompt_tokens` в Prometheus.
  Сейчас метрик по промпту нет вообще (`grep -n token
  observability/metrics.py` → 0 попаданий), `LLMResponse.usage` заполняет
  только deepseek, а primary-провайдер — minimax. Без этого любое «стало
  лучше» будет тем самым красивым PASS, который запрещён ADR-0018.
- **Активация** — гибрид: детерминированный пред-роутер на существующем
  `CommandParser` для очевидных случаев + тул `load_skill` для остального.
  `load_skill` не запасной вариант, а полноценный путь: его результат
  приходит tool-сообщением в самый хвост `messages`, то есть в позицию
  максимальной свежести, и модель действует в том же ходу.
- **Drift-guard** — обобщение `_validate_tools_in_prompt` (сейчас проверяет
  только музыку и только warning'ом) на все скиллы, блокером в CI.
- **Уборка мёртвого**: `skills/status_skill.py` (битый импорт
  `from .base_skill import BaseSkill`, модуль удалён в `e96b912d`),
  `prompts/compositor_prompt.txt` (15 КБ, ссылается на удалённые фасады
  `handle_music`/`handle_navigation`, прибит тремя тестами),
  `prompts/skills/*.txt` (5 файлов, не грузятся никуда — единственное
  чтение промпта в рантайме это `dialogue_node.py:990`).

**Не входит в scope (явные non-goals):**

- **НЕ** возврат `openai-agents` SDK (`Agent`/`Runner`) на диалоговый путь.
  SDK установлен в образ (`docker/vision/voice_assistant/requirements.txt:92`),
  но не импортируется ни одной строкой живого кода — это мёртвая
  зависимость. Разбор — в `design.md` §Alternatives.
- **НЕ** sub-агенты и handoff'ы. Это Compositor, он уже умер.
- **НЕ** `@function_tool`-обёртки. Каталог остаётся единственным
  объявлением контракта.

## Capabilities

### New Capabilities
- `dialogue-skill-context`: доменные профили контекста для диалоговой LLM —
  объявление скилла поверх каталога тулов, вклейка инструкций рядом с
  текущим ходом, активация, наблюдаемость размера промпта и защита от
  дрейфа «скилл ↔ каталог».

### Modified Capabilities
- (нет — `openspec/specs/` в пилоте ещё не заведён, существующих
  capability-спеков для модификации нет.)

## Impact

**Код:**
- `src/rob_box_core/rob_box_core/tool_catalog.py` + `_tool_catalog_data.py` —
  новое поле `skill` в `ToolCatalogEntry`; генератор `tools/gen_tool_catalog.py`.
- `src/rob_box_harness/rob_box_harness/core/dialog_core.py` — резолв
  инструкций скилла на ход; точка вклейки рядом с `dynamic_system`
  (`:625`); опциональная фильтрация в `_run_with_tools` (`:843`).
- `src/rob_box_harness/rob_box_harness/core/tool_registry.py` — выборка
  по скиллу поверх `llm_visible_tools()`.
- `src/rob_box_voice/rob_box_voice/dialogue_node.py` — пред-роутер на
  `CommandParser`, обобщённый `_validate_tools_in_prompt` (`:1044`).
- `src/rob_box_voice/rob_box_voice/observability/metrics.py` — гистограмма
  `voice_llm_prompt_tokens`.
- `src/rob_box_harness/rob_box_harness/providers/minimax.py` — заполнение
  `LLMResponse.usage` (сейчас пусто у primary-провайдера).
- `src/rob_box_mcp_tools/rob_box_mcp_tools/mapping_state.py` —
  `MAPPING_WHITELIST` становится обычным скиллом (Move B).

**Промпты:** `master_prompt_compact.txt` — §5 MUSIC (2 181 tok) и
§6 WAYPOINTS (184 tok) уезжают во фрагменты скиллов. §1 CORE INVARIANTS +
§2 ANTI-DUP (5 136 tok) остаются всегда — это инварианты, их резать нельзя.

**Конфиг:** `dialogue_node.yaml` — `skills_enabled`, `skill_tool_narrowing`
(по умолчанию `false`).

**Зависимости:** новых нет. `openai-agents` — кандидат на удаление из
`requirements.txt` отдельной карточкой (не в этом change).

**Совместимость:** Move A аддитивен и обратим флагом. Move B выключен по
умолчанию. Breaking-изменений в ROS-топиках и контрактах тулов нет.
