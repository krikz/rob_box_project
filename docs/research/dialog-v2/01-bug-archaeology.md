### По кругу?
Да. Один и тот же класс («сказал — не сделал») проходит через навигацию (02–03.2026), музыку (08.2026), поиск/время (31.08), память (22.09), пресеты (24.09), ТАРС (01.10). Каждый раз — новый детектор под новую предметную область. #3165 (29.09): phantom-гард #2559 и Bug E **наказывают правильный ответ** о состоянии → «Не получилось выполнить» — заплатка класса 1 породила баг класса 2.

### Архитектурная причина
**Решение в LLM вместо кода** + **фразу об успехе строит LLM, а не результат исполнения** + **нет события об исполнении**. Это ровно то, что ADR-0148 §2.1 формулирует как «Фразу об успехе действия строит код из результата исполнения». Пока ответ и действие — две независимые выдачи модели, их расхождение ловится только регексом.

### По кругу?
Да, это главный «круг» репо: каждый фикс класса 1 добавляет детектор, детектор даёт ложные срабатывания, ложные срабатывания чинятся сужением регекса или новым исключением. ## 4. Класс 3 — Служебный текст и разметка уходят в TTS

## 16. Сведение к архитектурным причинам

| Архитектурная причина | Классы | Что это значит для v2 (вывод, не решение) |
|---|---|---|
| **Решение в LLM вместо кода** | 1, 2, 9, 10 | действия, требующие гарантии (запомнить, остановить, громкость, спросить имя), не должны зависеть от того, вызовет ли модель тул; где решение уже вычислимо — код вызывает сам (ADR-0148 §2.1; пример: роутер медиакоманд #3134/#3176) |
| **Фразу об успехе пишет LLM** | 1, 3 | реплика об исполнении должна строиться из результата тула; «успех» = событие исполнителя, а не наличие имени тула в списке (#2949) |
| **Заплатка поверх ответа (регекс + ретрай)** | 2, 3 | каждый слой порождает ложные срабатывания; MiniMax не даёт `tool_choice` (ADR-0143) — значит гарантию надо брать не из API, а из структуры (узкий набор тулов по состоянию, `skill_tool_narrowing`) |
| **Владелец состояния не определён** | 7, 8, 9 | SILENCED, голос, персона, режим DJ, «кто говорит», «чей ход», история — без одного владельца и без TTL/события конца |
| **Молчаливая деградация** | 4, 5 | провайдер/голос/фолбек меняются без сообщения человеку и без явного статуса; таймауты складываются без общего бюджета хода |
| **Служебное и речевое в одном канале** | 3, 8 | история и `content` модели служат одновременно памятью, каналом инструкций и источником речи |
| **Дубль реализаций / несколько источников знания** | 6, 8, 10 | wake-списки, silence-списки, реестр тулов (класс/сервер/каталог/промпт), писатели на `/voice/tts/*` |
| **Нет события об исполнении** | 1, 2, 7 | гарды гадают по тексту; e2e проверяет паттерны в логах (§14) |
