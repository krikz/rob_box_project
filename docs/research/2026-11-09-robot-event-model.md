## 1. Коротко

1. **Данных мало, и они однообразные** [измерено].
   - Полные логи `voice-assistant` есть только у 78 прогонов марафона, с 03.11 21:09 по 06.11 01:18 UTC. В них 748 ходов.
   - Текстов шагов всего 153 уникальных. Один и тот же сценарий прошёл ~15 раз.
   - Живых ходов вне марафонов за 07–09.11 — 210. Они лежат в Loki, а Loki хранит 7 дней.
   - e2e-БД ходов (`dialog_events_<run>.db`) не сохранилась ни одна. Скрипт оставляет её в `/tmp` контейнера, и при каждом деплое её стирает пересоздание контейнера.
2. **(а) Звать ли LLM.** Из 649 ходов, где LLM звали, в 46 (7,1 %) модель только дёрнула тул из набора Tier-1 и ничего не сказала: голос, громкость, темп, тон, стоп музыки [измерено].
   - Правила `develop` не ловят ни один из этих 46. Причина — лишние слова после команды: «потише, а то разбудишь весь этаж» [измерено, повтор правил на тех же текстах].
   - В живых ходах после марафонов таких 1 из 189.
   - «Какую LLM» учить не на чем: 1006 из 1006 LLM-ходов за 7 дней ответил DeepSeek. Запасной провайдер не включался ни разу.
3. **(б) Какой срез тулов.** На 188 шагах, где сценарий ждёт конкретный тул, тул был в срезе во **всех 188** [измерено]. Модель не вызвала его, хотя он был в срезе, в 2 случаях.
   - Улучшать полноту среза некуда, но это на тех же фразах, под которые правила и настраивали. На перефразах и искажениях STT полноту уже мерил #4163, см. §4.2.
   - Запас есть в точности: сверх 6 всегда-видимых тулов срез даёт в среднем 4,1 тула, а ход использует 0,5.
4. **(в) Норма или сбой.** Механических сбоев (робот не услышал, ход не начался, ход без речи) — 23 шага из 941, то есть 2,4 % [измерено]. 16 из них — два акта, где робот был глухой целиком.
   - Сигналы в логах есть по отдельности (STT `ОТКЛОНЕНО`, бэклог `no_wake`), но код их не сводит в вывод «это сбой».
   - Из 42 упавших шагов, сопоставленных ходу, сигнал кода был у 8. Остальные 34 — ошибки смысла ответа, которые поток событий не видит.
5. **Вывод: модель сейчас делать не стоит.** Узкое место — разметка, а не мощность железа: 23 примера сбоя, 153 фразы, один провайдер. Дешевле:
   - сохранять данные, сейчас они теряются;
   - добавить в код два-три детерминированных детектора сбоя (ADR-0148);
   - для (а) — замерить «команда Tier-1 + болтовня» на живых фразах.

   Возвращаться к модели — когда наберётся ≥ 100 примеров каждого класса сбоя [догадка по размеру выборки, §5].
6. **Скорость 100+ токенов/с на Pi** — не замерена, бенч на Pi в этот шаг не входил: на робота ничего не ставим. По расчёту модель на 1–20 млн параметров в int8 на CPU Pi 5 должна давать сотни–тысячи токенов/с [догадка, §5.1]. Проверять стоит только тогда, когда будет что запускать.

## 4. Три задачи: как решает код и какая у него база

### 4.1 (а) Звать ли LLM и какую

**Как решает код** [по коду]. `turn_work` (`src/rob_box_dialog/rob_box_dialog/turn.py:1937`) идёт по порядку:

1. Ответ на открытый вопрос тула (`tool_ask.reply`).
2. Tier-1 — закрытая грамматика: `tier1_of` (`turn.py:335`) → `tier1_for` (`turn.py:328`). Фраза целиком или слова после вейка; спорная команда (`disputed`) уходит к LLM.
3. Иначе ход к LLM: `understand`, до `LLM_QUERY_ITERATIONS_MAX = 4` итераций (`knowledge.py:3008`).

Какую LLM: цепочка `llm_providers: "deepseek,minimax"` (`src/rob_box_voice/config/dialog_node.yaml:10`). `HealthAwareFallbackLLM` (`src/rob_box_harness/rob_box_harness/health.py:543`) ставит здоровые провайдеры первыми.

**Разметка бесплатно.** Слабая метка «LLM была не нужна»: модель вернула только команду, ничего не сказала, и все исполненные тулы — из набора, который умеет Tier-1 (`set_voice`, `set_volume`, `set_speed`, `set_pitch`, `stop_music`). Обратной метки («Tier-1 сработал зря») в логах нет. Её даёт только вердикт шага.

**База** [измерено, `out_analyze.txt`, `out_replay.txt`, `out_live.txt`]:

| | Марафоны 03–06.11 | Живые 07–09.11 (Loki) |
|---|---|---|
| Ходов | 748 | 210 |
| Без LLM (Tier-1 и ответ на вопрос тула) | 99 (13 %); Tier-1 — 92 | 21 (10 %); Tier-1 — 6 |
| LLM-ходов | 649: 1 вызов — 390, 2 — 235, 3 — 23, 4 — 1 | 189 |
| Токенов на LLM-ход, медиана | 10 341 | 11 084 |
| Время хода, медиана | LLM 2 825 мс (p90 4 859); без LLM 28 мс | LLM 2 955 мс |
| LLM-ход только с Tier-1-тулом и без речи | **46 (7,1 %)**: `set_voice` 21, `set_volume` 13, `stop_music` 6, `set_speed` 4, `set_pitch` 2 | 1 |
| Провайдер | DeepSeek 649 из 649 | DeepSeek 189 из 189; за все 7 дней — 1 006 из 1 006 |

- Шаги по пути хода: Tier-1 — 76 OK из 79 (96 %), LLM — 535 OK из 572 (93,5 %).
- Правила `develop` на текстах тех же 46 ходов Tier-1 не дают ни разу, проверено пустым снимком сессии. Пример: «Робот, нет, всё-таки потише, а то разбудишь весь этаж» → `None`, «Робот, потише» → `volume quieter`.
- Строгость грамматики — замысел: хвост может нести вторую просьбу. Поэтому это не баг правил, а место, где нужно решение «хвост — болтовня или просьба».
- Оговорка: 18 ходов, которые в марафоне шли по Tier-1, на пустом снимке ушли бы к LLM. «Выключи музыку» без играющей музыки — не Tier-1. Повтор правил без снимка сессии поэтому приблизительный.

**Что из этого следует.**

- Выигрыш здесь — не больше 7 % LLM-ходов марафона и около 2,8 с на каждом из них. В живых ходах он почти нулевой: 1 из 189.
- «Какую LLM» не задача для модели, пока провайдер один: в данных нет ни одного случая выбора.

### 4.2 (б) Какой срез тулов дать

**Как решает код** [по коду]:

- `available_tools` (`src/rob_box_dialog/rob_box_dialog/tools_view.py:269`): всегда-видимые тулы + группы по основам слов и переносу с прошлого хода (`groups_for`, `tools_view.py:30`), не больше `TOOLS_VISIBLE_MAX = 12` (`knowledge.py:796`).
- Дальше форма команды отсекает лишнее (`form_tools`, `turn.py:466`).
- Сам срез в строке хода не пишется. Он виден только в отладочном дампе запроса `tools(N): …`.

**Разметка бесплатно:**

- `expected_tool_calls` сценария: 612 шагов, 16 тулов (`out_expect.txt`);
- исполненные тулы хода (`📨 [execute]`).

**База** [измерено, `out_analyze.txt`, `out_slice_use.txt`, `out_replay.txt`]:

| Мерило | Значение |
|---|---|
| Шаг ждёт тул, тул был в срезе (полнота правил) | 177 из 177 LLM-шагов; ещё 11 шагов закрыл Tier-1. Повтор правил `develop` на тех же текстах — 185 из 185 |
| Тул в срезе, но модель его не вызвала | 2 из 188 |
| Тулов в срезе сверх 6 всегда-видимых | в среднем 4,08; исполнено из них — 0,5 |
| LLM-ходов, где не исполнен ни один тул сверх всегда-видимых | 334 из 648 |
| Токенов на ход с одним вызовом LLM: срез из 8 тулов против 12 | медиана 8 043 (n=111) против 10 175 (n=129). Разница не только от тулов: у ходов с 12 тулами и состояние больше [догадка] |

**Оговорка важнее цифры.**

- 100 % полноты получено на 153 фразах, под которые правила и правили. О новых фразах это не говорит ничего.
- Обобщение уже мерил #4163 ([dialog-v2/08](dialog-v2/08-understanding-measure-and-card-flow.md) §2, этап 2). Мерилось понимание шага целиком, не один срез. Код по словам (вариант A) против классификатора Jev (C):
  - перефразы — 89,8 % против 89,8 %;
  - реальные искажения STT — 71,2 % против 70,5 %;
  - английский — 61,1 % против 93,8 %.
- Решение Шифу 28.10: понимание остаётся за кодом, пересмотр — по трём условиям оттуда же.
- Значит, для (б) обученная модель даст выигрыш на другом языке. На русском — нет, а слабое звено там — STT.

### 4.3 (в) Норма или сбой

**Как решает код** [по коду]: отдельные сторожа на каждый механизм. Общего вывода «робот сейчас в сбое» нет.

- STT завис: `src/rob_box_voice/rob_box_voice/stt_hang_guard.py:122`.
- Эхо своей речи: `decide`, `src/rob_box_voice/rob_box_voice/core/echo_window.py:498`.
- Выступление без событий: `src/rob_box_dialog/rob_box_dialog/plan/perform.py:507`.
- Срок хода: `deadline.py:45`.
- Невалидный ответ модели: валидатор, `invalid:*` в `🧾 [command]`.
- ReSpeaker встал: `audio_node.py:596`.

**Разметка бесплатно.** Класс провала шага в `e2e_verdict.log`: `E2E_STEP <шаг> FAIL <класс>`.

**База** [измерено, `out_analyze.txt`; 941 вердикт по 78 прогонам с логами]:

| Класс | Шагов | Есть ли сигнал в логе | Сводит ли код в «сбой» |
|---|---|---|---|
| `no_accept` — фраза не принята, «кольцо горит, ничего не происходит» | 16 (из двух актов: робот был глух весь акт) | да: `[stt_attempt] yandex:empty→minimax:empty→vosk:empty`, `❌ ОТКЛОНЕНО` | нет |
| `turn_no_wake` — STT потерял «Робот», фраза ушла в бэклог | 5 (+5 спасено восстановлением) | да: `[backlog] accumulated reason=no_wake`, но для кода это норма | нет |
| `turn_nospeech` — ход закончился без речи | 2 | нет: `📊 [turn] status=finished` | нет |
| `FAIL` без класса — ответ не тот (ключевые слова, тул) | 48 | у 8 из 42 сопоставленных: `invalid:*` или эхо | — |
| OK | 757 + 96 через бэклог | ложный сигнал у 18 из 632 сопоставленных (2,8 %): почти все — `invalid`, который код спас | — |

- Механических сбоев — 23 из 941 шага (2,4 %).
- Эхо: 50 строк `[echo]` в логах марафонов, 81 — в Loki за 7 дней. Правды «это было эхо или нет» в данных нет: решение принимает сам `echo_window`, и проверить его не по чему.
- Зависание: `⏱️ [#4135]` — 38 раз за 7 дней в Loki. Сопоставить с ходами удалось 1 раз.
- Живые 210 ходов: `failed` 1, `addressed` без продолжения 4. Разметки у них нет.

**Что из этого следует.**

- Сбои, которые видны в потоке событий, редки и однотипны. Для каждого из них уже есть сигнал в логе — его просто никто не сводит.
- Детектор кодом вида «три фразы подряд пустые у всех STT-провайдеров» или «адресованный ход закончился без `SpeechEvent started` и без тула» ловит их без обучения и проверяется на тех же 23 случаях.
- Модели учиться не на чем: 23 положительных примера, из них 16 — два акта.

## 5. Что дешевле: модель или правила

### 5.1 Модель

**Вычисления [догадка, расчёт без замера].**

- Прямой проход трансформера стоит ≈ 2·N операций на токен. Для 1–20 млн параметров это 2–40 MFLOP.
- CPU Pi 5 (4 × Cortex-A76) на ONNX Runtime в int8 даёт порядка единиц–десятков GOPS. Отсюда сотни–тысячи токенов/с, так что планка Шифу в 100+ токенов/с, скорее всего, берётся.
- Для классификации нужен один проход на событие или на ход, а не генерация. Сравнимо с 28 мс хода по Tier-1.
- Hailo-8 на Vision Pi требует компиляции модели (Dataflow Compiler; пак вендора есть только на katana). Поддержку операций трансформера на нём не проверял.
- Бенч из комментария к карточке **не сделан**: в этом шаге на робота ничего не ставим.

**Данные [измерено] — вот узкое место:**

- 748 ходов марафона на 153 фразах;
- 210 живых ходов без разметки;
- 23 примера сбоя;
- один провайдер LLM.

Отложенная выборка из тех же 153 фраз проверит запоминание, а не понимание.

Чтобы оценить полноту детектора с точностью ±10 %, нужно ≈ 100 примеров на класс [догадка: биномиальный интервал при p≈0,8, n=100 — ±8 %]. При частоте 2,4 % это ≈ 4 000 вердиктов шагов — в 4 раза больше, чем сейчас есть с логами. И это должны быть разные фразы, а не повторы одного сценария.

**Стоимость:**

- конвейер событий в токены;
- обучение;
- отложенная выборка;
- выкладка на Pi или Hailo;
- сравнение с правилами на каждом релизе;
- вторая реализация решения рядом с кодом. По `AGENTS.md` её держать нельзя: модель включается только там, где она измеренно лучше, и тогда правила уходят.

### 5.2 Правила

- **(а)** 46 ходов «команда Tier-1 + болтовня». Решение «хвост — болтовня или вторая просьба» можно сделать структурой: Tier-1 + узкий вызов LLM только на хвост.
  - Грамматику по словам расширять нельзя. Для музыки действует мораторий на регексы (#3132), а строгость Tier-1 — замысел.
  - Но в живых ходах таких 1 из 189. Сначала замер на живых фразах, потом решение.
- **(б)** Полнота у правил уже 100 % на своих фразах. Резерв — точность среза (4,1 предложенных против 0,5 использованных) и STT. Отдельная модель среза на русском, по #4163, не выигрывает.
- **(в)** Два-три детерминированных детектора по сигналам, которые уже пишутся (§4.3). Каждый — функция над событиями, тест на поведение, проверка на 23 случаях архива. Это путь ADR-0148: «код решает». Их же может читать смотритель логов (#4033).

**Итог [догадка, по цифрам выше].** Правила дешевле на всех трёх задачах, пока данных столько, сколько сейчас. Модель имеет смысл:

- для (в), когда сбоев наберутся сотни и появятся классы, которые не описать правилом (например, «зависание» по рисунку событий, а не по таймеру);
- для (а) и (б), если понадобится другой язык (условие пересмотра из #4163).

## 6. С чего начать

1. **Перестать терять данные.** Это нужно при любом решении про модель.
   - Забирать `dialog_events_<run>.db` из контейнера в артефакт прогона, как уже забирается БД дикторов (`collect_e2e_speaker_db`, `e2e_voice_test.sh:3099`). Это файлы `scripts/ci/e2e/` — нужна отдельная карточка: там сейчас работает другой воркер.
   - Запускать `scripts/e2e/archive_e2e_artifacts.py` после каждого марафона.
   - Раз в сутки выгружать из Loki строки ходов `voice-assistant` (фильтры из `evidence/…/README.md`) в закрытое хранилище, иначе живые ходы пропадают через 7 дней.
   - Тексты людей — только в закрытое хранилище: в публичный репо не кладём.
2. **Писать причину итога хода в строку `📊 [turn]`** (`reason`). Сейчас без e2e-БД её не узнать.
3. **Детекторы сбоя кодом** для «робот глух» и «ход без речи». Мерить на 23 случаях архива и на ложных срабатываниях по OK-шагам.
4. **Через ~4 недели пересчитать базу** теми же скриптами (`evidence/robot-event-model-2026-11-09/`). Обучать модель только там, где правилам не хватает и примеров ≥ 100 на класс.
