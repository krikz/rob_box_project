# Диалоговый режим робота — видение целевой системы

> **Статус:** draft (видение товарища Шифу)
> **Дата:** 2026-08-28
> **Назначение:** описать, **какой должна быть** голосовая и диалоговая система робота — целевое состояние, по которому сверяются задачи и фазы. Детали реализации и исторические баги — в связанных документах (§8).

## 1. Общая картина: два «мозга»

У робота два независимых голосовых «мозга», каждый со своим входом и ролью:

| Мозг | Роль | Вход |
|---|---|---|
| **Личность** (`dialogue_node`) | разговаривает с обычными людьми: wake-word → STT → LLM → TTS | ReSpeaker, обычные пользователи |
| **Супервизор-агент** | мозг оператора: команды → инструменты (TTS, музыка, анимации, навигация); набор растёт постепенно | голос Quest + текст Telegram |

Оператор обращается к роботу через **один вход**: голос с Quest и текст из Telegram идут в супервизор-агент одинаково — «мотивируй народ» из Quest ≈ «мотивируй народ» из Telegram.

## 2. Как работает личность (диалоговый режим)

### 2.1 Пробуждение по wake-word
- Робот вступает в диалог **только по wake-word**: `робок`, `робот`, `роббокс`, `робокос`, `роббос`, `робокс`.
- Останавливается по команде «помолчи».

### 2.2 Робот не теряет услышанное (аккумулятор)
- Фразу **без wake-word** робот не отбрасывает, а складывает в **аккумулятор**: текст + `speaker_id` + время (скользящее окно из конфига, дефолт ~3 мин).
- При следующем wake-word накопленное уходит в LLM **отдельным блоком** с разметкой «кто / что / когда назад» + текущий запрос как «гипотетический».
- Голое «робот» (без команды) при непустом аккумуляторе тоже сливает накопленное.
- LLM сама **догадывается**, что в аккумуляторе и было то, о чём просили.

### 2.3 Мультиголосье
- **Робот узнаёт говорящих** (`speaker_id` + биометрия): известный → имя, неизвестный → «незнакомец».
- **Смена говорящего:** голос А «привет я Саша» → новый голос → робот понимает, что это другой человек, спрашивает «кто ты», потом спрашивает про Сашу.
- **Фоновый спор** (без wake-word) → третий голос: «робот, а ты что думаешь, кто прав» → робот отвечает **своё мнение**, а не пересказ.
- **Робот говорит разными голосами** через `set_voice` / `speak_text(voice)`.
- **Идентифицированный пользователь** → у робота есть профиль: имя + накопленные факты + голос/TTS-предпочтения (см. 2.4, 4.4).

### 2.4 Память и сессии
- Сессия сбрасывается **только по желанию юзера** («новая сессия»/`/clear`), никогда по таймеру.
- **Тёрны в БД не храним.** Окно диалога — временное (в памяти): прервали, выключили робота — сессия ушла, и это нормально.
- В долгую память робот пишет **только значимые события/факты** («пользователь любит X», «случилось Y»), а не каждый тёрн.
- Факты хранятся **по идентифицированному пользователю**: робот помнит, что говорил/любит этот человек, и использует это при следующем контакте с ним.
- **Когда сохранять:** если с роботом никто не говорит ~3 минуты — он коротко дописывает в долгую память, что делали и с кем (небольшой объём). Это не сброс сессии, а сохранение сводки.
- Память **честная**: старые тёрны не протекают в новый вопрос.

### 2.5 Планировщик: правки на лету
- Между LLM и исполнителями (TTS, музыка, анимация) стоит **планировщик** (TaskScheduler): LLM планирует, scheduler исполняет по сегментам.
- Робот умеет **договаривать** и **вплетать** правку в уже идущую речь/песню:

```
Пользователь: "Спой песню про комара"
Робот:        [поёт куплет 1]
Пользователь: "И ещё про енота!"      ← во время куплета 1
Робот:        [куплет 1 допевает до конца]
              [куплет 2 уже про енота — без паузы]
```

- **Инвариант:** правка (`update`) трогает только ещё не начатые (`PENDING`) сегменты; **текущий (`ACTIVE`) доигрывает до естественной границы**.
- Классификация нового ввода **до** barge-in: `MERGE | REPLACE | QUEUE | IGNORE | CLARIFY`. `MERGE` — цикл живёт, LLM выдаёт `task_delta` → правка PENDING; `REPLACE` — отменить цикл, дождаться границы ACTIVE, новая задача.

## 3. Как оператор управляет голосом робота (режимы)

| Режим | Кнопка / вход | Что делает | Статус |
|---|---|---|---|
| **рация** | правый grip | мой голос → динамик робота, без обработки | строится (P1–P3 done, P4 e2e) |
| **робот-голос** (стилизация) | левый grip | мой голос → STT → LLM(пресет + язык) → TTS | позже |
| **разговор с супервизором** | голос Quest / Telegram | диалог с ИИ-помощником по управлению: «выключи диалог», «покажи логи», «воспроизведи файл» — по инструментарию | позже |
| **нашёптывание** | режим | я говорю роботу, что делать «будто я юзер»; диалоговый режим не знает о вмешательстве | позже |

### 3.1 Рация
Правый grip → говорю → робот сразу воспроизводит мой голос через динамик, без STT/LLM/TTS. Ни один другой режим рацию не ломает.

### 3.2 Робот-голос (стилизация)
Полный пайплайн: **мой голос → STT → текст → LLM (промт + настройки) → TTS → динамик робота**.
- Каждый распознанный чанк обрабатывается LLM с выбранным **пресетом** и **языком вывода**, затем озвучивается голосом робота.
- Пресеты: технический язык, «по понятиям», как пещерный человек, деловая речь, как философ, как Ленин.
- **Язык вывода:** LLM отвечает на выбранном языке; если TTS не поддерживает письменность (например, иероглифы) — выдаёт **транслитерацию**.

### 3.3 Разговор с супервизором (управление)
На капитанском мостике оператор **говорит с роботом как с ИИ-помощником по управлению** — это полноценный диалог, а не разовые команды:
- «выключи диалоговую часть» → супервизор деактивирует диалог, дальше оператор работает через кнопку;
- «покажи логи» → выводит логи;
- «воспроизведи такой-то музыкальный файл» → играет файл;
- и так далее — зависит от **инструментария** супервизора (набор растёт постепенно).
- **Отвечает голосом в шлем:** супервизор отвечает оператору голосом (в Quest), а не только действиями/логами.
- Тот же вход и поведение дублируются через Telegram.

### 3.4 Нашёптывание
Говорю роботу, что делать, «будто я обычный юзер» (речёвки про ВУЗ, мотивируй молодёжь, поставь музыку), а диалоговый режим **не должен знать**, что вмешался оператор.

### 3.5 Панель режимов (на мостике)
- **Диалог off** — блокировка диалоговой ноды, полное управление оператора.
- **«Только я рулю телеоп»** — в очках + на мостике только оператор управляет движением; фраза «езжай на кухню» от постороннего не сработает.
- Остальные переключатели — продумать (§7).

### 3.6 Панель пайплайна (на мостике)
На мостике выводится **максимальный пайплайн** голоса оператора — каждую ступень можно выключить или настроить:

```
мой голос → STT → LLM → TTS → динамик
```

| Ступень | Что можно |
|---|---|
| **STT** | вкл/выкл — выкл = рация (сырой голос) |
| **LLM** | вкл/выкл — выкл = STT→TTS напрямую («повторить текстом голосом робота»); настройки: пресет + язык вывода |
| **TTS** | провайдер + голос |

- **Быстрый доступ уже есть:** правый grip — рация (сырой голос), левый grip — робот-голос (полный пайплайн).
- **Язык вывода:** LLM пишет на выбранном языке; если TTS не поддерживает письменность (иероглифы) — выдаёт транслитерацию. Пример: «всем привет» + язык «китайский» → LLM выдаёт китайский текст, TTS озвучивает его, а если иероглифы не поддерживаются — в пиньине.

### 3.7 Живое состояние пайплайна (на панели)
Пользователь видит, как его фраза идёт по пайплайну в реальном времени:
- зажал тангетку и сказал → видно, **что распозналось** (текст STT) и **за сколько**;
- дальше — что выдала LLM (текст, пресет, язык) и сколько это заняло;
- затем — что ушло в TTS (провайдер, голос) и что озвучивается;
- каждая ступень показывает статус (ждёт / работает / готово / ошибка) и задержку.

## 4. Музыкальные способности

### 4.1 Диджей
- «Ты диджей» → робот строит **план сета** (тема, персона, трек-лист) и ведёт его с авто-переходами (~45 с).
- Сет **заканчивается** финальным треком и прощанием — не зависает на бесконечной импровизации.
- Перед сетом — research: персона, сэмплы, треки библиотеки.
- Тех-гвардрейлы против какофонии: `Clock.clear()` первой строкой, ≤6 паттернов, amp ≤ 0.8, dur ≥ 0.5 / BPM ≥ 60, без `chop`.
- Wake-word под играющей музыкой не теряется.

### 4.2 Сочинение музыки (Renardo/FoxDot)
- Робот **сочиняет кодом**: LLM пишет live-coding Renardo/FoxDot и исполняет через `execute_music_code` («сыграй renardo бит»).
- Синтезатор — SuperCollider (scsynth + sclang). **Renardo бесплатен** — основная музыкальная способность.

### 4.3 Генерация музыки (открытый вопрос)
- MiniMax Music API (`generate_music`) **отключён** — программная генерация через MiniMax невозможна.
- Осталась библиотека `gen_*` + воспроизведение через sound_node.
- Куда идти — **открытый вопрос**: вероятно другой поставщик (Suno `docs.sunoapi.org` или иной недорогой), self-host MiniMax-Music3 как запасной. **Не в приоритете.**

### 4.4 Голос и синтезатор (TTS)
- **Голос:** `set_voice(voice=...)` / `speak_text(voice=...)`. Список голосов виден LLM.
- **Провайдер/синтезатор:** установка работает и на уровне **провайдера** (явный инструмент смены TTS-провайдера), а не только голоса внутри текущего.
- **Персонально по пользователю:** выбор голоса и TTS — личный: пользователь просит «говори так под меня» → робот сохраняет в профиль этого человека, **какой голос и какой TTS** тот предпочитает, и восстанавливает при следующем контакте.
- **Клонирование голоса (идея, не реализовано):** «говори моим голосом» → робот сохраняет **семпл голоса** пользователя (MiniMax TTS умеет клонировать голос) и использует его для TTS — робот говорит голосом этого пользователя. Семпл хранится в профиле.
- Fallback-цепочка **MiniMax → Yandex → Silero** — аварийная; при фолбеке — дефолтный голос фолбек-провайдера, при возврате — установленный голос восстанавливается.

## 5. Конфликты и правила

- **ReSpeaker AEC — ключевая железка.** Робот аппаратно выкусывает из микрофона то, что сам воспроизводит, поэтому с ним **можно говорить, пока он говорит**. Брали именно для этого.
- **Новая команда во время речи → робот НЕ замолкает.** Он продолжает говорить, слышит новую команду (благодаря AEC) и **вплетает** её через планировщик: текущий сегмент доигрывает, следующие правятся (см. 2.5). Явной остановки TTS по новому вводу **нет**.
- **Собственный вывод и голос оператора не принимаются за команду** — AEC + grace-период + подавление VAD.
- **Рация оператора** — отдельное явное прерывание: оператор жмёт PTT и забирает `voice_floor`, его голос идёт в динамик. Одновременно два голоса невозможны — говорит только держатель floor.
- **Wake-word под играющей музыкой не теряется** (ADR-0024).

## 6. Нефункциональные требования

- Latency рации **< 300 мс**; формат **int16 PCM 16 kHz mono**; аккумулятор ≤ 30 записей.

## 7. Открытые вопросы

- Финальный набор переключателей панели режимов.
- Технический механизм «диалог не знает про нашёптывание».
- Точный объём/формат «сводки» при ~3 мин тишины (что делали, с кем — насколько коротко).
- Порядок фаз для «робот-голос» и «команда супервизору».
- Миграция генерации музыки (Suno / иной поставщик) — **не в приоритете**.
