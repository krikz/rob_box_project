# LLM Voice Selection — пропозал

> Статус: **обсуждено** (13.08.2026, 11 вопросов Q1-Q11)
> Автор: architect
> Связано: TTS chain (MiniMax → Yandex → Silero), issue #1160 observability

## TL;DR

LLM (робот) получает возможность выбирать голос TTS: разово через `speak_text(voice=...)` и персистентно через новый инструмент `set_voice(...)`. По умолчанию используется дефолтный голос текущего провайдера. Список доступных голосов передаётся в системном тёрне рядом с инфо о TTS. При фолбеке провайдера используется дефолт фолбек-провайдера; при возврате исходного провайдера восстанавливается установленный голос.

## Мотивация

Сейчас `speak_text` принимает только `{text, animation}` — голос жёстко задан в конфиге (`YANDEX_TTS_VOICE=anton`). LLM не может:
- рассказать историю от разных лиц (старик → zahar, девушка → alena);
- спеть песню «в несколько голосов»;
- выполнить просьбу юзера «говори голосом Алены».

При фолбеке провайдера (MiniMax 429 → Yandex → Silero) голос меняется молча, и LLM об этом не знает.

## Решения (дискас Q1-Q11)

### Q1. Способ указания голоса
- **Имя провайдера** для текущей TTS (`voice="alena"`);
- **Характеристика** (`voice="female_calm"`) как fallback при фолбеке на другую TTS.

Проверено (deepseek, 13.08): LLM знает пол и характер голосов Yandex по имени из открытых данных, поэтому достаточно передавать список имён — LLM сама подберёт голос под персонажа.

### Q2. Где указывается
Только параметр `speak_text(voice=...)`. Отдельного инструмента на этом этапе нет (добавлен позже в Q7).

### Q3. Что LLM знает о голосах
Список **имён голосов активной TTS**. LLM сама знает пол/характер по имени (проверено). Характеристика — fallback, если имени нет у текущего провайдера.

### Q4. Динамика списка
Список **только текущего/активного провайдера**. При фолбеке — обновляется на голоса нового провайдера.

### Q5. Размещение в контексте
В **системном тёрне рядом с инфо о TTS** (уже передаётся). Строка обновляется при смене провайдера.

### Q6. Недоступный голос
- Говорим **дефолтным** голосом провайдера;
- В результате `speak_text` возвращаем `voice_used=<фактический>` — LLM видит и может поправиться;
- Дефолтный голос — **отдельной строкой** в системном тёрне.

### Q7. Персистентность
- `speak_text(voice=...)` — разовый вызов;
- **Новый инструмент `set_voice(voice=...)`** — держит голос на диалог, пока не сменят;
- По умолчанию (без set_voice) — дефолтный голос TTS.

### Q8. Контекст (что видит LLM)
```
[TTS] provider: yandex | default_voice: anton | current_voice: zahar | voices: anton, alena, jane, ...
```
- `default_voice` — дефолтный провайдера;
- `current_voice` — установленный set_voice (если был);
- `voices` — полный список доступных.

### Q9. Влияние
**Только TTS.** Анимации, личность, поведение не меняются.

### Q10. Проверка (acceptance)
- Юнит: speak_text принимает voice, валидация против списка, fallback на дефолт при неизвестном;
- **E2E-сценарии (~20)**:
  - 10 умных фраз разными голосами;
  - сказка «Красная Шапочка» по ролям (волк — низкий, бабушка — старческий, Шапочка — женский);
  - произвольные истории от 2+ лиц;
  - смена голоса через set_voice и возврат к дефолту;
  - фолбек-проверка: голос, недоступный у фолбек-провайдера → дефолт + voice_used.

### Q11. Фолбек и хранение
- **Фолбек**: при переходе на другой провайдер используется **дефолт фолбек-провайдера**;
- **Возврат**: при возврате исходного провайдера — **восстановить установленный голос** (если он есть у провайдера);
- **Хранение**: в **пользовательском профиле** (speaker_id определяет юзера, профиль ещё не сформирован — голос ляжет туда, когда профиль появится). Промежуточно: in-memory на dialogue_node + привязка к speaker_id.

## Контракт speak_text (изменение)

```json
{
  "tool": "speak_text",
  "params": {
    "text": "...",
    "animation": "happy",
    "voice": "alena"        // опционально; null/отсутствует → current_voice или default_voice
  }
}
```

Результат:
```json
{
  "status": "queued",
  "speech_id": "...",
  "voice_used": "alena",     // фактический голос (после валидации/фолбека)
  "provider": "yandex"
}
```

## Новый инструмент set_voice

```json
{
  "tool": "set_voice",
  "params": { "voice": "zahar" }
}
```

Результат:
```json
{
  "status": "ok",
  "voice_set": "zahar",
  "default_voice": "anton"
}
```

## Риски

1. **Список голосов**: источники списков у провайдеров разные (Yandex — конфиг, MiniMax — API, Silero — фиксированный). Нужен единый реестр voice_ids на провайдера.
2. **Качество LLM-выбора**: deepseek знает пол/характер по имени, но может ошибаться (проверено: путал zahar/женские). Fallback-характеристики (`female_calm`) — надёжный путь.
3. **Фолбек-голос**: восстановление установленного голоса при возврате провайдера требует хранения `(speaker_id, voice)` вне диалога — см. Q11 (профиль).
4. **Тайминги**: смена голоса на лету во время длинного TTS-чанка (batch) — нужен graceful переход между чанками.
