## 1. Что сейчас генерирует аранжировщик (реальный вывод)

`compose_music(name="axelf")` → RTTTL-рингтон → `harmonize` → `arranger.render`:

```python
Clock.clear()
Clock.bpm = 125
d1 >> play('X...o...X...o...', amp=var([0, 0.4125, 0, 0.55, 0], [56, 84, 28, 56, 28]))
d2 >> play('-.-.-.-.-.-.-.-.', sample=3, amp=var([0, 0.108, 0.168, 0], [28, 28, 84, 112]))
p1 >> moogbass([64, 64, 71, 67, ...31 нота], dur=[1, 1, ...], scale=Scale.chromatic,
               amp=var([0, 0.175, 0.5, 0.15], [140, 28, 56, 28]),
               amplify=var([0.3, 1, 0.3, 1, ...], [0.125, 0.875, ...]), lpf=523.3)
p2 >> blip([(52, 64), (55, 67), ...46 — весь рингтон октавами], ...)
p3 >> strings([(64, 67, 71), ...28 аккордов], dur=[1]*28, sus=0.4, lpf=gflt, ...)
Clock.future(252, Clock.clear)
```

## 3. Состояние кода (почему фичи «не складываются в звук»)

- 12 файлов музыки ≈ 14.9 тыс. строк, 478 функций; `music.py` — 5992 строки (#3014).
- Самые большие: `MusicManager.execute_code` 221 строка / CC 22,
  `_build_arrangement` 209, `spec_from_flat` 164.
- Сигнатура на ~40 параметров скопирована 4 раза (`execute`, `_execute_named`,
  `_build_arrangement`, `PreviewArrangementTool._execute_named`).
- ~25 ручек аранжировки (bass_approach, pad_register, lead_outliers,
  key_detection, harmonic_rhythm…) — **ни одна** не меняет ритм во времени
  или паттерны по секциям. В коде 57 разных issue-номеров и 57 пометок
  «FIX (live …)»: эвристики нарастали поверх гармонизатора рингтонов.

Вывод: доводка ручек текущего пайплайна до DJ Dave не доведёт — у него другая
модель (паттерн-луп по секциям), а не «мелодия + аккомпанемент».

## 5. Предлагаемый план (инкрементально, ADR-0013: один PR — один шаг)

1. **P0 — `-z 1024` → блок 64** (`-Z 1024` под JACK). Сначала замер CPU scsynth
   на Pi до/после, иначе не мержить. Выигрыш — все огибающие и свипы.
2. **P1 — новый режим `style="club"` в arranger, рядом со старым** (не
   переписывая). Модель — секции DJ Dave: build 16 / predrop 2 / drop 16 /
   verse 16 / breakdown 8, каждая секция = свой набор паттернов:
   - kick `play("X...")`, clap отдельным плеером, hats `dur=PDur(k,8)` с
     ростом k по секциям, perc `PDur(5,16)` + `delay=0.25`;
   - бас: 8-е на слабую долю (`amp=...*P[0,1]`), `sus≈0.25`, `lpf≤800`;
   - пампинг: `amp=...*P[0.25,0.8,1,1]` на `dur=1/4` (вместо `amplify`-var);
   - риф 1–2 такта из pentatonic (`PRand`/`PWalk`) или 2-тактовая выжимка
     из рингтона (мотив, а не вся мелодия);
   - маски: каждые 4 такта «stutter-gap» на одном слое, филл на 16-м такте,
     в predrop — кик выключен + `hpf=linvar([0,1500],…)` + снейр-ролл
     `dur=var([1,.5,.25,.125],…)`;
   - гейн-стейджинг по таблице §2 п.7, сумма пиков ≤ 1.0.
   Эталон — golden-тест на сгенерированный код + прослушка на роботе
   (запись через `tools/music_bench`).
3. **P2 — DJ-режим держит темп/тональность сета** и меняет слои вместо
   `Clock.clear()` (`dj_mode.py:851`, `arranger.py:1872`).
4. **P3 — техдолг #3014**: общий dataclass параметров вместо 4 копий
   сигнатуры; вынос Renardo-bootstrap из `music.py`.

Маппинг идиом Strudel → FoxDot, на котором построен п.2 (проверено по
исходникам renardo_lib, если не сказано иное): `arrange` → `amp=var([...],
[длины в битах])`; `euclid(5,16)` → `dur=PDur(5,16)`; `.late(1/16)` →
`delay=0.25`; `mask` → множитель `amp=P[...]`; `lpf(sine.range().slow(8))` →
`lpf=linvar([a,b],32)`; `ply(2)` → `.every(8,"stutter",2)`; `jux(rev)` →
`pan=[-1,1]`; `room` → `room=, mix=`; `[~|x]` → `amp=PwRand([0,1],[50,50])`.
Не проверено в Renardo: умножение `var * P` и `var * linvar` — проверить
первым делом на роботе.

## 6. Jev как слой решений для аранжировки (по запросу товарища Шифу)

Наш ресерч `docs/research/jev/` (PR #3101, #3084) про музыку ничего не
говорит — там acceptance/scheduler. Музыкальный пример в экосистеме один:
**Jevthoven** (github.com/cocktailpeanut/jevthoven, `e5e0c67`, MIT, TS, core
≈1.5 тыс. строк; исходники прочитаны, не запускался — ключа нет).

Как он устроен (`app/core/plan.ts`, `grooves.ts`, `barpatterns.ts`):

1. Промпт → план: метр, темп, форма (`buildup_drop`, `AABA`, …), энергетическая
   дуга (`rising`, `rise_fall`…), набор дорожек — **каждое** поле выбирается
   Jev `Choice` из закрытого словаря.
2. Форма компилируется кодом в секции (intro/build/drop/outro).
3. Гармония: Jev выбирает **шаблон прогрессии на секцию**, код раскладывает
   по тактам (раньше было меню из 97 аккордов — самоякорилось на тонике).
4. **Groove grammar**: на каждую дорожку × секцию Jev выбирает точку на
   осях (drums: kick beats/driving/sparse/syncopated/off, snare backbeat/
   third/…, hats 8th/16th/…, accent clave/open_hat/crash; bass: rhythm ×
   pitches root/root_fifth/walking; harmony: block/comp/arp/sustain; lead:
   density × syncopation). Код по seed сэмплирует **кандидатов целого такта**
   из этой области, Jev выбирает такт, код рендерит ноты.
5. ~75–80 платных вызовов на 16-тактовую пьесу из 4 дорожек.

Что из этого брать нам:

- **Главное — не Jev, а грамматика.** «Оси грува на дорожку × секцию +
  кандидаты целого такта + детерминированный рендер» — ровно то, чего нет в
  нашем arranger (§2 п.2–3: секции меняют только громкость). Это и есть
  каркас для `style="club"` из §5 п.2: оси → FoxDot-паттерны (`play()`-строки,
  `PDur`, маски `amp=P[...]`).
- **Кто выбирает точку на осях — подключаемо**, в духе паттерна «код
  генерирует кандидатов, модель выбирает, код исполняет» из
  `awesome-jev-survey.md §2`:
  1. по умолчанию — seeded-детерминированно (офлайн, бесплатно, воспроизводимо,
     golden-тесты);
  2. наша основная LLM, которая уже вызывает `compose_music`, — выбором из
     закрытых списков (не свободным кодом);
  3. Jev через уже готовый `DecisionOrchestrator` класса `QUALITY_CRITICAL`
     (не safety, дедлайн 800 мс, fallback = п.1). Решения принимаются **до**
     старта трека/секции, не в реальном времени звука, поэтому латентность
     Jev (p95 533–830 мс по чужим замерам) не критична.
- Не брать: по-тактовые вызовы (80 запросов на трек — дорого и медленно для
  DJ-сета); хватит ~10–20 решений на трек (план + грув на дорожку × секцию).
- Go/no-go для Jev в музыке — только после `JEV_API_KEY` и слепого сравнения
  на слух «seeded vs Jev» на одних и тех же осях. Сейчас: **не проверено**.

## 7. Референсы товарища Шифу — что из каждого берём

### 7.1 Стенограмма «DJ Dave — How to rave with Code» (прислана 28.09)

Техническая часть — только разбор файла в начале (стр. 12–55 стенограммы),
дальше интервью. Что она говорит сама:

1. **Шапка файла = пульт.** BPM, сэмплы, затем массивы паттернов бочки и
   сайдчейна, переключаемые одним индексом (`pick(beatsss, look)`,
   `pick(sidechain, look)`): «makes it possible for me to make a lot of
   changes at once… if I want to do like a build and a drop». → У нас:
   **одна переменная секции** управляет сразу несколькими слоями
   (кик-паттерн, сайдчейн, фильтр), а не по отдельному `amp=var` на слой.
2. **Один слайдер lpf на бас и ноты сразу** («a slider at the very top…
   controls the low pass filter that's on the baseline and the notes»).
   → Общий макро-фильтр `gflt = linvar(...)` на бас+лид+пэд, движется по
   секциям (сейчас `gflt` только на пэде и не привязан к секциям, §2 п.5).
3. **Главный элемент трека — лид квинтами**, записанный массивом. → Лид
   `(n, n+7)` вместо октавного дублирования целого рингтона.
4. **Бас: 4 ноты в первой части, потом перетасовка нот по минорной
   пентатонике; играется в двух октавах сразу** «to give it some dimension».
   → Бас-риф из 4 нот + вариация `PShuf`/`PRand` по пентатонике во второй
   половине секции; слой `(n, n+12)` (как в перекладке By Design).
5. **Ударные: клэп + брейк-луп**, вокальные чопы. Сэмплов вокала/брейков у
   нас нет — пропускаем (или `loop()` из пака, если разрешат).
6. **Живой сет начинается с «раскрытия» одного лупа**: один сэмпл → короче →
   питч → паттерн → эффекты, потом вводятся остальные слои. Она приходит с
   готовыми файлами, с нуля не пишет. → Для DJ-режима робота: интро трека =
   постепенное включение слоёв по 4–8 тактов, а не весь трек сразу.
7. **Гибридный сет**: переход между кодом и треками фильтром и фейдером на
   микшере. → Переходы между треками фильтр-свипом в одном темпе вместо
   `Clock.clear()` (§5 п.3).

### 7.4 «Bug From Heaven» (eefano, песня Tim Smith) — не танцевальный, но полезен

Акустическая аранжировка, три слоя из **одной** гармонии:
- **Гитара через аппликатуры**: аккорд задан аппликатурой на 6 струнах в
  стандартном строе (`E:"0:2:2:1:0:0"` → ноты 40+0, 45+2, …) — открытые,
  «разнесённые» голосоведения с удвоениями, а не тесные трезвучия, как у
  нашего пэда `(64, 67, 71)`. → Библиотека голосоведений (drop-2 / open /
  гитарные формы) в `harmonize`.
- **Страм**: струны вступают с микросдвигом (`[~ 3@10]` — 3-я струна на
  1/11 шага позже) + `late(1/64)`. → В FoxDot `P+(...)` раскладывает ноты
  группы по `sus`, `P*(...)` — по `dur` (проверено по исходникам
  renardo_lib `Patterns/PGroups.py`: PGroupPlus/PGroupStar). Для страма
  нужен сдвиг в миллисекунды — как именно выразить в Renardo, **не проверено**.
- **Бас пиццикато** на −12 чередует корень/квинту (`"<[1 2]>"`), `lpf(1000)`;
  **струнный пэд** почти не слышен (`gain .1`), удвоен со сдвигом `late(.1)`
  по панораме. → Роли разведены по полосам: гитара `hpf 300 / lpf 5000`, бас
  `lpf 1000`, пэд тихо фоном.
- **Форма и модуляции**: `"<~@2 [[0 1]!2]@16 2@3 3@8>".pickRestart([...])` —
  секции с длинами; последовательность `Am:u:6 E:v:5 Am:u:4 E:v:3` —
  третье поле транспонирует секцию, получается хроматический спуск на
  полутон каждые два такта. → Транспонирование секции как ось вариации.
- **Барабаны — минимум** (райд + малый, `lpf 1800`, `room 1`): жанр решает,
  сколько ударных нужно.

### 7.5 «(4S,4aS,8aR)-…-ol dub» (superlocrianlizardbuzzard) — самая развитая форма из присланных

150 BPM, ~28-тактовый цикл, всё построено на **масках по тактам** и **евклиде**:

- **Поэтапный ввод слоёв** — `mask("<0!N 1!999>")`: хэты с 4-го такта,
  лид-синт с 7-го, бочка и бас с 8-го. То же «раскрытие», что у DJ Dave
  (§7.1 п.6), только записанное декларативно. → В FoxDot:
  `amp=var([0, a], [N*4, inf-ish])` на каждый слой со своим N.
- **Интро-фильтр на весь микс**: `all(x => x.hpf("<999 888 777 667 0!999>/2"))`
  — первые 8 тактов весь микс под hpf, который ступенями открывается до 0.
- **Билд через глобальный гейт**: в тактах 9–12 `all(...)` навязывает ВСЕМ
  слоям ритм `struct("x(3,8)")`, добавляет клэпы, `lpf` пилой 222→2222 и
  нарастающий `shape` (перегруз) за 4 такта; в тактах 25–28 то же с
  `x(5,8)` + `ply` (заикание). → В Renardo есть `Master()` — `Group` всех
  играющих плееров, `setattr` раздаётся каждому (`renardo_lib
  runtime/__init__.py:191`, `Players.py:2200`), и встроенный
  `Ramp(t, ramp_time)` = `linvar([0,0,1,0],[t-ramp_time, ramp_time, 0, 0])`
  — готовый «разгон» в конце каждого t-тактового цикла. Кандидат на
  реализацию §5 п.2 (predrop): `Master().lpf = 300 + Ramp(32, 4) * 3700`.
  **На роботе не проверено**, как `Master()` ведёт себя с нашим
  санитайзером и `Clock.clear()`.
- **Евклид с меняющимися параметрами по тактам**:
  бочка `x(<3!4 5 3!3>, 8, <0 2 0 1 0 1>)` — плотность и поворот меняются
  каждый такт; хэты `x(<7 9 9 8 9 13>, 16, …)`; римшот и клэп тоже евклид.
  → `dur=PDur(var([3,3,3,3,5,3,3,3],4), 8)` (сочетание var внутри PDur —
  **не проверено** в Renardo; запасной путь — `Pvar` из готовых `PDur`).
- **Живость без случайности нот**: `velocity(perlin...)`, `late(perlin
  0.04..0.3)` на лиде (плавающая задержка), `speed(cosine 1.15..1.35 slow 9)`
  на хэтах — медленные LFO на тембр; призрачная копия хэтов
  `superimpose(gain .1, late 1/16)`. → `amp=linvar`/`sinvar` на хэтах,
  `rate=sinvar([...], 36)`; призрак — второй слой нельзя (6 слотов),
  поэтому `echo=` на хэтах.
- **Тональность**: G minor/major пентатоника, через 12 тактов — E minor/major
  (параллельные G major ↔ E minor — мягкий сдвиг); альтерации `1#`, `2bb`
  на ступенях пентатоники для красок. → Смена `Root.default` по секциям
  через `var` — у нас тональность на трек одна.
- **Частотные слоты явно**: лид `hpf 999`, пиано `hpf 555`, бас `lpf 222`,
  ударные `lpf 2222`, общий `postgain .5` на всё. Совпадает с выводом
  §7.4 — каждому слою своя полоса.
- **Синтезированная бочка**: `sine` + огибающая высоты (`penv 32, pdec .2`)
  — 808-кик кодом. У нас сэмплы бочки есть, но для 16 кГц синтез-кик
  (SinOsc с питч-огибающей) даёт чистый низ без артефактов сэмпла — можно
  добавить в `custom_synthdefs` отдельной задачей.

### 7.7 «Another Satellite» (eefano, песня XTC) — как надо играть МЕЛОДИЮ

Это прямой урок для нашего **текущего** режима (мелодия из рингтона):
здесь тоже вся песня держится на транскрибированной мелодии голоса
(`gm_oboe`), но звучит музыкально. Отличия от нашего вывода (§1):

- **Динамика по нотам**: у каждой ноты своя громкость — `d4:.7!3 d4:1` —
  проходящие 0.5–0.7, опорные 1.0. У нас `amp` на весь слой один, все ноты
  рингтона одинаково громкие. → `amp=[...]` по нотам: сильная доля / длинная
  нота / вершина фразы = 1.0, остальные 0.6–0.7 (эвристика по метру и
  длительности, данные есть в RTTTL).
- **Артикуляция**: `clip(.9)` — легато почти вплотную; у нас `sus` общий.
- **Подтяжки**: `c4@4:1:4` — третье поле уходит в `penv` (питч-огибающая):
  длинные ноты в конце фраз подтягиваются/сползают. → В Renardo есть эффекты
  `slide`, `slidefrom`, `glide`, `bend` (`renardo_lib
  runtime/synthdefs_initialisation/python_defined_effect_synthdefs.py:15-33`,
  прочитано; в arranger не используются). На длинных нотах концов фраз —
  `slidefrom=[0, 0, …, 0.03]` (**не проверено** на слух и на 16 кГц).
- **Дыхание**: паузы `~` между фразами; мелодия не непрерывна. Наш лид
  играет рингтон подряд до 12 раз без воздуха (§2 п.1).
- **Секции = разные куски мелодии** (`pickRestart` из 6 фраз: куплет,
  припев, бридж, аутро), а не вся мелодия повтором.
- **Аккомпанемент минимальный**: один гитарный сэмпл, перепитченный по
  корням (`note()` на сэмпле `g3`, `begin/end` вырезают атаку), по одному
  аккорду на такт; ударные очень тихие (`hh .05`, `bd .4/.2`, `rim .2`).
  Лид громче всего (`gain 1.7`). У нас наоборот: пэд бьёт аккорд на каждую
  долю, бочка 0.55 против лида 0.52.

→ Это отдельный от `style="club"` трек работ: **улучшить режим мелодии**
(динамика по нотам, легато, подтяжки на концах фраз, паузы между фразами,
тихий редкий аккомпанемент, лид сверху по громкости). Дешевле club-режима и
сразу слышно на всех рингтонах.

### 7.8 «Polish cow song» (Rogolop) — простая песня, три приёма, которых у нас нет

Гармония минимальная (цикл ступеней 7-4-3 в A minor), барабаны — только
`bd sd` на 0.3. Держится на оркестровке:

- **Один мотив — разные тембры по секциям.** Одна и та же фраза
  `[7 7] [4 4] 2 [- 4] …` звучит аккордеоном (интро, `pan .4`), потом
  фаготом (припев, `pan .6`); в куплете — другой мотив на синт-басе. Каждый
  инструмент молчит вне своей секции (`-!32`). У нас лид-синт один на весь
  трек. → Ось вариации «тембр лида по секциям» (из `MELODIC_LEAD_SYNTHS`).
- **Затакты (анакруза).** Секция начинается не с первой доли: `-!31 [4 4]` —
  31 такт тишины и две ноты-подхода прямо перед входом; бас в каждом такте
  подводит к следующему корню (`- - - [- 4]`, `[- -2]`). У нас бас играет
  корень аккорда на его длительность, без подходов. → Бас: последняя 8-я
  такта = подход к следующему корню (ступень выше/ниже или квинта).
- **Остинато с затуханием**: скрипка играет стаккато-восьмые `[7 -]*2`, а
  `velocity` по тактам `.9 .7 .4 .2` — фраза «гаснет» к концу каждой
  4-тактовки, плюс перенос на октаву `transpose("<[8P 0]>")` внутри такта.
  Это та же «динамика по нотам», что в §7.7, но на уровне фразы. →
  `amp=var([.9,.7,.4,.2], 4)` (по тактам) на остинато-слой.
- **Слои входят через 16 тактов** (скрипка после `-!16`, бас после `-!15`
  и затакта) — то же поэтапное «раскрытие», что в §7.1 и §7.5.

### 7.6 Сводка: что повторяется во ВСЕХ референсах (→ требования к `style="club"`)

1. Форма = маски по тактам (8/16), слои входят поэтапно; интро открывается фильтром.
2. Одна «секционная» ручка меняет сразу много слоёв (`look` / `all()` / `Master()`).
3. Евклид с меняющейся плотностью/поворотом по тактам, а не один 16-шаговый паттерн.
4. Бас/арп короткими нотами 16-ми → пампинг громкостью по шагам бочки.
5. Живость — медленные LFO на фильтр/скорость/громкость, а не случайные ноты.
6. Частотные полосы по ролям + общий `postgain` ≈ 0.5.
7. Билд = глобальный гейт + фильтр-свип + перегруз за 4 такта перед дропом.
8. Для режима мелодии (§7.7, §7.8): громкость по нотам и по фразе, паузы,
   затакты и подходы баса к следующему корню, смена тембра лида по секциям.
