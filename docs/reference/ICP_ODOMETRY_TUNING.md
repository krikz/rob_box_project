# Настройка ICP Одометрии RTAB-Map

## Обзор

Этот документ описывает параметры ICP (Iterative Closest Point) одометрии в RTAB-Map и объясняет, как они были настроены для уменьшения предупреждений о неудачной регистрации.

## Проблема

При работе RTAB-Map с 2D LiDAR сканером возникали многочисленные предупреждения:

```
[WARN] Registration failed: "limit out of bounds: rot: 2.33675/0.78 tr: 1.08605/0.2"
[WARN] Registration failed: "ICP correction too large -> 0.212752 m 0.253105 rad, limits=0.200000 m, 0.780000 rad"
[WARN] Registration failed: "Cannot compute transform (corrRatio=0.015957/0.100000 maxLaserScans=188)"
```

### Анализ проблемы

1. **Translation limit violations**: Робот двигался быстрее, чем ожидалось между сканами (>0.2м)
2. **Rotation limit violations**: Резкие повороты превышали лимит ~45° (0.78 рад)
3. **Low correspondence ratio**: Недостаточно совпадающих точек между сканами (<10% вместо ожидаемых 40%)

## Ключевые параметры ICP одометрии

### Icp/MaxTranslation

**Описание**: Максимально допустимое смещение между последовательными сканами

**Дефолт**: `0.2` (метры)  
**Новое значение**: `0.5` (метры)

**Обоснование**:
- Робот может двигаться со скоростью до 0.5 м/с
- При частоте сканирования ~10 Hz, максимальное смещение = 0.5м/10 = 0.05м
- Но в реальности могут быть задержки в обработке, поэтому запас в 0.5м разумен
- Слишком низкий лимит приводит к ложным отказам регистрации при нормальном движении

### Icp/MaxRotation

**Описание**: Максимально допустимый поворот между последовательными сканами

**Дефолт**: `0.78` радиан (~45°)  
**Новое значение**: `1.0` радиан (~57°)

**Обоснование**:
- Робот с дифференциальным приводом может делать резкие повороты на месте
- При угловой скорости 1 рад/с и частоте 10 Hz: 1/10 = 0.1 рад за скан
- Но при быстрых поворотах или пропуске кадров может быть больше
- Запас до 1.0 рад позволяет обрабатывать резкие манёвры

### Icp/CorrespondenceRatio

**Описание**: Минимальная доля совпадающих точек для успешной регистрации

**Дефолт**: `0.1` (10%)  
**Новое значение**: `0.2` (20%)

**Обоснование**:
- В динамичной среде (движущиеся объекты, люди) не все точки стабильны
- Слишком высокий порог (0.4 = 40%) приводит к отказам в сложных сценах
- Порог 0.2 (20%) - баланс между точностью и надёжностью
- Даже 20% совпадающих точек достаточно для ICP в 2D

### Icp/MaxCorrespondenceDistance

**Описание**: Максимальное расстояние между точками для их сопоставления

**Значение**: `0.1` (метры)

**Обоснование**:
- Точки дальше 10см друг от друга не считаются соответствующими
- Помогает избежать ложных совпадений
- Подходит для разрешения сетки Grid/CellSize=0.05м

### Icp/VoxelSize

**Описание**: Размер вокселя для фильтрации облака точек

**Значение**: `0.05` (метры)

**Обоснование**:
- Уменьшает количество точек, ускоряя ICP
- Соответствует разрешению карты (Grid/CellSize=0.05м)
- Достаточно для точной одометрии в помещении

## Другие важные параметры

### Odom/Strategy

**Значение**: `0` (Frame-to-Map)

**Описание**: Стратегия одометрии
- `0` = Frame-to-Map: сравнивает текущий скан с локальной картой
- `1` = Frame-to-Frame: сравнивает только соседние сканы

**Обоснование**: Frame-to-Map более устойчив к ошибкам накопления

### Odom/ResetCountdown

**Значение**: `1`

**Описание**: Количество неудачных регистраций перед сбросом одометрии

**Обоснование**: Быстрый сброс при потере трекинга предотвращает накопление ошибок

### Reg/Strategy

**Значение**: `1` (ICP)

**Описание**: Метод регистрации
- `0` = Visual (камера)
- `1` = ICP (лидар)
- `2` = Visual+ICP

**Обоснование**: Используем только лидар (2D SLAM без камеры)

## Конфигурация

### Файл: docker/main/config/rtabmap/rtabmap.yaml

```yaml
icp_odometry:
  ros__parameters:
    # ICP параметры - более мягкие лимиты
    Reg/Strategy: "1"
    Icp/PointToPlane: "false"
    Icp/Iterations: "30"
    Icp/Epsilon: "0.001"
    Icp/MaxTranslation: "0.5"
    Icp/MaxRotation: "1.0"
    Icp/CorrespondenceRatio: "0.2"
    Icp/MaxCorrespondenceDistance: "0.1"
    Icp/VoxelSize: "0.05"
    Odom/Strategy: "0"
    Odom/ResetCountdown: "1"
```

### Передача параметров через Launch

Параметры также передаются через аргументы командной строки в `docker-compose.yaml`:

```yaml
args:=--delete_db_on_start
  -p Reg/Strategy:1 -p Reg/Force3DoF:true
  -p Icp/VoxelSize:0.05 -p Icp/MaxCorrespondenceDistance:0.1
  -p Icp/MaxTranslation:0.5 -p Icp/MaxRotation:1.0
  -p Icp/CorrespondenceRatio:0.2
```

## Ожидаемые результаты

После применения этих настроек:

✅ **Уменьшение предупреждений**: Меньше "Registration failed" сообщений  
✅ **Лучший трекинг**: Одометрия не теряется при быстрых движениях  
✅ **Стабильная карта**: SLAM работает более плавно в динамичной среде  
✅ **Резкие манёвры**: Робот может делать повороты на месте без потери трекинга  

## Мониторинг и отладка

### Проверка логов

```bash
# Следить за логами ICP одометрии
docker logs -f rtabmap 2>&1 | grep icp_odometry

# Проверить соотношение успешных регистраций
docker logs rtabmap 2>&1 | grep "Registration failed" | wc -l
docker logs rtabmap 2>&1 | grep "Odom: ratio" | wc -l
```

### Ключевые метрики

В логах смотрите на:
- **ratio**: Должно быть >0.2 для успешной регистрации
- **std dev**: Стандартное отклонение одометрии (чем меньше, тем лучше)
- **update time**: Время обработки ICP (должно быть <10ms)

Пример хорошего лога:
```
[INFO] Odom: ratio=0.234567, std dev=0.001234m|0.002345rad, update time=0.005s
```

Пример плохого лога:
```
[WARN] Registration failed: "Cannot compute transform (corrRatio=0.015957/0.100000)"
[INFO] Odom: ratio=0.015957, std dev=0.000000m|0.000000rad
```

## Дальнейшая настройка

Если проблемы продолжаются, можно попробовать:

1. **Увеличить Icp/Iterations** с 30 до 50 (больше итераций ICP)
2. **Уменьшить Icp/Epsilon** с 0.001 до 0.0001 (более строгая сходимость)
3. **Увеличить Icp/MaxCorrespondenceDistance** до 0.15м (более мягкое сопоставление)
4. **Включить Icp/OutlierRatio** для фильтрации выбросов
