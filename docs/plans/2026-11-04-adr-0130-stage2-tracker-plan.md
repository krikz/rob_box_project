## PR-1 (этот): чистое ядро трекера, без ROS

`src/rob_box_perception/rob_box_perception/tracking/`:

| модуль | что делает |
|---|---|
| `params.py` | все параметры трекера в одном месте (`TrackerParams`), проверка при создании |
| `motion.py` | фильтр Калмана с постоянной скоростью, оси x/y независимы, без numpy |
| `assignment.py` | венгерский алгоритм; запрещённые пары (`None`) не попадают в ответ |
| `tracker.py` | шаг трекера: предсказание → сопоставление активных → повторный захват потерянных → рождение → старение; жизненный цикл `tentative → confirmed → lost → удалён`; событие `close_encounter` (§6) |
| `observation_adapter.py` | `Observation` → `Detection` по полям, без импорта ROS; точка в фрейме не `ok` → причина, а не нули |

Тесты: `src/rob_box_perception/test/unit/tracking/` — пересечение двух людей (точное и с шумом, при любом порядке детекций), пропуск кадров, выход и вход в кадр, вспышка-шум, лицо без тела, `candidate_id` при равном расстоянии, поздний пакет, детерминизм, сверка венгерского алгоритма с перебором.

Нагрузка: 10 людей, 10 Гц, 3000 шагов — **0.36 мс на шаг** (измерено на ПК разработчика, Windows, Python 3.11, **не на Pi**). На Main Pi — догадка: в несколько раз медленнее, порядка 1–2 мс на шаг; проверяется в PR-4.

Чего в PR-1 нет: ROS-ноды, сообщения `Track.msg`, compose, деплоя. Шов без потребителя не появляется: топиков и `_publish_*` нет.

Параметры по умолчанию (ворота 0.8 м, 3 попадания до `confirmed`, `lost` через 1 с, удаление через 10 с и т. п.) — **догадка**. ADR-0130 §2.6 и §8 п.1 оставляют пороги открытыми; калибровать на наборе ADR-0144 (сейчас записана одна пилотная сцена из 13, §10.1).

## PR-2: `Track.msg` и тонкая нода

- `Track.msg` по эскизу §2.14 в пакете сообщений (+ массив для одного кадра, если Шифу выберет так, вопрос 3).
- Нода `perception_tracker` в `rob_box_perception` — только провода:
  - подписка `/perception/observations`;
  - буфер переупорядочивания по `header.stamp` (лицо из `vision-face` приходит позже тела из `vision-hailo` того же кадра; ядро пакет старше предыдущего отбрасывает и считает в `late_batches_dropped`). Размер окна — по замеру задержки, не на глаз;
  - пакет = все наблюдения с одним `stamp` и одним `source`;
  - `to_detection(msg, frame)`, счётчики отказов по причинам (`no_transform`, `transform_stale`, …) — в лог и метрику (§5.1 п.7);
  - публикация `/perception/tracks` с `header.frame_id` фрейма трекера;
  - параметры ноды → `TrackerParams` (один YAML, ядро остаётся владельцем дефолтов);
  - `track_id` = префикс + метка запуска + счётчик, чтобы id не повторялись после рестарта ноды.
- Тесты ноды — на стабах, как у `vision_hailo_node`.
- Гард `seam_without_consumer`: у `/perception/tracks` пока нет подписчика — либо потребитель в том же PR (см. PR-3), либо запись в `seam_allowlist.json` с причиной и ссылкой на PR-3.
- В compose ноду **не** включать.

## Ждёт решения Шифу

1. **Дочерний ADR этапа 2.** §7: «дочерний ADR — перед этапом по ADR-0013». Его нет. PR-1 — только чистое ядро без ROS; варианты: (а) ADR перед PR-2 (нода, сообщения, топики), PR-1 вливается как есть; (б) ADR перед PR-1 — тогда PR-1 ждёт; (в) этот план считать достаточным. Предлагаю (а).
2. **Фрейм трекера, когда нет `map`.** §2.14: `Track.header.frame_id = odom | map`. В `Observation` есть только `base_link` и `map`, `odom` нет. Когда RTAB-Map не публикует `map`, у наблюдений `map_status = no_transform`. Варианты: (а) без `map` треков нет (честный статус в ноде); (б) запасной режим в `base_link` — треки «едут» вместе с роботом, на стоящем роботе работает; (в) добавить в `Observation` точку в `odom` (правка этапа 1). Ядро от фрейма не зависит, решение — в ноде.
3. **Состояние жизненного цикла в `Track.msg`.** В эскизе §2.14 есть `name_state` (про имя), но нет поля `tentative / confirmed / lost` трека. Варианты: (а) добавить `track_state`; (б) публиковать только `confirmed`, `lost` не публиковать. И: одно сообщение на трек или массив на кадр.
4. **Лицо без тела трек не рождает** (решение этого PR, в ADR его нет). Причина: лицо и тело одного человека приходят разными пакетами, и лицо родило бы дубль. Цена: человек вплотную к камере (лицо есть, тела нет) трека не получит. Варианты: оставить / разрешить рождение от лица, если рядом нет трека.
5. **§6 «сброс `confirmed → tentative` у обоих при сближении».** Ядро только отмечает сближение (`close_encounter`, `close_encounter_at`); сбрасывает `name_state` потребитель имени (этапы 3–4). Подтвердить, что так.
6. **История треков ~30 с для поздних улик (§2.5).** «Трекер хранит историю» — в этап 2 (PR-2) или в этап 4, где улики появляются? Предлагаю этап 4: в этапе 2 потребителя у истории нет.
7. **Дефолтные пороги** — догадка до набора ADR-0144. Записывать набор (12 сцен) до PR-4 или мерить PR-4 на живых проходах в мастерской?
