## 1. Главное за сессию

План миграции из хендоффа 2026-09-05 был **пройден по коду целиком** ещё до
начала этой сессии. Но на живом железе агент оператора не работал вообще. За
сессию найдено и починено **пять независимых дефектов**, каждый из которых по
отдельности делал ТАРС неработоспособным.

Метод, который сработал: не доверять зелёным тестам и документам, а идти на
робота и мерить. Каждый дефект найден живым замером, ни один — чтением кода.

| # | Дефект | Как найден | PR |
|---|---|---|---|
| #2131 | Однопоточный `rclpy.spin` голодает `on_result` → таймаут 10 с на КАЖДЫЙ инструмент | тайминги в логе: результат приходит на 1.3–1.7 с ПОЗЖЕ таймаута, дважды | #2153 |
| #2132 | `llm_adapter` подписывает запросы ТАРС как `sender=dialogue_node` → срез режет все операторские инструменты | живая проба `say` → `🚫 Slice blocked` | #2133 |

## 2. Первое, что должен сделать следующий агент

Деплой и проверка. Порядок важен — каждый шаг проверяет свой дефект.

```bash
# 1. Вейк из шлема (#2135). Оператор говорит «ТАРС, ты здесь» в шлем.
ssh ros2@10.1.1.21 "docker logs voice-assistant 2>&1 | grep -E 'Получена фраза|ПРИНЯТО'"
# Ожидание: длительность в СЕКУНДАХ, не 0.02с. И «✅ ПРИНЯТО (wake): ...».
# Если фразы стали целыми, но вейк не сработал — это #2158, см. §4.1.

# 2. Инструменты (#2131).
ssh ros2@10.1.1.21 "docker logs avatar-supervisor 2>&1 | grep 'Timeout ожидания результата'"
# Ожидание: пусто. Раньше — на каждый tool call.

# 3. Звук в шлем (#2136).
ssh ros2@10.1.1.21 "docker logs rob-box-quest 2>&1 | grep 'deliver_audio(operator_tts) ok'"
# Ожидание: строки с ненулевым числом байт (лог добавлен в #2154).

# 4. Мигание (#2144) — глазами в шлеме, с включёнными камерами.
# 5. Экраны ТАРС — глазами: стали 3.0 м, угол прежний.
```

**Полезная проба агента без шлема** (лежит на роботе, `/tmp/probe.py`):
rclpy-узел публикует в `/avatar/command` и слушает `/avatar/command_result` +
`/avatar/tts/request`. Проверено — работает через `docker exec avatar-supervisor`.
Так был пойман и молчащий ТАРС, и таймаут инструментов.

## 3. Доступ к железу

Робот и шлем в одной сети с рабочей станцией — **прямой ssh работает**:

```bash
ssh ros2@10.1.1.21 "docker ps"
```

Когда сеть другая — через katana, см. память `robot-ssh-access`. Внутри
контейнеров ROS живёт в `/ws/install`, не `/ros2_ws/install`.

Шлем Quest 2 подключается по USB, `adb` есть:
`C:\Users\krikz\AppData\Local\Microsoft\WinGet\Packages\Google.PlatformTools_*\platform-tools\adb.exe`.
Скриншот: `adb shell screencap -p /sdcard/x.png` + `adb pull` (**из PowerShell**,
Git Bash ломает пути `/sdcard/...`). Кадр стерео 3664×1920 — левый глаз режется
пополам, так удобнее смотреть.

**Грабли adb:** после перезагрузки шлема авторизация слетает, а новый диалог
«Allow USB debugging» НЕ появляется от `kill-server`/`reconnect`. Помогает
физическое переподключение кабеля в системном меню либо генерация нового
adb-ключа (старый лежит в `~/.android/adbkey.backup-2026-09-08`).

## 4. Ловушки

### 4.1 Вейк может не сработать даже после #2135

В `wake_words.yaml` namespace `operator` — ровно два варианта: `тарс`, `tars`.
Живой замер показал, что STT теряет «Т»: `✅ ПРИНЯТО (respeaker): арс расскажи
мне анекдот`. Если из шлема будет то же — вейк не сработает.

Оговорка: замер с ReSpeaker, не со шлема. По шлему данных нет, потому что до
#2155 туда целых фраз не доезжало. Карточка — **#2158**, там же вторая
гипотеза: «Т» может резать клиентский VAD-гейт, и тогда правка не в списке
слов, а в пороге/предбуфере `voice_capture.ts`.

### 4.2 Сторож ADR-номеров пропускает коллизии — трижды за день

`validate_adr_namespace.sh` сравнивает новый номер **только с `develop`** и не
видит, что два открытых PR взяли один и тот же. За сессию разводил руками
трижды: 0072, 0073, 0075. Каждый раз оба PR были **зелёными в CI**.

Хуже: #2139 брал `ADR-0067`, **занятый в develop**, — сторож локально даёт
`EXIT=1`, а в CI чек зелёный. То есть гейт не отрабатывает и на прямых
коллизиях. Это ровно то, о чём #2072: «сторож есть, но мержем его обходят».

Следствие, которое уже случилось: три дочерних PR кластера #2138 влились в
`develop` со ссылками на `ADR-0067`, где лежит совсем другой документ. Девять
ссылок из production-кода и CI-скриптов вели в пустоту. Починено в #2139.

**Перед заведением ADR:** свободный номер — от **0077**. Занятые в develop —
до 0076 включительно. Всегда прогонять сторож руками, не полагаясь на CI.

### 4.3 Тесты `rob_box_quest` молча скипаются целиком

`audio_common_msgs` на dev-машине нет → весь пакет скипается. Именно так один
раз по ошибке закрыли #1992. Правильный приём применён в #2155: логику выносить
в чистый модуль без rclpy, а для тестов уровня моста делать conftest с
заглушками. Проверять не «зелено», а что тесты **выполнились**.

### 4.4 Карточки не закрываются автоматически

`#2131, #2132, #2135, #2136, #2137, #2142, #2143, #2144` — **все OPEN**, хотя их
PR влиты. Авто-закрытие (#2129) влито, но не отработало. Закрывать руками либо
разбираться с гейтом.

### 4.5 Развёрнутые версии ≠ `develop`

Образы на роботе тегированы `-dev` и не пересобираются сами. `webxr_client` —
TypeScript-приложение, раздаётся с робота; фиксы UI без пересборки quest-образа
до шлема не доедут.

## 5. Что я сделал неверно

Записано специально: следующий агент должен видеть, где рассуждение подвело.

1. **Диагноз #2138 был неверен.** Я написал, что клиент шлёт `voice_id: ""`,
   сославшись на `main.ts:279-293`. Это `sendStyleChange` — путь AV-28 (стиль и
   язык). У пикера свой путь, `main.ts:832-851`, и он шлёт **настоящий**
   `voice_id`. Поймал #2139. Причина #2138 до сих пор не установлена.

2. **Списал мигание на upstream.** Нашёл three.js issue #29294 с совпадающим
   симптомом и объявил, что наш код чист. Владелец проверил официальный пример
   three.js на том же шлеме — **не мерцает**. Вывод был опровергнут за минуту,
   после чего бисект дал настоящую причину. Урок: совпадение симптома с
   upstream-issue — не доказательство.

3. Едва не удалил ветки с непримененной работой. Спасло правило ADR-0047:
   критерий — не состояние PR, а `merge_commit_sha` в целевой ветке. У **каждой**
   ветки с влитым PR нашлись коммиты, добавленные после мержа.
