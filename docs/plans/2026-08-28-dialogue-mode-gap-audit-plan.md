## Ф2. Ядро: правка на лету без замолкания (§2.5 + §5)

> Самая дорогая фаза. Разбита так, чтобы каждый шаг был отдельно
> прогоняемым и обратимым флагом.

- **Ф2.1 Feature-flag.** Параметр `barge_in_policy: replace | classify` в `dialogue_node.yaml`, дефолт `replace` (текущее поведение). Все шаги ниже включаются только под `classify`.
  Файлы: `dialogue_node.py`, `docker/vision/config/voice_assistant/dialogue_node.yaml`.

- **Ф2.2 `quick_decide` — правила-уровень.** Чистый модуль `rob_box_voice/scheduler/quick_decide.py`: `(text, active_task) → Verdict` из `{IGNORE, PENDING_LLM}`. Правила ловят только явный мусор (шум, междометия, повторы) — согласно решению ревизии v5 (`SCHEDULER_DESIGN.md:554-604`, «уровня 2 нет»). Всё остальное → `PENDING_LLM`.
  Acceptance: правила решают мусор за < 50 мс на ≥ 50% случаев из корпуса живых логов.

- **Ф2.3 Сегментная модель.** Добавить `Segment` со статусами `PENDING / ACTIVE / FROZEN / DONE` в `scheduler/task_scheduler.py` рядом с `SchedulerTask`. `FROZEN` — сегменты, уже уехавшие в пре-ген (`pre_gen.py` уже знает это слово: `speculative_executor.py:89`).
  **Инвариант к тесту:** `ACTIVE` не отменяется никогда, доигрывает до естественной границы.

- **Ф2.4 `TaskScheduler.update(task_id, delta)`.** Правит только `PENDING`-сегменты. Касание `FROZEN` → отменить пре-ген с `CANCEL_REASON_MERGE_TOUCHED_FROZEN` (константа уже есть) и перегенерировать.

- **Ф2.5 Контракт `task_delta` с LLM.** Новый MCP-тул (или поле в ответе) + блок `[SEGMENT PLAN]` в динамический системный контекст рядом с уже существующим `[ACTIVE TASKS]` (`dialogue_node.py:2470`). Формат — `SCHEDULER_DESIGN.md §7.1`.

- **Ф2.6 Снять безусловный `_cancel_run`.** `dialogue_node.py:1809` — вызывать `_cancel_run` **только** при вердикте `REPLACE`. При `MERGE / QUEUE / CLARIFY` цикл живёт, `STOP` в `/voice/tts/control` не публикуется (разрешение блокера П1, `SCHEDULER_DESIGN.md §4.4`).
  ⚠️ Самая рискованная правка во всём плане: `_cancel_run` сейчас также освобождает TTS-локи (`release_all_tts`) и чистит sound-события. Нужен отдельный путь «не отменять, но не залипнуть».

- **Ф2.7 e2e.** Переписать `00_barge_in.yaml` (сейчас он закрепляет старое поведение) + новый сценарий `05_merge_song.yaml` — дословно «комар + енот» из §2.5: куплет 1 допевается, куплет 2 уже про енота, паузы нет.
  Acceptance: `assert_tts_not_stopped` между двумя STT-инъекциями.

- **Ф2.8** Обновить `SCHEDULER_DESIGN.md §11.6` (таблица статусов) и §12 (список OPEN issue).

## Ф3. Память по спеку (§2.4)

- **Ф3.1** Параметр `persist_turns: false` (дефолт по спеку). При `false` — `dialog_core` не вызывает `append_turn`, окно диалога живёт в памяти процесса. Файлы: `rob_box_harness/core/dialog_core.py:533,559,1036`, `memory/sqlite_voice.py`.
  Зависит от **Q3** (что делать с существующей `~/.rob_box/voice.db`).
- **Ф3.2** Idle-сводка: таймер ~180 с тишины → отдельный вызов LLM «коротко: что делали и с кем» → `save_fact(scope=speaker:<tag>)`. Точка врезки — `dialogue_node._on_inactivity_check:4583`. **Не** сбрасывает сессию. Зависит от **Q5**.
- **Ф3.3** Детектор смены говорящего: `speaker_tag` изменился внутри активной сессии → системная подсказка в `[SYSCTX]` («сменился собеседник, предыдущий — Саша»). Зависит от **Q4**.
- **Ф3.4** Мерж профиля «незнакомец → представился»: перенести факты со временного tag на постоянный `speaker_id`. Зависит от **Q10**.
- **Ф3.5** Тест «память честная»: после «новой сессии» ни один старый тёрн не появляется в `messages` следующего запроса.
