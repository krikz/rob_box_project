## 0. Главный принцип — мы ВНУТРИ робота

Мостик — **эгоцентричный** RViz. Начало координат сцены = `base_link`,
жёстко. Оператор стоит в кабине; передний экран — это вид из робота.
Мир едет вокруг оператора: карта доворачивается под курс
(`mapPlaneTransform`), лидар рисуется от центра, путь и цели — тоже в
`base_link`.

**Модели робота / URDF / TF-дерева «со стороны» в сцене нет и не будет** —
это другой вид приложения (решение товарища Шифу, 28.09).

Следствия для всех новых слоёв:

| Слой | Система, в которой пришло | Как рисуем |
|---|---|---|
| Карта `map_2d` | `map` | доворот по позе робота (уже так) |
| Лидар `lidar_2d` | `laser` → `base_link` | как есть, от центра |
| Путь Nav2 | `map` | на клиенте: `map → base_link` по последней позе |
| След одометрии | `odom`/`map` | то же, хвост N точек, гаснет по времени |
| Nav-цель | оператор тыкает лучом в пол (`base_link`) | клиент пересчитывает в `map` по позе, шлёт `nav_goal` |

## 2. Что на каких экранах

Оператор стоит на подиуме в `(0,0,0)`, смотрит в −Z.

| Место | Что показываем | Поток | Почему там |
|---|---|---|---|
| Главный экран-стена `(0,1.5,−3.9)` | вид вперёд из робота | `camera_rear` (OAK-D color) | это «лобовое стекло» кабины |
| Потолочный экран | камера потолка | `camera_ceiling` | смотришь вверх — видишь верх |
| Левое крыло TARS (+50°) | речь TARS, диалог | `/tars1/text` | ближе к голосовому пайплайну |
| Правое крыло TARS (−50°) | метрики / логи | Prometheus / Loki | диагностика |
| Боковая панель −75° | глубина OAK-D | `camera_oak_depth` | вторичный сенсор |
| Пол | карта + лидар + (волна 2) путь Nav2, след, цель | `map_2d`, `lidar_2d`, `nav_path` | RViz-слой под ногами |
| Стена слева вверху | статус-HUD + (волна 1) суммарный трафик | `robot_status` | всегда в поле зрения |
| Панель «ПОТОКИ» (волна 1) | профили подписок, кбит/с и fps по каждому потоку | клиентский счётчик | управлять каналом, не выходя из VR |
| Голо-проекторы `(±1.0, 0, −1.8)` | (волна 3) кандидат под 3D-облако / детекции в миниатюре | `lidar_3d` | голограмма — естественное место для 3D |

## 3. Подписки и тонкий канал

Сейчас: клиент подписывается сам (`SUBSCRIBE{topic}`), камеры на роботе
включаются только при живом зрителе (linger 5 с). Этого мало для
интернета: поток идёт с той частотой, с какой публикует ROS.

Волна 1:

- `SUBSCRIBE{topic, max_hz?}` — лимит частоты на сессию × поток на
  стороне сервера (кадры сверх лимита отбрасываются, выживает свежий).
- Клиентский `SubscriptionManager` с профилями:

| Профиль | Камеры | Лидар | Карта | Статус |
|---|---|---|---|---|
| **LAN** | все, полная частота | полная | да | да |
| **Интернет** | главная ~5 Гц, боковые выкл. | 5 Гц | да | да |
| **Минимум** | нет | 2 Гц | да | да |
| **Свой** | как настроил оператор | | | |

- Счётчик трафика на клиенте (кбит/с, fps по потоку + итог), выбор
  сохраняется в localStorage.

Дальше (волна 3): `quality` (сейчас принимается и игнорируется) →
реальный пережим JPEG на роботе или H.264; `stream_stats` от сервера
(сколько отброшено).

## 4. Отладка без шлема

Волна 1: `index.html?sim=1` — mock-робот прямо в браузере (без сервера):
настоящий протокол, настоящие кодировки потоков, простой мир-полигон,
кинематика по `teleop_twist`. Ходьба по мостику: pointer-lock + WASD,
езда роботом — стрелки с зажатым Space, E — аварийная остановка.
