## 1. Диагноз: какие оси заморожены и почему

Товарищ Шифу 05.10 на слух: «подложка всегда одна и та же, инструменты одинаковые; у живых диджеев большой спектр разнообразия; почему все тесты были заточены под попкорн и пару мелодий; принимать нужно сет из нескольких случайных мелодий из базы, с оценкой разнообразия помимо гармонии и лада». Замер подтверждает (фактура §4, PR #3416 `diversity.py --offline 5 --seed 20261005`, 25 треков на случайных темах): **пэд 1, лид 2, бас 2, бочка 1, форма 1**, индекс разнообразия состава 0.148.

Что меняется от трека к треку сегодня: тоника (квинтовый ход, `set_plan.py:65-67`), прогрессия (8 шт., `arrange/harmony.py:15-18`), каркас хэтов (5 шт., `knowledge.py:219-225`), хук и его развитие (`arrange/hook.py:238`), сэмплы psr/луп/FX (`arrange/samples.py:38-40`), энергия (волна `knowledge.py:54`). Что заморожено — и почему (фактура §2.1–§2.2, сверено):

## 2. Модель разнообразия

### 2.1 Оси и кто их фиксирует

Принцип: **тема фиксирует характер, сет — грув, трек — материал.** Каждая ось — данные в `knowledge`, выбор — код по сиду со штрафом за недавнее (`diversity.weighted_pick`, `diversity.py:105`), история — `music_history` (`:59-66`) плюс `SetMemory` между сетами (`engine/session.py:60-85`).

| Ось | Фиксирует тема (`ThemeProfile`) | Фиксирует сет (`SetPlan`) | Меняется по трекам (`TrackPlan` → `compose`) | Память |
|---|---|---|---|---|
| Жанровое окно (темп, бочка по умолчанию, лады) | предлагает строка темы или хеш | **один жанр на сет** (I7: один темп; В6) | — | `music_history.bpm`, новое поле `genre` — штраф между сетами |
| Темп, свинг | окно жанра | один (`set_plan.py:88-92`) | — | как сейчас |
| Семья тембров (`dark/hard/bright/warm`) | да (`THEME_TIMBRE :459`) или LLM из перечня | — | — | — |
| Синт пэда / лида / баса | семья даёт пул ≥ 2 / ≥ 3 / ≥ 2 | — | **да**, из пула семьи, со штрафом по `music_history.pad/lead/bass` (колонки есть `:59-66`, пишутся `:274-279`) | между сетами через `SetMemory` |
| Рисунок пэда (`pumped16` / `held` / `stabs`) | — | — | **да**; `held` — без сайдчейна (ниже §3.2) | новое поле `pad_figure` |
| Рисунок баса (`offbeat` / `rolling8`) | — | — | да | новое поле `bass_figure` |
| Бочка (сэмпл) | — | пул жанра (`GENRE_KICKS[genre]` ≥ 2) | **да**, со штрафом (`kick` — колонка есть `:62`, сейчас не пишется) | между сетами |
| Каркас ударных | — | — | да (есть, `:219-225`) | есть (`kit`) |
| Форма трека (шаблон, длины секций) | — | — | **да**, из `FORMS` (≥ 3), первый трек сета — всегда с полным интро (блэнд) | новое поле `template` (колонка есть `:61`) |
| Энергия | — | волна / поправка LLM | да (есть) | — |
| Прогрессия, тоника, лад | лад — у хука | тоника сета | да (есть) | есть |
| Хук и развитие | хуки темы (код) | порядок/подмножество — LLM | да (есть, штраф между сетами #3408) | есть |
| Сэмплы psr / луп / FX | — | — | да (есть) | есть |

Что **не** варьируется и почему: темп внутри сета (I7), жанр внутри сета (вопрос В1 §9: по умолчанию нет — живые диджеи держат один грув 20–60 минут; Kim et al. 2020, research 2.1), бочка внутри трека (вид секции `LOOKS :401-405` меняет рисунок, не сэмпл).

### 2.2 Как это выражено в данных

```python
# set_plan.py — возвращаются поля ADR-0149 §4.5
@dataclass(frozen=True)
class TrackPlan:
    no: int; energy: int; root_shift: int
    template: str        # ключ knowledge.FORMS  (сейчас форма одна, compose.SECTIONS)
    kick: str            # ключ knowledge.KICK_SOUNDS из пула GENRE_KICKS[plan.genre]
    timbre: Timbre       # frozen: pad, lead, bass (синты семьи), pad_figure, bass_figure

@dataclass(frozen=True)
class SetPlan:
    ...; genre: str      # ключ GENRE_WINDOWS; сегодня всегда "club" через ThemeProfile.genre
```

`compose(plan, no, history)` читает всё из `plan.track(no)`; свой `random.Random(f"timbre:{seed}:{no}")` в `compose.py:235` уходит — выбор делает `set_plan.seeded_plan` с историей, одним местом для всех осей (сейчас тембр выбирается в `compose`, остальное — в `compose` тоже, но история для тембра **не используется**: `mix.timbres` `mix.py:100-103` — `rng.choice`, без `weighted_pick`). Валидатор `model.validate` (`model.py:393-400`) дополняется: `template ∈ FORMS`, `kick ∈ KICK_SOUNDS`, синты ∈ пула семьи, и — новое — **бюджет нагрузки** (§3.6).

`knowledge` получает: `FORMS` (шаблоны форм, §3.4), `KICK_SOUNDS` ×N + `GENRE_KICKS`, `TIMBRES` с ≥ 2 пэдами на семью, `PAD_FIGURES`, `BASS_FIGURES`, `GENRE_WINDOWS` ×2–3 (§3.5, после В1), `LAYER_BANDS` (полосный замер слоёв, §3.1), `LOAD_BUDGET` (§3.6). Одна таблица знания — остальные импортируют (ADR-0149 §2.1).

### 2.3 Что пишется в лог трека (I24, A12/A13/A16 по записи)

На `started` (там, где `SetSession` уже знает модель: `engine/session.py:206-218`, `self._models`) в ту же строку лога добавляется `composition={...}` — компактный JSON вектора состава в осях `diversity.py --dir` из #3416 (`AXES`, `scripts/music/live_dj/diversity.py:33`): `pad, lead, bass, pad_figure, bass_figure, kick, kit, template, bpm, mode, root, hook, progression, loop, fx, energy, history_key`. Полная `Track` как JSON — в файл `/data/music_v2/tracks/<track_id>.json` (I24: «полная модель в логе»; в строку лога она не лезет). `diversity.py --dir` тогда считает состав **по логу**, а не офлайн-реконструкцией; проверка A13 «прогрессия ≤ 3/10» перестаёт зависеть от `SetMemory` до серии (`acceptance_2026-10-05.md` §A12–A13).

## 3. Палитра: что добавляется и как каждое попадает в модель громкости

### 3.1 Способ и место замера (честная модель громкости остаётся)

Правило не меняется: в выбор идёт только слой с замером (`LANE_DB_AT_UNIT :351-354`). Меняется **объём** замера и **что** меряется.

- **Что меряется.** Как раньше — dB RMS слоя при известном `amp` в NRT 16 кГц через `masterfilter dyn 0` (`LOUDNESS_SOURCE :335-338`), плюс **полосы** того же рендера: доли энергии < 150 / 150–2000 / > 2000 Гц (те же границы, что `compare.py`) → `knowledge.LAYER_BANDS[role][synth] = (low, mid, high)`. Без полос модель микса не может предсказать A9 (§4): `space` был громче модели на 4–6 дБ **в середине** (`:450-451`), и это узнали только по записи робота.
- **Чем.** Харнесс v2 `scripts/music/loudness_nrt_v2.py`: `render(track) → Program → render.events.program_events` (есть, `render/events.py`) → партитура OSC (`/s_new` с таймстампами) → `scsynth -N` на 16 кГц с SynthDef-ами Renardo 0.9.13 + `custom_synthdefs/` + `masterfilter.scd` → WAV → RMS и полосы по слою. Это перенос идеи удалённого `club_loudness_nrt.py` (`06919517a^:scripts/music/club_loudness_nrt.py`, docstring: «рендерит реальную программу … в scsynth NRT на 16 кГц, как на роботе»), но от модели v2, без эмуляции `Players.py` v1. Режимы: `--sweep-synths <роль> <синты…>` (таблица слоёв), `--sweep-kicks`, `--track <seed>` (A9 по модели против записи).
- **Где.** Предложение (вопрос В4 §9): **katana**, ручной workflow `L: Music NRT loudness` в контейнере из образа `supercollider` репо (там sclang + scsynth + `custom_synthdefs`), с `pip download renardo_lib==0.9.13 --no-deps` для `.scd` Renardo и паком сэмплов `0_foxdot_default` + DJ_Dave (Ресурсный пак, ADR-0125/0126). На роботе NRT **не гоняется** (ADR-0149 §9.1: «NRT — только офлайн на katana, не на роботе»); на Windows у воркера SuperCollider нет (`docs/music_bench.md`). Запасной путь, если на katana нет сэмплов: контейнер `supercollider` робота в простое под `flock /tmp/music_test.lock`, тяжёлые контейнеры погашены — это не NRT «на лету», а разовый прогон 5–10 минут.
- **Регресс самого харнесса.** Первый прогон обязан воспроизвести 29.09: `sinepad −74.4`, `pluck −53.4`, `bass −24.4`, `four_on_floor −24.6` (`:340-346`) в пределах ±1.5 дБ; расхождение больше — харнесс не принимается, пока причина не названа (ADR-0018).
- **Бочки** меряются **на роботе**, как 02.10 (`KickSound`, `:464-478`: `jack_rec`, одна бочка 4/4 @130, доля < 250 и < 120 Гц), потому что известный дефект «`X` без `sample=` звучит щелчком на роботе, хотя файл на 99 % ниже 250 Гц» (`:476-478`) — именно расхождение NRT и живого тракта. Скрипт `scripts/music/live_dj/kicks_probe.sh`: по одной бочке на 30 с, `compare.py` на каждую.
- **Синт в палитре и синт на сервере — разные проверки.** Палитра (`SYNTH_PALETTE`) ⊆ подтверждённые прелоадом (`music_stack_validation.confirmed_synths_from_log`); `PlayerOwner.check` до exec (ADR-0149 I15) остаётся.

### 3.2 Пэды (главная жалоба)

Сейчас один рисунок — аккорд на каждой 16-й с `sus` = шаг (`compose.py:113-121`), потому что сайдчейн «S» живёт на событиях (`amplify`, `render/renardo.py:101-116`). Отсюда и один синт. Решение — **рисунок пэда как ось** (`PAD_FIGURES`), и у каждого рисунка свой пул синтов:

| Рисунок | Что звучит | Сайдчейн | Синты (пул → после замера) | Нагрузка |
|---|---|---|---|---|
| `pumped16` (сейчас) | аккорд на каждой 16-й, `sus` = шаг | да (`DUCK_ROLES :387`) | `sinepad` (замерен), `ambi`, `pads`, `mhpad` (подтверждены на роботе, не замерены) | 16 событий × 3 ноты × 2 голоса на такт — самый дорогой |
| `held` | аккорд на 2 такта, `sus` = 8 долей, смена по голосоведению | **нет** (качание даёт бас и psr-слой) | `warmpad` (замерен −43.1; хвост 1.2 с — для `held` это плюс), `strangerpulsepad` (custom, хвост 1.6 с), `space` (замерен; с полосной моделью §4), `marchstrings` (custom, `held`) | 1 событие × 3 × 2 на 2 такта — в ~30 раз дешевле |
| `stabs` | аккорд на оффбит-восьмых («и» долей 1–4), `sus` короткий | да | те же, что `pumped16`, плюс `pluck`/`karp` в регистре пэда | 4 × 3 × 2 на такт |

Это DJ_Dave-приём «один слайдер» (`LOOKS :390-405`): энергия секции по-прежнему переключает рисунок бочки и глубину насоса, а `held` просто не подписан на насос. Гипотеза на слух: `held` на тёмном пэде в брейке — то самое «восхождение», которого эксперт 05.10 не услышал. Стерео два голоса (`ROLE_STEREO :504-512`) — у всех рисунков. Цель палитры: **≥ 5 замеренных пэдов, ≥ 2 на семью**, в двух рисунках.

### 3.3 Лиды и басы

- Лиды: замерить все 10 из `SYNTH_PALETTE["lead"]` (`:187`) плюс подтверждённые `bell`, `kalimba`, `steeldrum`, `keys`, `pianovel`, `glass`-класса нет в прелоаде (фикстура) — только то, что есть. Семья получает 3–4 лида; `karp`/`marimba` остаются с честным максимумом (`mix._level :81-84`: не громче потолка `amp`). Хук на `bell`/`kalimba` в `break` (половинные) — гипотеза на слух, A/B.
- Басы: `subbass`, `jbass`, `moogbass`, `donk`, `wobblebass` (подтверждены), `tb303` (пропатчен в образе, research 3.8). Семья — 2–3 баса. `BASS_FIGURES`: `offbeat` (сейчас, `arrange/bass.py`) и `rolling8` (тоника на каждую восьмую, без октавы) — оба комплементарны прямой бочке (ADR-0149 §3.4). `acid16` с огибающей фильтра на ноту (research 1.2/3.8, `lpf=[...]` списком) — **после** замера `tb303`, отдельный PR, только для `hard`.
- Полосное правило (§3.1): лид с долей < 150 Гц > 0.05 или бас с долей 150–2000 > 0.5 при своём уровне роли **не отвергается**, а получает поправку уровня по модели A9 (§4). Отвергается только синт, который на потолке `amp` не дотягивает до уровня роли более чем на 12 дБ (его не слышно за бочкой — честный `WARNING palette_too_quiet{synth}`, не тихое исключение).

### 3.4 Бочки

Новые слои не должны раздуть `late` (05.10: 75 строк 2–150 мс при тяжёлых контейнерах, 0 — без них; фактура §2.3, §2.6). Модель уже знает все события (`render.events.program_events`), поэтому:

### 3.7 Сравнение с эталоном по полосам и динамике

Эталон @16 кГц (`ref_dj_16k_profile.txt`, медианы): низ/середина/верх **0.65 / 0.32 / 0.01**, RMS −24.7, crest 15.7, минуты от −40 (интро) до −13 (пик), размах 8.9 дБ. Робот 05.10: низ 0.30–0.41, RMS ≈ −28, crest 17–19, размах 5.3–6.4.

## 4. A9 против разнообразия: решение

Факты: A9 (низ 0.5–0.8) считается по минутам (`compare.py --chunk 60`), а по секциям 05.10 — build 0.25 (без баса по #3396), drop 0.42, break 0.05 (без бочки и баса по построению), drop2 0.38 (`acceptance_2026-10-05.md`, таблица секций). Метрику поднимали, сужая палитру (PR-3c `space`, #3394 лид, #3396), и она всё равно упала. Модель микса (`test_low_share.py:1-8`, #3401): низ дропа на роботе = **0.62 × модельная доля бочки+баса**; после #3411 ожидание 0.53/0.50, вживую после #3411 **не мерено** (фактура §1: «проверено расчётом, не вживую»).

Решение (три части, все — «решает код»):

1. **A9 считается по дропам, не по минутам.** Критерий: медиана низа по секциям `drop*` каждого сета ≥ 0.5 (`sec_bands.py`, уже есть в приёмке 05.10), по минутам — только страховка ≥ 0.35 (ниже — середина явно перевешивает). Брейк и build «без низа» — замысел дуги (ADR-0147, #3396), а не дефект. Вопрос В2 §9.
2. **Тембр не исключается из палитры за A9 — ему считается уровень.** Полосный замер (§3.1) даёт модели микса долю низа **на трек**: `mix.mix_parts` (`mix.py:154-165`) получает `predicted_low(drop)`; если < 0.8 (модельный порог из `test_low_share.py:21`: 0.5 / 0.62), уровень пэда и лида в дропах опускается ступенями по 2 дБ (не ниже «неслышно» −12 дБ от цели роли) до выполнения; не дотянули — трек всё равно играет, в `composition` пишется `a9_model=0.7x` (честно, не тихо). Так `space` и `warmpad` возвращаются в палитру с тем уровнем, которого они стоят, а не выкидываются.
3. **Низ держат бочка и бас — их пулы растут первыми** (§3.3–§3.4): бочка с суб-долей и `subbass`/`jbass` поднимают 0.65 вернее, чем любое вычитание середины. Порядок PR отражает это (§7).

Что остаётся правилом: `ROLE_LEVEL_DB :365-380` — одна точка уровней ролей; ступени A9-модели — поправка **на трек в `Mix`**, не новая таблица.

## 5. Тема и LLM (ADR-0148: код решает, LLM говорит)

Находка 05.10 (фактура §2.6): LLM-редактор сета вытеснил хуки темы, найденные кодом (`terminat, theme_178, theme_177`), хуками строки таблицы `cyber` (`robotroc, robot`), и валидатор это пропустил — потому что кандидаты = хуки профиля **плюс все строки таблицы плюс пул** (`rob_box_music/reasoner.py:62-65`), а промпт прямо разрешает «или других, если они ближе к теме» (`:100-101`). Результат — «терминатор» 1/4 треков с темой вместо 4/4.

Правило: **хуки темы, найденные кодом (`ThemeProfile.theme_hooks`, `theme.py:37`), — решение кода.** LLM:

| Может | Как | Не может |
|---|---|---|
| выбрать **порядок и подмножество** хуков из `theme_hooks` (≥ 1) | `hooks: enum = theme_hooks` — только они, когда `theme_hooks` непусты; строки таблицы и пул — кандидаты **только** при пустых находках | добавить хук не из находок; заменить найденное по теме строкой таблицы |
| уточнить лад из окна жанра | `mode: enum` (есть) | темп (есть: нет в схеме) |
| выбрать дугу энергии | `energy[]` (есть) | длительности, форму конкретного трека |
| выбрать семью тембров | `timbre_family: enum(TIMBRES)` — новое | назвать синт, бочку, рисунок |
| выбрать жанровое окно сета | `genre: enum(GENRE_WINDOWS)` — новое; применяется **только** к ещё не отрендеренным трекам и **не меняет темп** текущего сета (I7): если окно не содержит текущий `bpm`, поле отвергается `PlanInvalid("genre")` без ретрая | сменить темп, жанр посреди сета (это делает «давай тему X» — новый сет, #3412) |
| выкрик `hype_line` под флагом | есть (В2: выключен) | фразу об успехе (I5) |

Реализация — в `rob_box_music.reasoner.hook_candidates`/`_hooks`/`schema` (`:62-69, :72-87, :118-125`): перечисление в схеме и тот же список в валидаторе — «сузить выбор структурой» (ADR-0148 §2.2 п.2). Промпт правится в одну фразу («хуки — только из найденных по теме»), но решение держит валидатор, а не фраза. Тест — на `validate`: `theme_hooks` непусты + хук строки таблицы → `PlanInvalid("hooks")`.
