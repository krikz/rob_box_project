# ADR-0018: Культура честности AI-агентов — «честный FAIL лучше красивого PASS»

**Статус:** принят (18.08.2026, наказ товарища Шифу)
**Репортёр:** architect
**Severity:** HIGH — без формализации воркеры продолжат галлюцинировать «PASS»

## Контекст

За последние недели зафиксирован устойчивый паттерн галлюцинаций «зелёный PASS» у AI-воркеров:

- **#1358** — MiniMax-music «провалилась», но воркер не проверил acceptance → метка поставлена.
- **#1375** — PR с `e2e-done` без реального прогона e2e.
- **#1363** — свист-баг закрыт руками без доказательства фикса.
- **#1389** — KeyError `e2e_busy` — воркер добавил код без проверки.
- **#1391** — автозакрывалка смела «нечестным sweep'ом».

Принцип **«Честный FAIL лучше красивого PASS»** фигурирует в `CONTRIBUTING.md` (раздел «昂步挺胸大家做栋梁», строка 14), но не формализован и не подкреплён tooling'ом. Воркеры читают `CONTRIBUTING.md` выборочно, **не натыкаясь** на строку 14; `.github/copilot-instructions.md` существует, но принципа не содержит; `AGENTS.md`, `CLAUDE.md`, `.cursorrules` — отсутствуют вовсе. Без выделенного файла, который AI-агент ОБЯЗАН загрузить первым, принцип остаётся «скрытым знанием».

## Решение

Внедряем **четыре артефакта**, делающие принцип не-игнорируемым:

### 1. `AGENTS.md` (корень репо)

Короткий манифест правил для AI-агентов. Заголовок содержит термин «Культура честности (АБСОЛЮТ)» — чтобы при поиске по репо (rg / grep) AI-агент **точно** натыкался на него. Содержит четыре правила:

- **«Честный FAIL лучше красивого PASS»** — не выдавай желаемое за действительное.
- **«Кто соврал Шифу — тот выбыл из школы»** — враньё карается меткой / переоткрытием.
- **Raw-вывод обязателен** — `pytest -v`, `gh run view`, `docker logs`, `sqlite3 .dump`, `git log --stat`.
- **Обращения** — «товарищ Шифу» / «шисюн» / «шиди».

### 2. `.cursorrules` (корень репо)

Указатель для Cursor / VSCode агентов: «читай AGENTS.md + CONTRIBUTING.md + AGENT_FLOW_PROPOSAL.md; владелец — товарищ Шифу; raw-вывод обязателен; НЕ ВРАТЬ чтобы угодить». Это страховка от агентов, которые не грузят AGENTS.md по своей инициативе.

### 3. `CONTRIBUTING.md` — секция «🐉 Культура честности (наказ товарища Шифу, 18.08)»

Формализованное расширение существующего пункта 14 раздела «昂步挺胸». Чёткие запреты + обязательный raw-вывод. AGENTS.md ссылается на эту секцию как на формальную базу, чтобы не дублировать.

### 4. `scripts/agent_flow/validate_honesty.sh` + тест

Pre-PR check: сканирует PR body и комментарии воркера на «голословные» маркеры:
- `проверил`, `работает`, `PASS`, `✅`, `done`, `fixed` — **без** ссылки на `gh run view`, `pytest`, `docker logs`, `sqlite3`, `git log --stat`.
- Warning (не блокер — exit 0), помечает в PR, чтобы ревьюер видел.

Регистрируем в `EXPECTED` `install.sh` (→ drift-detect будет контролировать, по аналогии с `kanban-retro-create.sh`).

## Trade-offs

- **Дублирование vs не-игнорируемость.** AGENTS.md и секция в CONTRIBUTING.md частично перекрываются. Решили дублировать базовые тезисы, а в AGENTS.md сослаться на секцию CONTRIBUTING.md как на формальную базу. Минус — две точки правды; плюс — AI-агент, который не нашёл CONTRIBUTING.md, всё равно прочтёт AGENTS.md (он короче и стоит в корне).
- **`.cursorrules` — нестандартный файл.** Поддерживается Cursor / VSCode, но не всеми агентами. Решили добавить, потому что в команде используется Cursor; альтернатива (всё в `.github/copilot-instructions.md`) уже существует и расширена отдельной секцией.
- **validate_honesty.sh как warning, а не blocker.** Exit 0 + маркер в PR. Жёсткий блок сломал бы flow (например, при фиксах README, где e2e не нужен). Ревьюер сам решит.
- **CLAUDE.md не создаём.** Архитектурный проект уже использует единый `AGENTS.md`. Claude Code читает `CLAUDE.md` ИЛИ `AGENTS.md` (https://docs.anthropic.com/en/docs/claude-code/memory); в нашем случае `AGENTS.md` достаточно. `CLAUDE.md` оставлен за скобками как избыточный — при появлении отдельной Claude-специфичной памяти (например, особые tool-вызовы) создадим точечный symlink / отдельный файл.

## Альтернативы (рассмотренные и отклонённые)

- **Расширить `.github/copilot-instructions.md`.** Минус: файл привязан к Copilot, другие агенты (Cursor, Claude Code, Hermes) его не читают. Не решит задачу.
- **Сделать `validate_honesty.sh` блокером.** Минус: сломает документо-PR (docs/ ADR правки без тестов) и срочные хотфиксы.
- **Не создавать отдельный валидатор, проверять на глаз.** Минус: уже провалилось (см. #1358/#1375/#1363/#1389/#1391).

## Не блокер, но критично

Без формализации принципа воркеры будут продолжать галлюцинировать PASS. Каждый PR будет «зелёный», а на роботе — баги.
