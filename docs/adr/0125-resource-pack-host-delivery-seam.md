## 1. Контекст

На Vision Pi бинарные ресурсы приезжали четырьмя разными путями, и ни один
не знал про остальные:

1. **BuildKit cache-mount + `wget` внутри Dockerfile** — Vosk и Silero
   запекались в образ `voice-base`. Сборка ходила в сеть и падала целиком,
   если `alphacephei.com` недоступен.
2. **Хостовый скрипт** — `download_yolov8n_hef.sh` и
   `download_retinaface_hef.sh`, два файла по ~87 строк, второй дословная
   копия первого с другим URL и sha.
3. **Отдельный образ + init-контейнер** — `voice-resources` (ADR-0111).
4. **git + bind-mount** — `sound_pack`.

Плюс второй класс, который не лезет ни в один из четырёх: **закрытые
вендорные артефакты Hailo** (wheel, `libhailort.so`, два `.deb`). Их нельзя
скачать скриптом — нужен аккаунт Developer Zone; они живут в
`/opt/rob_box/vendor` на katana и на Vision Pi, и в каждом из этих двух мест
лежит РАЗНОЕ.

Цена зоопарка: добавление пятого ресурса означало выбрать один из четырёх
механизмов и написать пятый скрипт, а отсутствие ресурса обнаруживалось
по-разному — от красной сборки до молчаливой деградации ноды.

## 2. Решение

### 2.1 Манифест — единственный источник правды о том, ЧТО доставляется

`docker/vision/scripts/resource_pack/manifest.yaml`: одна запись на ресурс,
поля `name`, `type` (`open` / `gated` / `build-time` / `git`), `kind`, `url`,
`sha256`, `size_bytes`, `unpack`, `verify_file`, `target`, `target_host`,
`required` (`hard` / `soft`), `on_missing`, `degrade_note`, `consumers`.

Добавление ресурса — это строки в YAML, а не новый скрипт и не правка
workflow.

### 2.2 `apply_resource_pack.sh` — единственная реализация того, КАК

Bash + coreutils + curl/wget, без python и PyYAML: скрипт обязан работать на
голой Pi, как работают сегодняшние `download_*_hef.sh`. Идемпотентен: файл на
месте и sha256 совпал → no-op без сети.

Коды возврата: `0` — всё на месте либо объявленная деградация; `1` —
hard-провал или несовпадение sha256; `2` — сломанный манифест или вызов.

### 2.3 Несовпадение sha256 — ВСЕГДА hard, даже для `required: soft`

Решение принято при реализации, в плане явно не стояло.

- **Отсутствие** ресурса — объявленная деградация: нода честно уходит в stub,
  деплой жив (ADR-0018).
- **Файл с другим содержимым** — неизвестное состояние робота. Скрипт в этом
  случае не трогает ничего и возвращает 1.

Практическое следствие: шаг деплоя «Ensure HEF models» раньше не падал
никогда (`|| true`), теперь коды 1/2 валят его с `::error`.

### 2.4 Два канонических host-каталога, третий не заводим

- `/opt/rob_box/models` — открытые ресурсы (HEF, Vosk, Silero). Монтируется
  в контейнеры `:ro`.
- `/opt/rob_box/vendor` — закрытые вендорные артефакты, кладёт человек.

### 2.5 Gated-записи без явного `--host` пропускаются

Один и тот же путь `/opt/rob_box/vendor` на katana и на Pi содержит разное,
поэтому угадывать, где идёт прогон, скрипт не имеет права. Без
`--host katana` / `--host vision-pi` такие записи именно **пропускаются**, а
не «проверяются успешно».

### 2.6 Что означает поле `sha256` у открытых ресурсов

Для Vosk и Silero вендор контрольных сумм не публикует. Поэтому записанные
значения — это **фиксация того, что реально приехало и заработало на роботе**
(снято 21.09.2026), а не «официальная сумма вендора». Смысл поля здесь —
заметить обновление или подмену апстрима, а не подтвердить подлинность. Если
alphacephei выложит новую сборку модели, деплой упадёт красным, и это
правильнее, чем молча подсунуть роботу другую модель распознавания.

## 3. Что это меняет на практике

| Было | Стало |
|---|---|
| Vosk+Silero (~227 МиБ) внутри образа `voice-base`, сборка ходит в сеть | Файлы на хосте, приходят bind-mount `/opt/rob_box/models:/models:ro`; пути ВНУТРИ контейнера не изменились |
| Два почти одинаковых `download_*_hef.sh` | Две записи в манифесте; скрипты живут ещё один релиз-цикл как быстрый откат |
| 34 строки bash-цикла в шаге деплоя | Один вызов с `--only` |
| Промах ресурса: от красной сборки до тишины | Единая семантика: `soft` → деградация, `hard` → красный деплой, sha-mismatch → всегда красный |

## 4. Граница с ADR-0111 (разведена явно)

ADR-0111 (`voice-resources` image sourcing) **не отменяется и не сужается**.
Renardo-сэмплы продолжают ехать своим путём — отдельным образом и
named-volume, который заполняет one-shot init-контейнер. Причина: этот
ресурс нужен ВНУТРИ сборки и на старте стека, а не на хосте, и переносить
его в Ресурсный пак значило бы ломать работающее ради единообразия.

В манифесте `renardo-samples` и `sound-pack` присутствуют как записи
`type: build-time` / `type: git` с прямой пометкой «доставляется не этим
швом» — реестр обязан знать обо всех ресурсах, даже о тех, которыми не
управляет. Иначе пятый способ доставки заведётся снова.

## 5. Последствия, которые надо принять вместе с решением

1. **Первый деплой после перехода качает ~227 МиБ на Pi.** Нет сети — шаг
   падает красным (`required: hard`), контейнер не стартует с пустым
   `/models`. Это осознанно: «зелёный деплой + глухой робот» мы уже
   проходили. Прогрев руками снимает риск.
2. **Правка `voice_base/Dockerfile` инвалидирует ~10 ГБ кеша** у
   `voice-assistant` и `supervisor`. Поэтому Этап 3 — отдельный коммит:
   откатывать дорогую часть можно, не теряя манифест и HEF.
3. **У двух из четырёх закрытых артефактов эталон физически утрачен.**
   Проверено 21.09.2026: на Vision Pi каталога `/opt/rob_box/vendor` нет
   вовсе, а пакеты установлены (`dpkg -l`: `ii hailort 4.24.0 arm64`,
   `ii hailort-pcie-driver 4.24.0 all`). Файлы `.deb` были применены и не
   сохранены. Это аргумент к зеркалу закрытых артефактов (план §4.3), и
   заметили мы это только потому, что пошли считать суммы.
4. **Прогрев `torch.hub.load` для Silero удалён** вместе со ступенью
   Dockerfile и ничем не заменён. Если оба файловых пути отвалятся,
   `tts_node` полезет в сеть за HEAD чужого репозитория прямо в рантайме.
   Требует отдельного решения.

## 6. Альтернативы, которые рассматривались

| Вариант | Почему нет |
|---|---|
| Оставить как есть | Пятый ресурс = пятый способ. Дублирование уже случилось: два `download_*_hef.sh` — дословные копии |
| Всё запекать в образы | Возвращает сетевую зависимость сборки и лишние ~227 МиБ в каждый `docker pull` |
| Python + PyYAML в скрипте | Скрипт обязан работать на голой Pi; сегодняшние `download_*_hef.sh` обходятся bash + curl, и это свойство стоит сохранить |
| OCI-зеркало для закрытых артефактов | Не отклонено, а отложено: требует ответа по лицензии Hailo — решение владельца, не архитектурное |

## 7. Проверено (raw)

Прогон на живой Vision Pi (`ros2@10.1.1.21`), 21.09.2026:

```
[resource_pack] vosk-ru-small: OK установлен — /opt/rob_box/models/vosk-model-small-ru-0.22 (README на месте)
[resource_pack] WARN: unzip не найден — распаковываю через python3 -m zipfile
[resource_pack] silero-tts-v5-ru: OK установлен — /opt/rob_box/models/silero/v5_ru.pt (145382211 байт)
[resource_pack] итог: установлено 2, без изменений 0, пропущено 0, hard-провалов 0
```

Второй прогон (идемпотентность) и он же после простановки sha256:

```
[resource_pack] vosk-ru-small: OK no-op — распакован, README на месте
[resource_pack] silero-tts-v5-ru: OK no-op — на месте, sha256 совпал
[resource_pack] итог: установлено 0, без изменений 2, пропущено 0, hard-провалов 0
```

`unzip` на Vision Pi отсутствует — сработал заявленный фолбэк
`python3 -m zipfile`. sha256 файла `retinaface_mobilenet_v1.hef` на роботе
совпал с записанным в манифесте (`1fbc7be2…bff472`) — эталон в манифесте
верен против реально раскатанного артефакта.

Локально: `32 passed` (`tests/unit/docker/test_resource_pack.py` гоняет
настоящий скрипт на фикстуре через локальный HTTP-сервер; боевые URL не
дёргаются).

## 8. Что осталось открытым

1. **Лицензия Hailo** — можно ли зеркалить закрытые артефакты. Решение
   владельца. Блокирует план §4.3, не блокирует Этапы 1-4.
2. **Судьба `torch.hub`-фолбэка** в `tts_node` (см. §5.4).
3. **`docker/vision/telegram_bot/Dockerfile:47-53`** качает ТУ ЖЕ Vosk-модель
   на этапе сборки своего образа — пятый путь доставки, которого нет в
   реестре плана. Кандидат в манифест отдельной карточкой.
4. **`tests/unit/docker/` не гоняется ни одним workflow** — тест Ресурсного
   пака сегодня зелёный только локально.
