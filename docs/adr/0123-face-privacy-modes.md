# ADR-0123 — Режимы приватности лицевого канала (заменяет ADR-0089 §8)

**Дата:** 2026-09-16
**Статус:** Proposed (решения владельца от 16.09.2026, реализация — карточки из §9)
**Автор:** владелец + Claude Code
**Заменяет:** ADR-0089 §8 «Privacy (только для Phase 2)» и строку R6 в §7
**Связанные:** issue #2599 (лицо, Phase 2), ADR-0093 (ring незнакомых голосов), ADR-0096/0105 («Встреча»), ADR-0106 («Знакомый»), PR #2699 (чистка устаревших VisionEvent)

## 1. Контекст

ADR-0089 §8 задал для лица одну строгую политику: снимки не хранятся нигде, в `faces.db` только эмбеддинг и имя, запись лица — только по явной команде, автоудаление через 90 дней, privacy-review — блокер слияния Phase 2. Под эту политику PR-B/PR-C/PR-D из #2599 не начинались: privacy-review никто не делал, владелец ревью в ADR-0089 §10 п.3 так и не назначен.

Где робот работает на самом деле: мастерская владельца, изредка — выставка. Задача ближайших месяцев — отладка узнавания, а для неё нужно видеть, *кого* и *по какому кадру* робот узнал или не узнал. Строгая политика этого не позволяет: без снимков невозможно разобрать ложное срабатывание.

Второе желание владельца, которого ADR-0089 не предусматривал: замечать, что человек изменился с прошлой встречи (другая одежда, стрижка). Эмбеддинг ArcFace для этого бесполезен — он специально обучен не замечать таких изменений. Значит, нужны снимки и что-то, что их сравнивает.

Голос уже живёт по двум разным правилам: знакомые — в `speakers.db` без ограничений, незнакомцы — только в памяти (ADR-0093). У лица единой политики тоже не будет — нужна явная переменная, от которой зависит поведение.

## 2. Решение

Приватность лицевого канала — **режим**, один на робота, задаётся конфигом и проверяется в одном месте — в хранилище лиц (`FaceStore`, §5). Остальной код режим не читает: он просит хранилище «запиши», а хранилище решает, что из этого реально ляжет на диск.

| Режим | Когда | Знакомые | Незнакомцы | Снимки | Облачное сравнение |
|---|---|---|---|---|---|
| `workshop` | мастерская, отладка. **По умолчанию сейчас.** | эмбеддинги + снимки на диск | **на диск**, как знакомые, без имени | да, с ротацией (§4) | да |
| `exhibition` | выставка, много посторонних | эмбеддинги + снимки на диск | **только в памяти**, до конца сессии (как ADR-0093) | только знакомых | только знакомых |
| `strict` | на будущее | только эмбеддинг + имя (как ADR-0089 §8) | не хранятся | нет | нет |

Решения владельца от 16.09.2026, на которых стоит `workshop`:

1. **Запоминаются все подряд.** Любое лицо, признанное встречей (§3), получает запись; имя привязывается позже. Команда «запомни меня» остаётся, но не является условием.
2. **Снимки хранятся** и ротируются по встречам.
3. **«Было/стало» сравнивает облачная vision-LLM.** Снимки покидают робота — в `workshop` это допустимо.
4. **Незнакомцы пишутся на диск** — для отладки нужно видеть, кого робот не узнал.
5. **Галерею смотрят** в Telegram, в Quest и файлами на Vision Pi.

Робот обязан уметь сказать, в каком он режиме: режим попадает в `/perception/health` (или соседний статус) и в ответ `get_robot_status`.

## 3. Встреча, а не кадр

Сегодня на одного человека в кадре приходит ~5 `VisionEvent` в секунду (живой замер 16.09: 88 событий `face` за минуту от одного лица). Писать по записи на событие нельзя. Единица хранения — **встреча** в смысле ADR-0096/0105:

- лицевой трекер склеивает детекции между кадрами (IoU bbox + близость эмбеддингов) в трек;
- трек становится встречей, когда лицо было в кадре не меньше `min_track_sec` (стартовое значение 2 с) и хотя бы в одном кадре не меньше `min_face_px` по короткой стороне (стартовое 48 px);
- на встречу выбираются **1–3 лучших кадра**: крупнее, фронтальнее (по landmarks RetinaFace), резче;
- эмбеддинг встречи — среднее эмбеддингов лучших кадров, нормированное.

Мелькнувшие на полсекунды лица встречей не становятся и не пишутся ни в одном режиме.

## 4. Что хранится

Всё — на Vision Pi, в томе `/data/faces/` (не в образе, переживает пересоздание контейнера).

### 4.1 Запись человека

Ключ — `Acquaintance.id` шва «Знакомый» (ADR-0106). Своего `person_id` лицевой канал не заводит; `last_seen`/`seen_count` по-прежнему принадлежат шву (как требовал ADR-0089 §8 — это правило остаётся).

- **Галерея эмбеддингов**: несколько 128-dim векторов на человека, а не один. Внешность меняется — новый эмбеддинг добавляется, когда встреча уверенно отнесена к человеку. Лимит `max_embeddings` (стартовое 20); при переполнении вытесняется самый похожий на остальные (он даёт меньше всего нового).
- **Эталонный снимок** — первый снимок при создании записи. Не ротируется.
- **Снимки встреч** — по одному лучшему на встречу за последние `keep_encounters` встреч (стартовое 10). Старые удаляются.

### 4.2 Состав снимка

- **Кроп лица** с запасом 40 % по краям (видно причёску, очки), JPEG.
- **Кроп фигуры** — bbox `person` от `vision-hailo` (yolov8n), выбранный по пересечению с bbox лица. Нужен для одежды: по кропу лица её не видно. Если `person` в кадре нет — снимок без фигуры, это не ошибка.
- Метаданные: время, `source_camera`, confidence детекции, размер лица в px, режим, в котором снимок записан.

Полные кадры не хранятся ни в одном режиме.

### 4.3 Незнакомец

Запись того же вида без имени. Имя появляется через слияние (§6). В `exhibition` та же структура живёт только в памяти и исчезает при рестарте ноды или по TTL сессии.

## 5. Хранилище и граница режима

`FaceStore` — единственный модуль, который пишет в `/data/faces/`. Интерфейс в терминах предметной области: `record_encounter(...)`, `attach_name(...)`, `merge(...)`, `forget(...)`, `gallery(person)`. Режим передаётся ему при создании, и каждое решение «писать ли на диск / отдавать ли в облако» принимается внутри него. Тесты режимов — тесты `FaceStore`, без ROS и без камеры.

**Смена режима** не переписывает прошлое молча:
- `workshop → exhibition`: записи незнакомцев с диска **удаляются** (иначе режим выставки начнётся с чужих снимков из мастерской); знакомые остаются.
- `* → strict`: удаляются все снимки и все незнакомцы; у знакомых остаётся по одному эмбеддингу-центроиду.
- Переход в более мягкий режим ничего не восстанавливает.

Удаление — команда «забудь меня» / из Telegram: стирает галерею, снимки и привязку в шве для этого человека. Работает во всех режимах.

## 6. Узнавание и слияние

- Встреча сравнивается с галереями всех записей; совпадение выше `face_identify_threshold` → это он. Порог калибруется на реальных данных, как голосовой в #2348 (таблица sweep, а не «на глаз»).
- **Привязка имени голосом**: если в окне встречи голос уверенно опознал человека (порог голосового `identify`) **и в кадре ровно одно лицо** — лицевая запись сливается с этим человеком через `IdentitySeam.merge`. Два и больше лиц в кадре — слияния нет (это открытый вопрос ADR-0105 §3 п.4, здесь он не решается).
- **Пополнение галереи** — по тому же правилу: уверенное узнавание лицом *или* голос + одно лицо. Иначе в галерею Дениса однажды попадёт лицо того, кто стоял рядом.
- До слияния надо разобрать дубли голосовых профилей: 16.09 у владельца в `speakers.db` шесть записей (три «Денис», две «Денчик», «Зовут»), и лицо не должно привязываться к любой из них случайно.

## 7. Сравнение «было/стало»

- Когда встреча отнесена к знакомому, у которого есть снимок прошлой встречи, два снимка (лицо + фигура) уходят облачной vision-LLM с вопросом «что изменилось во внешности».
- Результат — короткий текст, кладётся в контекст встречи; Личность может его использовать («О, подстригся?»). Сам снимок в контекст Личности не попадает.
- Одно сравнение на встречу, не на кадр.
- DeepSeek (текущий LLM диалога) изображения не принимает — нужен отдельный провайдер; выбор — в карточке реализации.
- **Отказ провайдера виден**: ошибка/нет денег → `appearance_change: unavailable` и строка в логе уровня WARN, а не пустой ответ. Голосовой стек уже деградировал молча, когда кончались деньги у LLM/TTS, — здесь так быть не должно.
- В `exhibition` — только для знакомых; в `strict` — выключено.

## 8. Просмотр

- **Файлы на Vision Pi**: `/data/faces/<person>/` — эталон, снимки встреч, `meta.json`. Смотреть по SSH/scp.
- **Telegram**: команда боту — список людей, галерея человека, последние встречи, «забыть». Доступ — только операторы бота.
- **Quest**: панель галереи и таймлайна встреч. Отдельная карточка, после Telegram.

## 9. Реализация — карточки (дробление по ADR-0013)

1. Слить дубли голосовых профилей владельца (разовая операция + инструмент слияния).
2. `FaceStore` + режимы + конфиг режима + статус режима в health. Без камеры, чисто тестами.
3. PR-B #2599: ArcFace-эмбеддинги, лицевой трекер, встреча (§3), узнавание (§6), адаптер `IdentitySeam`.
4. Снимки лица + ротация (§4.1–4.2).
5. Кроп фигуры из `vision-hailo` (сопоставление `person` ↔ `face`).
6. Сравнение «было/стало» (§7).
7. Просмотр в Telegram.
8. Просмотр в Quest.

Порядок: 1 и 2 независимы; 3 требует 2; 4–5 требуют 3; 6 требует 4–5; 7–8 требуют 4.

## 10. Последствия

**Плюсы.** Узнавание можно отлаживать по реальным кадрам. Появляется «ты изменился». Политика — одна переменная, и выставочный режим уже продуман, а не будет пришиваться потом.

**Минусы и риски.**
- В `workshop` робот хранит снимки всех, кто попал в кадр мастерской, и отправляет снимки знакомых в облако. Это осознанное решение владельца для закрытого помещения; для любой публичной площадки режим обязан быть `exhibition` или строже. Переключение — ручное, робот сам место не определяет.
- 152-ФЗ: `workshop` и `exhibition` не соответствуют требованию явного согласия на биометрию, которое ADR-0089 §8 пытался обеспечить. Для выставки этот ADR лишь сокращает риск (незнакомцы не на диске), а не закрывает его. Нужна табличка/объявление на стенде — вне кода.
- Место на диске: ~10–30 КБ на снимок, ×(1 + 10) на человека — мегабайты даже при сотнях записей. Незнакомцев в `workshop` много; нужен верхний предел числа записей незнакомцев (`max_strangers`, стартовое 500, вытесняется самый давний).
- Память Vision Pi (16.09 свободно ~1 ГБ): в памяти держатся только эмбеддинги, снимки — только на диске.

## 11. Что остаётся от ADR-0089 §8

- Эмбеддинги и снимки не покидают Vision Pi, **кроме** сравнения из §7.
- `last_seen`/`seen_count` — в шве «Знакомый», не в лицевом хранилище.
- «Забудь меня» удаляет данные человека.
- Stub-события не создают записей и встреч (ADR-0089 §2.2, #2583).

Отменяется: запрет на снимки, обязательный явный enrollment, 90-дневный TTL как единственная политика, privacy-review как блокер Phase 2.
