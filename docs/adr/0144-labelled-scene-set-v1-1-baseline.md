## 2. Формат записи

### 2.1 Принцип: пишем входы, а не решения

Сцена ценна тем, что её можно прогнать через **любую** версию конвейера. Значит, в бэг идёт то, что конвейер **получает** (датчики и заявки человека), а не то, что он **решил**. Решения живой 1.1 пишутся тоже, но роль у них — контроль «офлайн-прогон 1.1 совпадает с живой 1.1»; метрики 1.1 считаются по **офлайн-прогону**, а не по контролю, иначе 1.1 и 2.0 мерились бы разными линейками.

### 2.2 Топики

| Топик | Тип | Роль | Зачем |
|---|---|---|---|
| `/camera/camera/color/image_raw/compressed` | `CompressedImage` (JPEG) | вход | лицо, person-bbox |
| `/camera/camera/depth/image_rect_raw/compressedDepth` | `CompressedImage` (PNG 16UC1) | вход | 3D-положение (ADR-0138) |
| `/camera/camera/color/camera_info` | `CameraInfo` | вход | intrinsics |
| `/tf_static` | `TFMessage` | вход | фреймы камеры |
| `/audio/speech_audio` | `AudioData` | **вход** | **готовые фразы** — именно их слушают `stt_node` и `speaker_id_node`; `utterance_id` = хеш этих байт (ADR-0131) |
| `/audio/audio` | `AudioData` | вход (запас) | сырой поток 16 кГц — на случай, если 2.0 переделает нарезку фраз |
| `/audio/vad` | `Bool` | вход | фронты VAD |
| `/audio/direction` | `Int32` | вход | DOA (этап 5) |
| `/voice/speaker/register` | `String` | вход | заявка «запомни меня» от `dialogue_node` (LLM) с `utterance_id` — без неё сид-сцена s00 не воспроизводит регистрацию голоса |
| `/voice/tts/state`, `/voice/tts/finished` | `String` | вход | когда робот говорит (гейт `speaker_id_node` #2747); плюс видно реплики дирижёра |
| `/voice/stt/result`, `/voice/stt/speaker` | `String` | метка | что сказано — для разметки и согласий (§4.3) |
| `/voice/speaker/result` | `String` | контроль | решение живой 1.1 по голосу |
| `/vision/hailo/events` | `VisionEvent` | контроль | решение живой 1.1 по лицу + маркер Встречи |
| `/perception/observations` | `Observation` | контроль | живое наблюдение с 3D |

**Отличие от согласованного 29.09 списка**: добавлены `/audio/speech_audio`, `/voice/speaker/register`, `/voice/tts/state`, `/voice/tts/finished`. Причина — по коду (`stt_node.py:538`, `speaker_id_node.py:597-609`) голосовые узлы слушают **не** `/audio/audio`, а `/audio/speech_audio`; нарезку фраз делает `audio_node` прямо с PyAudio, из топика её не повторить. Без этих топиков офлайн-прогон голоса невозможен (пилот это и показал). Поток `/audio/speech_audio` ≈ `/audio/audio` в пределах речи, то есть ≤ 0.03 МБ/с — на бюджет не влияет.

### 2.3 Хранилище и формат

- **rosbag2 `sqlite3`**, без сжатия (JPEG/PNG уже сжаты). В `voice-assistant` пакет `rosbag2_storage_mcap` есть (29.09, `ros2 pkg list`), но в образе `vision-hailo`, где бэг читается для декодирования и извлечения, его **нет** — поэтому `sqlite3`, иначе чтение привязано к одному образу.
- Пишется **внутри `voice-assistant`** — единственный контейнер, где одновременно есть `audio_common_msgs`, `rob_box_perception_msgs` и `compressed_depth_image_transport`. Потом `docker cp` на хост.
- Место: `~/scenes/<сцена>_<UTC>/` на **хосте** Vision Pi: бэг + `scene.yaml` + `conductor.log`. **Не** `/data` (там живые профили, память `robot-data-is-shared-with-live-people`), **не** git (сырое видео лица).
- Бюджет: 108 МБ/мин → 13 сцен по ~2 мин ≈ 3 ГБ. Свободно на Vision Pi 86 ГБ (29.09, `df -h /`).

## 3. Сцены

### 3.1 Набор (12 + сид)

Каждая сцена прогоняется **с одного и того же сида** (результат s00), независимо от остальных: иначе ошибка в s03 переезжала бы в s04, и сцены перестали бы быть отдельными измерениями.

| Сцена | Что происходит | Что проверяет |
|---|---|---|
| **s00** | чистая регистрация владельца: лицо + «запомни меня» | сид-БД для всех прогонов (лицевое хранилище + `speakers.db`) |
| s01 | владелец входит, стоит, уходит | базовое узнавание, задержка, одна Встреча |
| s02 | владелец в очках | облик в очках (#2771) |
| s03 | очки надеваются и снимаются в кадре | дробление при смене облика на глазах у робота (ADR-0130 §1.2 п.5) |
| s04 | шапка / капюшон | облик с закрытым лбом |
| s05 | спиной, потом поворачивается | узнавание после поворота; нет ложного имени спиной |
| s06 | вносят маску, молча | незнакомец: **ни одного имени** маске |
| s07 | маска «представляется» голосом с телефона | представление → имя маске (с момента представления) |
| s08 | владелец и маска вместе | двое в кадре: имена не перепутаны, слияние голос→лицо не срабатывает при двух лицах |
| s09 | владелец проходит перед маской | перекрытие: треки не перескакивают |
| s10 | маску уносят и возвращают через ~1 мин | повторная Встреча = 1 приветствие, та же запись |
| s11 | фото владельца на экране телефона | подделка (spoof) — считается отдельно (§6.2) |
| s12 | владелец искажённым голосом говорит «я Литвин», в кадре только маска | регрессия неверного слияния лица и голоса 29.09: голос, **не принадлежащий** лицу в кадре, не даёт этому лицу имя |

Для s12 «правильный» ответ зафиксирован явно в `expected` сцены (§4.2): маске не разрешено ни одно имя, владельцу — только «Дэнчик». Это решение разметки, а не вывод кода; если товарищ Шифу сочтёт иначе — правится `scene.yaml`, инструменты не меняются.

### 3.2 Не покрыто (отложено до живого второго человека)

- гость в очках;
- двое живых людей расходятся/пересекаются;
- гость со спины.

Отчёт метрик **обязан** печатать эти три строки как `not covered` — чтобы «набор зелёный» не читался как «проверено всё».

### 3.3 Честно о пределах маски

Маска статична: у неё нет мимики, поворота головы, походки; её «голос» идёт из динамика телефона, а не изо рта. Поэтому сцены с маской меряют **сопоставление** (кто есть кто, имя не туда), а не узнавание живого незнакомца. Цифры по маске нельзя выдавать за «работу с гостями».

## 4. Разметка

### 4.1 Дирижёр

Размечает не человек задним числом, а **сам робот во время съёмки**: скрипт-дирижёр читает YAML-сценарий сцены и по шагам:

1. говорит команду через `/voice/tts/request` — JSON `{"ssml": "<speak>…</speak>", "source": "operator"}` (поле `text` `tts_node` молча выкидывает);
2. ждёт `/voice/tts/finished` (синтез MiniMax ~6 с — фиксированный `sleep` врёт);
3. ставит метку события (`enter`, `leave`, `glasses_on` …) с **временем по часам хоста**, ждёт паузу шага и идёт дальше.

Правила дирижёра (по итогам пилота 29.09, согласовано с владельцем):

- **Команды — повелительные и однозначные**, звучат ровно тогда, когда действие должно произойти: «войдите в кадр», «выйдите из кадра», «наденьте очки». Никаких «можете входить».
- **Пустой кадр проверяет сам дирижёр** перед каждым `enter` и возвращением: подписан на `/perception/observations` и ждёт ≥ 3 с без единого наблюдения `person`/`face`, затем говорит «кадр пуст» и ставит метку `empty` (`t_empty`). Не пусто за `N` с — повторяет «выйдите из кадра» и пишет это в `conductor.log`. `leave` проверяется так же: метка ставится на первый момент, с которого кадр пуст ≥ 3 с (`t_left`), а не на момент команды. Владелец подтвердил, что из кадра выйти может даже в углу (29.09 15:2x UTC, 0 наблюдений 8 с).
- Для **статичных** участников (маска, телефон с фото) проверка «пусто» не применяется к их коридору `anchor_cx` — маска на подставке в кадре законно.
- **Расстояния — по меткам на полу**: скотч на 1.0 / 1.5 / 2.0 / 3.0 м от стекла камеры; дирижёр называет метку («встаньте на метку полтора метра»).

Запись бэга дирижёр запускает и останавливает сам — так `t = 0` сцены и `t = 0` бэга совпадают по построению (метка хранит абсолютное время; относительное считается от `starting_time` из `metadata.yaml` бэга).

Реплики дирижёра попадают в микрофон. `audio_node` гейтит свою речь (`/voice/tts/state`), и этот гейт записан (§2.2); если что-то всё же просочится в `/audio/speech_audio`, результат голоса без окна `say` в разметке считается «неатрибутированным» и печатается в отчёте (§6.1), а не молча отбрасывается.

### 4.2 `scene.yaml`

```yaml
schema: 1
scene: s07_mask_introduces
recording: {bag: s07_mask_introduces_20261001T101500Z, robot_commit: <sha>, started_utc: ...}
participants:
  - {label: owner, truth: Дэнчик, kind: person, known_before: true}
  - {label: mask,  truth: Литвин, kind: mask,   known_before: false, anchor_cx: [0.15, 0.45]}
events:                        # t — секунды от начала бэга
  - {t: 1.0,  type: empty}                  # кадр пуст ≥ 3 с (проверено дирижёром)
  - {t: 4.1,  type: enter,     who: owner}
  - {t: 9.8,  type: enter,     who: mask}
  - {t: 15.2, type: say,       who: mask, until: 19.0, text: "Привет, я Литвин"}
  - {t: 15.2, type: introduce, who: mask, name: Литвин}
  - {t: 40.0, type: leave,     who: mask}
consent: []                    # §4.3
expected:                      # необязательно; по умолчанию — правила §6.1
  allowed_names: {mask: [{from: 15.2, names: [Литвин]}]}
  max_greetings_per_visit: {owner: 1, mask: 1}
  max_records: {owner: 1, mask: 1}
```

- `kind`: `person` | `mask` | `photo`. `photo` — подделка (§6.2).
- `anchor_cx` — горизонтальный коридор центра bbox (доли кадра) для **статичного** участника. Нужен только сценам, где в кадре двое: так событие лица относится к маске или к владельцу без ручной разметки кадров.
- `events.type`: `empty` (кадр проверенно пуст), `enter` / `leave` (присутствие в кадре; `leave` — момент проверенно пустого кадра), `say` (окно речи `t..until`, для голоса), `introduce` (с этого момента имя разрешено), остальные (`glasses_on`, `hat_off`, `turn_back` …) — справочные, в метрики не входят.
- Участник, присутствующий с начала — `present_at_start: true`.

### 4.3 Согласие и хранение

Сейчас в кадре только владелец (свои данные) и маска (не человек) — согласие не требуется. Для будущих сцен с гостем:

- **устное согласие записывается в начале сцены**: дирижёр спрашивает, гость отвечает в микрофон; ответ остаётся в бэге (`/voice/stt/result`), в `scene.yaml` — `consent: [{participant, t, utterance}]`. Нет согласия — сцена не пишется (дирижёр останавливается, если шаг `consent` не подтверждён оператором);
- сырые кадры хранятся **только** на Vision Pi в `~/scenes/`, в git и на katana не копируются;
- по просьбе владельца (или гостя через владельца) каталог сцены удаляется целиком — бэг, `scene.yaml` и все результаты прогонов этой сцены (`~/scenes/_replay/*/<сцена>/`). Отдельного срока хранения нет: набор нужен до конца сравнения 1.1/2.0, дальше — решение владельца.

Это согласуется с режимом «мастерской» (решение 16.09.2026): лица и так пишутся все подряд; сцены — не новый класс данных, а то же самое, собранное в одно место с разметкой.

## 5. Офлайн-прогон

### 5.1 Где и как изолирован

Только на **Vision Pi** (Hailo-8). Никакого `ros2 bag play` в живой граф: записанный звук ушёл бы в живой STT, а записанные лица — в живое хранилище. Изоляция — пять независимых барьеров, любой из них сам по себе уже отрезает живой граф:

1. **Собственный Zenoh-роутер** (контейнер из того же `eclipse/zenoh:1.6.2`), слушает только `tcp/127.0.0.1:7457`, никуда не подключается, multicast-scouting выключен.
2. Сессионный конфиг узлов прогона — `connect` **только** на этот роутер, scouting выключен, пространство имён Zenoh `replay/<run>`.
3. `ROS_DOMAIN_ID=77` (живой граф — 0).
4. **`/data` не монтируется** ни в один контейнер прогона. Лицевое хранилище (`FACE_STORE_ROOT`) и `speakers.db` (`db_path` и соседние `*_db_path`) — во временном каталоге прогона, куда сперва копируется сид. Даже если переменная окружения потеряется, узел запишет в эфемерный `/data` контейнера, а не на хост.
5. Порт метрик `speaker_id_node` — не боевой 9112.

Скрипт прогона проверяет барьеры 1–4 **до** запуска и отказывается стартовать, если хоть один не выполнен (проверка — чистая функция, покрыта тестом).

### 5.2 Контейнеры прогона

| Контейнер | Образ | Что делает |
|---|---|---|
| роутер | `eclipse/zenoh:1.6.2` | §5.1 п.1 |
| декодер | `vision-hailo` | подписан на сжатые кадры, публикует `Image` `bgr8` и глубину `16UC1` с **исходным** `header` (узел лица слушает сырые топики, `gaze.py:405-407`) |
| лицо | `vision-hailo` (тег живого `vision-face` — для 1.1; для 2.0 — свой) | `start_vision_face.sh` с `FACE_STORE_ROOT=/replay/faces`, `FIRST_FRAME_TIMEOUT_SEC` с запасом |
| голос | `voice-assistant` (тег живого) | `speaker_id_node` с `db_path=/replay/speakers.db` |
| запись выходов | `voice-assistant` | `ros2 bag record` выходов прогона |
| проигрыватель | `voice-assistant` | `ros2 bag play` **только входов** §2.2 (белый список; контрольные топики не проигрываются никогда — иначе они смешались бы с выходами прогона) |

Живой `vision-face` на время прогона **останавливается** и после — перезапускается: второй процесс, открывающий Hailo рядом с живым узлом, уже ронял его в `HAILO_STREAM_ABORT(63)` при `healthy` в `docker ps` (22.09.2026). После прогона — проверка `docker logs vision-face --tail 20` на `STREAM_ABORT`.

### 5.3 Время

`VisionEvent.stamp` ставится узлом по `now()` (`vision_hailo_node.py:523`), то есть в прогоне — по часам прогона, а не сцены. Смещение «часы прогона − часы сцены» считается по `/camera/camera/color/camera_info`: он есть в обоих бэгах (проигрыватель публикует его с исходным `header.stamp`, запись выходов прогона пишет его же), смещение = медиана (приём − stamp) в прогоне − та же медиана в сцене. Обе медианы — только доставка сообщения, без обработки конвейером; если брать stamp кадра из `Observation`, из времени прогона вычлась бы и сама обработка, и задержка «вошёл → confirmed» у прогона вышла бы короче, чем у живой 1.1. Нет `camera_info` — извлекатель отказывается, смещение задаётся вручную и помечается в отчёте.

## 6. Метрики

### 6.1 Нормализованный журнал и атрибуция

Извлекатель превращает выходы (прогона или контроля) в журнал записей `{t, channel: face|voice, kind: detection|encounter|speaker, id, name, tentative_name, bbox_cx}`. Считалка метрик работает **только** с этим журналом и `scene.yaml`. Для 2.0 появится свой извлекатель (треки, `Acquaintance.id`), считалка останется той же — это и есть шов, за счёт которого 1.1 и 2.0 меряются одной линейкой.

**Атрибуция лица**: участник присутствует от `enter` до `leave` с допуском ±`grace` (по умолчанию 1.5 с — команда дирижёра опережает движение человека). Одно лицо в кадре по разметке → событие его. Двое → статичный участник, если `bbox_cx` в его `anchor_cx`; иначе единственный нестатичный. Иначе — «неатрибутировано».

**Атрибуция голоса**: результат голоса в момент `t` относится к окну `say` с `start ≤ t ≤ until + voice_lag` (по умолчанию 8 с — фраза сперва должна закончиться и пройти эмбеддинг); при нескольких — к последнему начавшемуся.

**Разрешённые имена** участника в момент `t`: `known_before` → `{truth}` с нуля; `introduce(name)` → добавляет `name` с момента события; `expected.allowed_names` — **заменяет** правила целиком для этого участника.

### 6.2 Определения

| Метрика | Определение | Цель |
|---|---|---|
| **Ложные имена** | число атрибутированных событий с **уверенным** именем (лицо: `display_name` / имя маркера Встречи; голос: `name`), не входящим в разрешённые участнику в этот момент. Печатаются раздельно лицо/голос и списком пар (участник, имя) | **0** |
| Подделка принята | то же для участника `kind: photo` — считается отдельно: фото владельца, названное «Дэнчик», не «не тот человек», но и не живой человек | 0; отдельной строкой |
| Дробление | участник, у которого за сцену событий лица с > `max_records` (по умолчанию 1) различными `id` записи; отдельно для голосовых `speaker_id` | ↓ относительно 1.1 |
| Доля опознанных встреч | визит = пара `enter..leave`; визит «называемый», если за его время участнику разрешено хоть одно имя; «опознан», если в нём есть событие лица с разрешённым именем. Доля = опознанные / называемые | ≥ 1.1 |
| Двойные приветствия | в каждом визите число маркеров Встречи (`encounter: start`) участника сверх `max_greetings_per_visit` (по умолчанию 1); сумма | 0 |
| Задержка «вошёл → confirmed» | по опознанным визитам: время первого события с разрешённым именем − max(`enter`, момент, когда имя стало разрешено). Визит без предшествующей метки `empty` (кадр не был проверенно пуст) в задержку **не входит** и печатается отдельным счётчиком — иначе человек, уже стоявший в кадре, даёт «задержку» с отрицательным смыслом (пилот). Печатаются медиана и максимум | измеряется; цель — после первого прогона 1.1 |
| Неатрибутировано | события лица/голоса, не отнесённые ни к кому, отдельно — с именем | печатается всегда |

Для 1.1 «confirmed» = уверенное имя в событии (`display_name` лица непуст; для голоса — `name`, не `tentative_name`). Для 2.0 — состояние трека `confirmed` (ADR-0130 §2.6) через свой извлекатель.

### 6.3 Отчёт

Считалка печатает **raw-таблицу** по сценам и итог (ADR-0018): сцена, версия, прогон (`run_id`), каждая метрика числом, плюс строки `not covered` §3.2. Никаких «PASS» без таблицы. Если сцена не прогналась — строка с причиной, а не пропуск.

## 7. Отвергнутые альтернативы

| Альтернатива | Почему нет |
|---|---|
| Писать только выходы живой 1.1 и мерить по ним | 2.0 нечем прогнать; и 1.1 с 2.0 мерились бы разными способами (живой против офлайна) |
| `mcap` | в `vision-hailo` плагина нет, а читать бэг нужно там (cv2) |
| `ros2 bag play` в живой граф «ненадолго» | записанный звук уходит в живой STT, лица — в живое `/data/faces` |
| Изоляция только `ROS_DOMAIN_ID` | в `rmw_zenoh` все узлы идут через общий роутер, мост на Main Pi; один пропущенный параметр — и прогон в живом графе. Отсюда пять барьеров §5.1 |
| Ручная разметка кадров после съёмки | 13 сцен × 5 Гц × 2 мин ≈ 8 000 кадров; дирижёр размечает по ходу бесплатно и точнее по времени |
| Прогон сцен цепочкой (s01 → s02 → …) на одной БД | ошибка одной сцены портит все следующие |

## 8. Trade-offs

- **Маска не человек** (§3.3) — цифры по «гостям» условны до живого второго человека.
- **Нагрузка при записи**: CPU хоста до 80.6 %, температура до 80.1 °C на пилоте. Сцены держать короткими (≤ 2–3 мин) и не писать подряд без остывания.
- **Прогон останавливает живое лицо** на время прогона (§5.2) — робот в это время не узнаёт людей.
- **Время событий прогона** пересчитывается по `camera_info` (§5.3); погрешность — десятки мс (джиттер доставки), для задержки «вошёл → confirmed» (секунды) несущественно. Не замерено — проверяется на первом прогоне сравнением контроля и прогона 1.1.
- **s12 — решение разметки**, а не код; спорно и оставлено явным в `scene.yaml`.
