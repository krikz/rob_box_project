## 1. Проблема

Единственный материал темы в v2 — одноголосая RTTTL-мелодия (`arrange/hook.py:156-196`): из неё берутся первые 4–8 тактов, а **всё остальное аранжировщик сочиняет сам**: прогрессия — лучший из восьми шаблонов стиля по покрытию нот хука (`arrange/harmony.py:69-87`, `knowledge._CLUB_PROGRESSIONS` `:790-793`), бас — тоника/квинта аккорда на шагах рисунка (`arrange/bass.py:27-35`), пэд — обращения с минимальным движением (`harmony.pad_chords :49-66`). Партитура (MusicXML) несёт то, чего RTTTL не несёт: гармонию автора, басовую линию, фактуру аккомпанемента, структуру частей и повторы, размер и темп. Координатор 06.10 показал на роботе: верхний голос сюиты «Интерстеллар» → RTTTL → `compose()` **работает, но гармония и бас партитуры теряются**. На выборке 71 партитура шаблонный подбор совпадает с аккордом оригинала в **23 %** 2-тактовых слотов; лучший шаблон пула (потолок подхода) — **36 %**; «везде тоника» — 37 %. То есть при материале с 250k партитур (PDMX) аранжировщик сегодня выбросит ≈ 4 из 5 авторских аккордов.

Шифу хочет: (1) брать PDMX как материал, (2) чтобы аранжировщик умел с ним «бомбически и качественно», (3) научиться у существующих аранжировок алгоритмам.

Что аранжировщик v2 может «научиться» из этого: (а) гармонию автора брать как есть, а когда её нет — марковскую таблицу переходов вместо 8 петель; (б) выбирать фразу-хук по повторам, а не по позиции; (в) развитие «тот же ритм, другой контур» как четвёртую операцию `DEVELOPMENT`; (г) политику тонов баса (терция/подход) как данные; (д) арпеджио как фактуру пэда. Всё — детерминированный код и таблицы (ADR-0148), без нейросетей в рантайме.

## 3. Решение

### 3.1 `ScoreMaterial` — материал темы, независимый от источника

Новый модуль `rob_box_music/material.py` (frozen dataclasses, валидатор как у `Track`, ADR-0149 §3.1). Единицы — доли **исходного** размера, абсолютный MIDI, никаких секунд (I22):

```python
@dataclass(frozen=True)
class ChordSpan:  beat: float; dur_beats: float; root_pc: int; quality: str  # "maj"|"min"|"dim"|"aug"|"sus"|"dom7"…
                  degree: Optional[int]   # 0..6 в key материала; None — недиатонический (заимствованный)
@dataclass(frozen=True)
class Phrase:     bar: int; bars: int; relation: str   # "repeat"|"sequence"|"rhythm"|"new" к предыдущей фразе
                  repeats: int                          # сколько раз фраза повторяется в пьесе (Н9)
@dataclass(frozen=True)
class ScoreSection: name: str; bar: int; bars: int; origin: str  # "text" (метка) | "repeat" (по повторам)
@dataclass(frozen=True)
class ScoreMaterial:
    material_id: str          # "pdmx:<id>" | "local:<sha8 файла>"
    title: str; composer: str; source: str; license: str   # "CC-BY-4.0" | "PD" | "unknown" (→ не используется)
    meter: Tuple[int, int]    # (3, 4); смена размера внутри пьесы → материал режется на части по размеру
    bpm: Optional[int]        # первая метрономная метка или None
    key: Key                  # из партитуры (знаки + Крумхансл по всем голосам), не по 8 тактам мелодии (Н2)
    melody: Tuple[PitchEvent, ...]     # skyline (Н1); accent 3 на первой доле
    chords: Tuple[ChordSpan, ...]      # полутактовые окна, слитые (Н4)
    bass: Tuple[PitchEvent, ...]       # басовый голос: низшая звучащая нота, начинающаяся на онсете (Н7)
    phrases: Tuple[Phrase, ...]; sections: Tuple[ScoreSection, ...]
    stats: MaterialStats      # rating, n_views, complexity (PDMX.csv), key_fit мелодии, доли фактур, unique_bar_share
```

`Hook` (`model.py:121-125`) получает `source` = `material_id` — поле уже строка, историю (`HistoryKey.hook`, `music_history.melody_name`) менять не нужно.

### 3.2 Импортёр — офлайн, пакетный, вне git

`scripts/music/score_import.py` (music21, BSD-3; **только офлайн**, на хосте/katana — на роботе music21 не ставится: разбор 71 партитуры занял 88.6 с, медиана 0.9 с/партитуру, максимум 5.5 с (сюита, 372 такта) на этой машине (x86, один процесс) — 250k PDMX ≈ 2.6 суток на одном ядре, на katana параллельно — часы; один файл (`Mozart K.545 Allegro`) music21 не разобрал — `MusicXMLImportException: incorrect accidental`, такие идут в отчёт отказов, §5 M1). Делает ровно то, что `score_material_probe.py` делает сейчас (skyline, аккорд полутакта по 24 трезвучиям с инерцией, басовый голос, отпечатки тактов → фразы/секции, метки) и пишет **JSON `ScoreMaterial`** + строку индекса:

- *(Место заменено ответом Шифу по В7, §8: `/opt/rob_box/scores` ресурсным паком с katana.)* Библиотека: `/data/score_library/<material_id>.json` на роботе (том `/data`, как `voice_memory.db`), источник — katana `…/score_library/` (батч по PDMX). Индекс — таблица `score_index` в том же SQLite, что RTTTL-библиотека (`core/rtttl_library.py:564-594`, `VOICE_MEMORY_DB_PATH`): `material_id, title, composer, genres, rating, n_ratings, meter, bpm, key, bars, license, phrase_count, hook_phrase_bar` — поиск по теме/жанру/рейтингу теми же `search.terms/ranked` (`engine/search.py:187-200`), что для RTTTL.
- Фильтры PDMX (из `PDMX.csv`, по брифу): подмножество `no_license_conflict`; `rating`/`n_ratings` ≥ порога (В2); `complexity` в окне; дедуп по заголовку+композитору+отпечатку первой фразы; `genres` → `knowledge.THEME_CONCEPTS`.
- **В git**: схема JSON, тесты на синтетических партитурах (3–4 файла по 8 тактов, написанных нами), выученные таблицы (§3.4). **Не в git**: партитуры PDMX и чужие аранжировки (Интерстеллар), сама библиотека.

### 3.3 Как аранжировщик берёт материал

Правило ADR-0148: решение — код по данным материала; LLM по-прежнему видит только `dj_set(theme)`/`request_music(text)` (ADR-0149 §5.1).

| Шаг | Сегодня (`origin/develop`) | С материалом |
|---|---|---|
| Хук | `hook.from_rtttl(rtttl, id, bpm, root, mode)` → первые 4–8 тактов (`hook.py:77-93`) | `hook.from_notes(notes, bpm_src, id, bpm, root, mode)` — общий путь для RTTTL и материала (RTTTL → `parse_rtttl` → ноты). Фраза из материала: `material.phrases` с максимальным `repeats` длиной 4 или 8 тактов (Н9); ничья — раньше в пьесе; секция с текстовой меткой «theme/main» — приоритет (Н12). Остальное — как сейчас: `time_scale`, перенос в тонику трека, `key_fit ≥ 0.6`, коридор, `MAX_FOLDED_SHARE` |
| Тональность трека | лад хука по `detect_key` на 8 тактах (`hook.py:181-182`) | `material.key` (Н2), тоника — из плана (`track_key`) |
| Гармония | `fit_progression`: лучший из 8 шаблонов по покрытию (`harmony.py:69-87`) | `harmony.from_material(material, phrase, style, key)`: аккорды окна фразы → ступени в тональности трека по слотам `CHORD_BARS` (аккорд слота — по длительности); недиатонический → ближайший диатонический по общим pc (2 из 3) или остаётся заимствованным, если `Style.borrowed_ok` (данные стиля); последний слот петли, не ведущий к первому (нет перехода в таблице §3.4 с P ≥ порога) → каденция стиля (`Style.cadence`, ADR-0153 §2.1). Фраза с одним аккордом (sustained, Н8) → Витерби по таблице переходов (Н6), не шаблон |
| Пэд | `pad_chords` — обращения минимального движения | без изменений (голосоведение корпуса не мерили, Н7 про бас) |
| Бас | тоника ×(n−1) + квинта (`bass.bar_notes`) | рисунок (`BASS_FIGURES`) остаётся ритмом; **тон** шага — из политики `knowledge.BASS_TONES` (Н7: прима/квинта/терция/подход, по лад-статистике корпуса) с опорой на `material.bass`: если басовый голос оригинала на этом такте стоит на терции (обращение) — терция; подход полутоном к следующему такту — если он есть у автора и `APPROACH_MAX_BEATS` позволяет (`model.py:23`) |
| Развитие | `DEVELOPMENT` build/drop/break/drop2 (`hook.py:239`) | + `drop2` вариант `rhythm`: ритм хука с контуром **следующей** фразы материала (Н10, самый частый приём корпуса); `break` — как сейчас |
| Форма | `Style.forms` (club48…) | без изменений: секции трека — стиля; `material.sections` используются только для выбора фразы и для песенной формы (`arrange/song.py`: куплеты = секции материала, аккомпанемент — из `material.chords`, а не `core/harmonize`; ADR-0153 §4.3 второй шаг) |

### 3.4 Знания из корпуса — данные в `knowledge`, выученные офлайн

Одна таблица знания (ADR-0149 §2.1): новые таблицы живут в `knowledge.py` (или `knowledge/corpus.py` с импортом через `__init__`) с шапкой-провенансом (корпус, число партитур, дата, скрипт, sha выборки):

- `PROGRESSION_TRANSITIONS: Mapping[mode, 7×7 log-P]` — переходы ступеней (Н5/Н6); `Style.progressions` остаётся пулом петель для разнообразия (A13), таблица — для Витерби и каденций.
- `BASS_TONES: Mapping[mode, {root, third, fifth, other, approach_share}]` (Н7).
- `PHRASE_RELATIONS` (Н10) — веса операций развития; `TEXTURES` (Н8) — пул фактур пэда по стилю (`arp` добавляется в `PAD_FIGURES`, ADR-0152 §3.2).

Перевыучивание — скрипт `scripts/music/research/score_markov_harmony.py` (есть) → генерирует таблицу, PR с диффом таблицы и raw-выводом. Тест проверяет свойства таблицы (строки суммируются в 1, V→I в топ-3 мажора), а не числа побайтно.

### 3.5 Выбор материала по теме (код)

`theme.seeded_profile` (`theme.py:81-104`) получает `found` от `engine/search.theme_hooks` (`search.py:275`) — туда же добавляется `score_index`: «интерстеллар» → `local:<sha>` (сегодня #3463 переводит «интерстеллар» в тему «космос» — с материалом тема получает **свой** хук). Приоритет: точное название в индексе партитур > RTTTL-библиотека > строка `THEMES`. Первый трек сета (`opening_form`) берёт материал №1 (#3427). `TrackPlan` (`set_plan.py:40-45`) получает поле `material: str = ""` — как `kick`/`template`.

### 3.6 Размер 3/4 (и 6/8) → 4/4 клуба

Варианты для хука из партитуры в 3/4 (бочка 4/4, `BEATS_PER_BAR = 4`):

| Вариант | Как | + | − |
|---|---|---|---|
| (а) растянуть такт ×4/3 | 6 восьмых → 8 слотов | такт в такт | ноты сходят с сетки 16-х (`_onsets` округляет) — ритм ломается |
| (б) **дополнить такт паузой** (3 + 1 доля) | каждый такт 3/4 → 4/4 с паузой на 4-й доле | ноты и темп те же, тема узнаётся; клубные фразы и так кончаются паузой | остинато из восьмых теряет «бег» (Интерстеллар-орган) |
| (в) полиметр: 3-дольный хук над 4/4 | хук идёт своим циклом, сходится раз в 12 долей | «тот самый» приём ремиксов | 8-тактовая петля (32 доли) не делится на 3 — стык формы рвётся (`CHORD_BARS`, `SECTION_BARS = 8`) |
| (г) перевод в 6/8 → 4/4 как 2 + 2 по триолям | 6/8 такт = 2 доли по 3 восьмых → `offset_ms` свинга | для 6/8 честно | `STEPS_PER_BAR = 16` не триольный; отложено до `meter` стиля (ADR-0153 §3 п.3) |

Решение: **(б) по умолчанию**, (в) — только в `break` (там нет бочки и баса, `hook.py:215-218`), (а)/(г) — не делать. Сравнить (б) и (в) на слух — В5.

### 3.7 Лицензии и что коммитится

- PDMX: CC-BY-4.0 (по брифу; README репозитория говорит об MIT для кода) → в репо нужна атрибуция (`docs/music/ATTRIBUTION.md`: PDMX, Long et al., ICASSP 2025; MuseScore-авторы — в `stats`/индексе на роботе). Подмножество `no_license_conflict` — обязательно (12.29 % файлов с конфликтом вне).
- В git: выученные **статистические таблицы** (§3.4), синтетические тест-партитуры, схема. Не в git: партитуры, JSON-библиотека, чужие аранжировки (Интерстеллар — не PD: музыка Циммера 2014, в PDMX такие — `license_conflict`).
- Вопрос В1: допустимо ли хранить на роботе JSON-материал пьес, которые PD как произведение, но аранжировка — пользователя MuseScore (CC-BY требует указать автора — поле `composer`/`source` в `ScoreMaterial`).
