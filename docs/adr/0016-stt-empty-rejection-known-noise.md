## 1. Контекст и бизнес-проблема

### 1.1 Симптом

Deploy-workflow (`L-Deploy and Verify.yml`) сгенерировал issue #781:

```
[stt_node-6] [WARN] [1776095961.497403368] [stt_node]: ❌ ОТКЛОНЕНО (пустое)
```

Severity `warning`, kind `warning_log`, scope `vision`, container `voice-assistant`.
Авто-sweep 12.08 уже закрыл issue #781 как «известный шум (тишина/пустой STT),
контейнер Up (healthy) — не деплой-сбой».

### 1.2 Это не деплой-сбой, а защита от эхо-петли

Строка `stt_node.py:407` — **намеренный** WARN из issue #989:

```
робот говорит фразу → микрофон ловит эхо → VAD триггерит новую фразу
→ STT (Yandex+Vosk) возвращает пустой текст → stt_node логирует WARN
и НАМЕРЕННО молчит (без «не расслышал»), чтобы не зациклиться
```

Тот же класс — `ОТКЛОНЕНО (короткое)` (Vosk/Yandex вернули «ага»/«не» — реальная
речь, но не команда). Оба случая — штатное поведение, не сбой деплоя.

## 2. Почему валидатор сработал

`deployment_issue_dedup.py` (`.github/scripts/`):

- `WARNING_MATCH_RE = \b(warn|warning)\b` ловит любую строку с «warn»;
- белые списки `WARNING_EXCLUDE_COMMON` / `WARNING_EXCLUDE_BY_SCOPE` не содержали
  паттерна `ОТКЛОНЕНО (пустое)` — поэтому первая же WARN-строка stt_node
  стала кандидатом в issue.

## 3. Решение

Кодовый фикс уже сделан в **PR #1148** (задача #684, коммит `17670537`):
добавлены два regex в `WARNING_EXCLUDE_COMMON`:

```python
r"❌ ОТКЛОНЕНО \(пустое\)",
r"❌ ОТКЛОНЕНО \(короткое",
```

+ 2 теста (`test_extract_relevant_log_line_ignores_stt_empty_rejection_vision`,
`..._short_rejection_vision`). PR открыт, мержабелен, CI зелёный (кроме
in-progress unit tests).

**Данный ADR дублировать кодовый фикс НЕ будет** — второй PR с тем же diff
создаст конфликт при мерже и шум. ADR фиксирует архитектурное решение, чтобы
будущие агенты не тратили время на повторный разбор:

1. `ОТКЛОНЕНО (пустое/короткое)` — известный шум STT, исключать из
   deploy-problem отчёта (уже сделано в PR #1148).
2. Семантику WARN в `stt_node.py` не менять: уровень `warning` — это
   диагностический маркер для локальных логов на роботе; рядом уже есть
   `info`-маркер `[issue 989]` для телеметрии. Менять `warning` → `info`
   не нужно (это снизит видимость в `docker logs` при ручной диагностике).
3. Будущим авто-issues на этот паттерн: triage → close с комментарием
   «известный шум, PR #1148», без передачи воркерам.

## 4. Альтернативы (отклонены)

| Вариант | Почему отклонён |
|---|---|
| Изменить `stt_node.py` (warning → info) | Меняет семантику диагностики на роботе; `info` уже занят маркером `[issue 989]`. Риск потерять видимость в логах. |
| Расширять `WARNING_EXCLUDE_BY_SCOPE["vision"]` | Паттерн не специфичен для vision — stt_node может жить в любом контейнере; `WARNING_EXCLUDE_COMMON` — правильное место (так и сделано в PR #1148). |
| Сложная эвристика severity (считать occurrences) | Overengineering для одного известного паттерна. |

## 5. Trade-off

- **Плюс**: ложные deployment issues на эхо-петлю исчезают; агенты не тратят
  циклы на «проблему», которой нет.
- **Минус**: если когда-нибудь `ОТКЛОНЕНО (пустое)` станет симптомом реального
  сбоя (например, STT умер и возвращает пусто 100% времени), deploy-workflow
  его не заметит. Компенсация: контейнер health-check (`docker inspect`) и
  `container_status` issues продолжают ловить мёртвый voice-assistant.

## 6. Статус

Accepted. Фикс — PR #1148 (ожидает merge). Данный ADR — документация решения.
