# ADR-0105: «Встреча» — in-process шов как первый инкремент; распределённая схема отложена до лица

| Поле | Значение |
|---|---|
| Статус | **Proposed** (решение к ревью товарища Шифу; код уже в `develop`, см. §1.2) |
| Дата | 2026-09-15 |
| Автор | Claude Opus 5 (по серии issue #2440/#2442/#2531/#2532/#2536/#2538) |
| Тип | architecture decision — разрешение расхождения между принятым дизайном и реализацией |
| Заменяет | ADR-0096 (`docs/adr/0096-encounter-seam.md`) §2.5, §9.3, §9.4 (статус того ADR — Proposed, не Accepted) |
| Родители | ADR-0013 (инкрементальная поставка), ADR-0018 (честный FAIL), ADR-0080 (порт-шов, не shared domain type) |
| Связанные | issue #2442, PR #2593 (влит `19bfeb00`), issue #2440 (шов «Знакомый», влит `8cb84bc9`), ADR-0102 («Повод»), issue #2582 (коллизия номеров ADR — причина расхождения) |

> **TL;DR.** ADR-0096 (Proposed) спроектировал «Встречу» как отдельную ROS-ноду
> `encounter_node` с собственным `EncounterState.msg`, топиком `/encounter/state` и **списком**
> встреч. PR #2593 реализовал её как in-process модуль `rob_box_harness/encounter/` с **одной**
> текущей Встречей и типизированным `who: Acquaintance`. Это расхождение по трём пунктам, два из
> которых ADR-0096 отвергал явно (§9.3, §9.4). Настоящий ADR фиксирует: **оставляем in-process
> вариант как первый инкремент**, распределённую схему откладываем до появления лицевого канала.
> Причина расхождения — не спор, а коллизия номеров ADR (#2582): на момент реализации ссылка
> «ADR-0096» разрешалась неоднозначно (три файла на этот номер, включая
> `0096-vision-hailo-launch-file-decoupling.md`), и дизайн-документ «Встречи» не был найден.
> Коллизия устранена этим же issue #2582 (renumbering PR): «ADR-0096» теперь однозначно указывает
> на этот файл.

---

## 1. Контекст

### 1.1 Что предписывал ADR-0096

| § | Предписание |
|---|---|
| §2.5 | Отдельная нода `encounter_node`, публикует `/encounter/state`; `dialogue_node` и `mcp_server` подписываются и держат read-only кеш, своей копии состояния не имеют. |
| §2.5.1 | Новый `src/rob_box_perception_msgs/msg/EncounterState.msg` — потому что «Encounter живёт дольше, чем один perception tick», разные lifecycle → разные msg. |
| §9.3 | Альтернатива «одна Встреча на всех» **отвергнута**: теряем «в мастерской сейчас двое». Вердикт — список `EncounterState.encounters[]`. |
| §9.4 | Альтернатива «`кто` как объект `Знакомый`» **отвергнута**: `Encounter` живёт в `rob_box_harness`, `Знакомый` — в отдельном пакете; shared domain type нарушает ADR-0080. Вердикт — `кто: str`. |

### 1.2 Что реализовано и влито

PR #2593 (`19bfeb00`, issue #2442), модуль `src/rob_box_harness/rob_box_harness/encounter/`:

- `EncounterSeam.current(*, now=None) -> Encounter | None` — **одна** текущая Встреча, не список.
- `Encounter.who: Optional[Acquaintance]` — **типизированный объект** из шва идентичности (#2440), не строка.
- `EncounterSeam.observe(channel, who, confidence, *, now=None)` — запись для адаптеров.
- `VoiceEncounterAdapter.on_speaker_result(payload)` — голосовой адаптер.
- Ни ноды, ни msg, ни топика. In-process, синхронное чтение, 18 unit-тестов.

То есть расхождение по §2.5, §9.3 и §9.4.

### 1.3 Почему разошлось

Не разногласие по существу — **не нашли документ**. На момент реализации на `develop` лежали три
файла с номером 0096 (`0096-encounter-seam.md`, `0096-minimax-stt-empty-text-semantics.md`,
`0096-vision-hailo-launch-file-decoupling.md`, см. issue #2582). Ссылка «ADR-0096» в переписке и
в `docker/vision/README.md` разрешалась в vision-hailo launch, и при реализации #2442 дизайн-
документ в поле зрения не попал — работа шла от текста issue.

Это первый зафиксированный случай, когда коллизия номеров привела к расхождению принятого
дизайна и кода, а не только к путанице в ссылках. Отмечено в #2582. Коллизия устранена
renumbering-PR того же issue: `0096-minimax-stt-empty-text-semantics.md` → ADR-0108,
`0096-vision-hailo-launch-file-decoupling.md` → ADR-0110; `0096-encounter-seam.md` (этот файл)
сохранил номер 0096 как первый по merge-time.

---

## 2. Решение

Оставляем **in-process вариант из PR #2593** как первый инкремент. ADR-0096
помечается Superseded в части §2.5 / §9.3 / §9.4; остальное (структура значения, edge-кейсы §6,
lifecycle §7, тест-план §8, stub-фильтр) остаётся в силе и продолжает быть спецификацией.

### 2.1 Почему одна Встреча, а не список (против §9.3)

Список оправдан только тогда, когда источник способен выдать больше одного человека
одновременно. Сегодня единственный работающий канал — голосовой, и он по своей природе даёт
одного: `speaker_id_node` публикует `/voice/speaker/result` на одну реплику, а реплика
принадлежит одному говорящему. Лицевого канала нет — Phase 2 в ADR-0089 не начат.

То есть `encounters[]` сегодня — это список, который по построению содержит ровно один элемент.
Он не даёт семантики «в мастерской двое», он даёт её *обещание*, за которое платят все
потребители: каждый обязан решить, какой элемент списка считать собеседником.

Когда лицевой канал появится, «двое в кадре» станет достижимо, и тогда список понадобится
по-настоящему — вместе с правилом выбора адресата реплики, которого сейчас нет ни в ADR-0096,
ни в ADR-0102 («Повод»). Это отдельное решение, и принимать его без единого пользователя рано.

### 2.2 Почему `Знакомый`, а не строка (против §9.4)

Аргумент §9.4 — «`Знакомый` в другом пакете, shared domain type нарушает ADR-0080» — исходил из
предположения, что identity уедет в отдельный пакет `rob_box_identity`. По факту #2440 влит
(`8cb84bc9`) **в тот же `rob_box_harness`**: `rob_box_harness/identity/`. Общего пакета пересекать
не нужно, оба шва — соседние модули одного пакета.

При этом строка обходится дороже, чем кажется: `кто: str` заставляет каждого потребителя
самостоятельно резолвить id обратно в `Знакомого`, чтобы спросить `since_last_seen` — то есть
ровно тот дефект «три места сравнивают строки по-своему», который #2440 и закрывал.

### 2.3 Почему in-process, а не нода с топиком (против §2.5)

Три довода §2.5 — «переживает падение», «нет дублирующего состояния», «явный сигнал устаревания
через `stamp`» — верны, но их цена сегодня не окупается: новый msg в
`rob_box_perception_msgs`, новый узел в launch, новый ROS-хоп через Zenoh между Main Pi и Vision Pi,
и новый failure mode «нода жива, состояние протухло».

Главное: оба потребителя (`dialogue_node`, `mcp_server`) уже зависят от `rob_box_harness` — это
показал #2440. Шов между ними не пересекает границу процесса **по необходимости**, он пересекает её
исторически. Вводить распределённое состояние раньше, чем появился второй пишущий процесс (лицевой
адаптер на Vision Pi) — это создать шов под гипотетического адаптера. «Один адаптер — шов
гипотетический, два — настоящий».

Ровно тогда, когда лицевой адаптер поедет на Vision Pi, второй пишущий процесс появится, и §2.5
станет обоснованным. Тогда и вернуться.

### 2.4 Что это стоит — честно

- «В мастерской сейчас двое» недостижимо до Phase 2. Если такой сценарий понадобится раньше,
  это решение придётся пересматривать, а не расширять.
- `EncounterSeam` живёт в памяти процесса. При рестарте `dialogue_node` текущая Встреча теряется —
  человек «входит заново». Для присутствия это допустимо (оно эфемерно по определению, ADR-0096 §7),
  для «давно не виделись» — нет, но это поле берётся из `since_last_seen` шва «Знакомый», который
  persistent.
- Пока потребители не мигрированы (см. §3), состояние дублируется: `EncounterSeam` существует
  параллельно с `dialogue_node._current_speaker` и `mcp_server.current_speaker_id`. Это временно
  и хуже, чем было бы после миграции.

## 3. Что остаётся сделать (следующие инкременты #2442)

1. Миграция потребителей: `dialogue_node._current_speaker` и XML `<user_profile>`,
   `mcp_server.current_speaker_id`, три фоллбэка в `tools/memory.py` → `EncounterSeam.current()`.
   До этого шага дублирование состояния сохраняется.
2. Зрительный адаптер — после того, как зрительный канал начнёт отдавать реальные события
   (маркер заглушки влит в PR #2583, источник кадра — в PR #2578).
3. Очистка и ограничение буфера `_hailo_events` в `context_aggregator_node.publish_event`
   (ADR-0096 §5.2 — остаётся в силе).
4. Пересмотр этого решения при появлении лицевого канала: список Встреч + правило выбора
   адресата реплики. Триггер пересмотра — первый сценарий, где в кадре двое.

## 4. Последствия для ADR-0096 (`0096-encounter-seam.md`)

Файл остаётся как спецификация значения, edge-кейсов, lifecycle и тест-плана. В его шапку
добавлена строка Superseded-by с указанием, что §2.5, §9.3 и §9.4 заменены настоящим ADR,
а §10 Open questions Q-3 (config-fix топика) закрыт PR #2578.

Коллизия номера 0096 (три файла на один номер) разведена в рамках issue #2582
(renumbering-PR, следующий за PR #2594, который развёл коллизию 0101): `0096-encounter-seam.md`
сохранил номер как первый по merge-time, два соседних файла переехали в ADR-0108 и ADR-0110.
Ссылка «ADR-0096» теперь однозначно указывает на этот файл — оговорка про ссылки по имени файла
больше не нужна.
