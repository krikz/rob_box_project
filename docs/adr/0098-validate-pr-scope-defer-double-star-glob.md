## 1. Контекст

Read-only ревью `scripts/agent_flow` (ночной sweep 2026-09-14,
kanban task `t_b969454d`) нашёлло в shipped-коде inline-комментарий,
помеченный словом «TODO» (`scripts/agent_flow/validate_pr_scope.sh:165`):

```bash
# bash case поддерживает *, ? — для ** нужен extglob. У нас fnmatch-
# не нужен (paths типа "*.md", "docs/**/*.png" → раскладываем
# вручную: для ** это "docs/*/*.png" и т.п. — TODO если спросят).
# Пока — простой wildcard через case.
```

Это не долг по функциональности (текущая логика корректно обрабатывает
`*` и `?` через bash `case`, что покрывает все текущие PR — все 12
сценариев `tests/test_validate_pr_scope.sh` PASS), но ADR-0018
«honest naming» и CONTRIBUTING.md §🐉 явно говорят:

> недоделки (`TODO`/`NotImplementedError` в merged-коде, фича без теста,
> скрипт без регистрации в `install.sh`) — недопустимы в shipped-коде.

`validate_pr_scope.sh` — критичный post-merge gate (см. ADR-0055,
ADR-0095, PR #2040 / PR #2447). Inline TODO в нём:

1. **Нарушает честность нейминга**: комментарий обещает возможное
   будущее поведение (`docs/**/*.png` → `docs/*/*.png`), которое
   сейчас не реализовано и не запланировано.
2. **Создаёт точку неопределённости**: читатель кода не знает,
   «TODO» = «запланировано и скоро будет» или «забытый хвост
   черновика» (что и было — автор комментария оставил метку на
   случай, если спросят, но не заводил под это issue).
3. **Ломает авто-детектор**: `agent-flow-nightly-review.sh` и
   связанные скрипты ловят `TODO` в merged-коде (см. §3a
   CONTRIBUTING.md, ретро 03.09). Один зафиксированный `TODO`
   = ежесуточная ложная находка, которая размывает сигнал.

## 2. Решение

Принят **Option 1** из issue #2490 (record-only):

1. **Зафиксировать отложенное намерение в этом ADR** (это и есть
   tracked feature-issue, согласно ADR-0018 — TODO либо реализуется,
   либо превращается в issue).
2. **Заменить inline-комментарий** в `validate_pr_scope.sh:165` на
   ссылку «see ADR-0098» — комментарий больше не обещает
   функциональность, которой нет; вместо этого указывает на
   архитектурное решение отложить.
3. **`**`-glob НЕ реализуется** в рамках этой задачи — это вне
   scope read-only ревью и не блокирует текущие PR (все 12
   сценариев теста PASS без `**`).

### 2.1 Альтернатива (отклонена)

**Реализовать `**`-glob сейчас** (Option 2 из issue #2490).

- Плюс: комментарий превращается в реальную фичу.
- Минус 1: расширение scope read-only ревью (новый код в
  критичный gate; требует собственных тестов + проверки на
  существующих PR с `**` в glob'ах).
- Минус 2: спрос на `**`-glob не подтверждён. Текущие PR
  (по `tests/test_validate_pr_scope.sh` сценарии A–J, плюс
  ретро PR #2444 / #2489 / #2491) используют только `*` и `?` —
  реализация была бы YAGNI-работой.
- Минус 3: ADR-0018 «honest naming» выполняется и через этот
  ADR: «превращение TODO в issue» — допустимый вариант per
  ADR-0018, не обязательно «реализация прямо сейчас».

Решение: **отклонить реализацию пока не появится зафиксированный
спрос** (новый PR или issue, требующий `**`-glob).

### 2.2 Что меняется в `validate_pr_scope.sh`

**До** (текущее):
```bash
# bash case поддерживает *, ? — для ** нужен extglob. У нас fnmatch-
# не нужен (paths типа "*.md", "docs/**/*.png" → раскладываем
# вручную: для ** это "docs/*/*.png" и т.п. — TODO если спросят).
# Пока — простой wildcard через case.
case "$f" in
    $g) ALLOWED=1; break ;;
esac
```

**После** (с этой PR):
```bash
# Поддерживает *, ? через bash case. **-glob (например, "docs/**/*.png")
# НЕ поддерживается — если потребуется, см. ADR-0098 (deferred feature).
case "$f" in
    $g) ALLOWED=1; break ;;
esac
```

Это:
- убирает слово `TODO` из shipped-кода (CONTRIBUTING.md §🐉 + ADR-0018);
- делает ограничение **явным** (а не «TODO если спросят»);
- указывает, **где** искать контекст (ADR-0098) — это та же
  форма, что уже используется в скрипте (`see ADR-0055`,
  `see ADR-0115 §8`).

### 2.3 Что НЕ меняется

- Логика сопоставления glob'ов (`case "$f" in $g) ...`) — та же.
- Контракт gate'а (PR_ALLOWED_PREFIXES, PR_ALLOWED_GLOBS, exit codes).
- Существующие тесты (`scripts/agent_flow/tests/test_validate_pr_scope.sh`,
  все 12 сценариев A–J + E2 — PASS).
- Регистрация в `install.sh` (`EXPECTED[]` — без изменений).

## 3. Trade-offs

- **«Заменить TODO на ссылку» vs «удалить TODO совсем».**
  Удалить короче, но ADR-0095 / ADR-0098 уже установили формат
  «see ADR-NNNN» в этом же скрипте; единообразие улучшает
  читаемость. Решили: заменить на ссылку.
- **«Завести отдельное GitHub issue на `**`-glob» vs «этот ADR —
  и есть tracked feature».** ADR-0018 говорит «превращаться в issue»
  без уточнения формы. В нашем процессе ADR — это **полноправный
  трекаемый артефакт** (см. ADR-0095 «PR pollution detection» —
  feature задокументирована в ADR, потом реализована в PR #2447).
  Решили: ADR-0098 = tracked feature, отдельный GH-issue не нужен.
- **«Поднять приоритет (открыть PR на реализацию)» vs «ждать спроса».**
  Нет PR / issue, требующего `**`-glob. Решили: ждать. ADR-0098 —
  это «opt-in точка» для будущего триажа: когда кто-то скажет
  «нужен `**`-glob», триаж-агент найдёт ADR-0098 за 1 grep.
- **«Удалить комментарий совсем» vs «оставить ссылку».**
  ADR-0098 — opt-in для будущей фичи. Без явного комментария
  в коде будущий воркер может заново «изобрести» `**`-glob и
  не найти ADR-0098. Решили: оставить комментарий-ссылку
  (2 строки, ~80 символов — overhead минимален).

## 4. Альтернативы (рассмотренные и отклонённые)

- **Реализовать `**`-glob через bash `shopt -s globstar` + цикл.**
  globstar в bash 4+ поддерживает `**`, но только для **раскрытия
  путей в файловой системе**, а не для pattern-matching произвольных
  строк (как у нас — пути приходят из `git diff`, не из FS).
  Потребовалось бы симулировать FS (создавать временные файлы) —
  безумие для gate-скрипта. Не подходит.
- **Реализовать через `fnmatch` (GNU coreutils, не POSIX).**
  Есть в `bash` через `[[ … = $pattern ]]` (extglob), но в POSIX
  `case` — отсутствует. Зависимость от bash-расширений в gate'е,
  который должен работать в любой CI-среде — рискованно.
- **Вынести pattern-matching в Python helper.**
  Усложняет контракт (сейчас single bash-скрипт, 200 строк,
  zero-dependency). YAGNI, пока спроса нет.
