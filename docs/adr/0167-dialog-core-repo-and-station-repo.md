## 1. Контекст

- Пакет `rob-box-dialog-core` уже есть внутри репо (`packaging/dialog-core/pyproject.toml`, PR #4278): собирается из тех же
  каталогов `src/`, без копий. Тесты из пакета на 3.10–3.12 зелёные (run 41678633883, **измерено** в #4245).
- 07.11 ядро запущено **на самой колонке** (Яндекс Станция Лайт, armv7, 244 МБ ОЗУ, `/data` 76 МБ): Питон 3.12
  python-build-standalone, консоль v2, LLM DeepSeek — «Робот, который час?» → «Сейчас двенадцать ноль пять…», пик 49,7 МБ,
  запуск + ход 13–14 с; голос MiniMax (синтез → динамик → микрофон → распознавание) вернул ту же фразу (**измерено**).
- Чтобы это запустить, на колонку пришлось руками собрать 133 файла, которые консоль открывает (трасса `sys.addaudithook`),
  поверх пакетов целиком. Среди них **не-Python данные вне пакета**: `src/rob_box_voice/prompts/master_prompt_compact.txt`,
  `docker/sound/config/wake_words.yaml`, `migrations/*.sql` (12 файлов), `rob_box_dialog/phrases/ru.yaml` (**измерено**).
  Значит, граница пакета ещё не замкнута: ядро читает файлы робота.
- Связка хода живёт в `rob_box_voice` (ROS-пакет робота), пакет ядра берёт её отдельными модулями (`py-modules`),
  `rob_box_voice` и `rob_box_mcp_tools` в пакете **неполные** (комментарий в `pyproject.toml`, **по коду**).
- Связку импортируют робот-хосты вне ядра: `rob_box_mcp_tools` (mcp_server, tools/dialogue, tools/system, voice_request,
  engine/gen/song), `rob_box_supervisor` (supervisor_node, operator_turns), `rob_box_quest` (streams/voice_picker),
  `rob_box_voice` (plan_host, turn_context, utils/legacy_voice_facts) (**по коду**, `grep`).

## 2. Решение — три репозитория

```
rob_box_dialog_core   (пакет rob-box-dialog-core, без ROS)  ◀── pip, тег vX.Y.Z ──┬── rob_box_project (робот, ROS-хосты)
   ход, адресация, LLM, мост команд,                                               └── rob_box_station (колонка)
   память, фразы, адаптеры STT/TTS, консоль
```

### 2.1. `rob_box_dialog_core` — что входит

| Часть | Откуда | Метка |
|---|---|---|
| `rob_box_core`, `rob_box_llm`, `rob_box_harness`, `rob_box_dialog`, `rob_box_music` (модель) — целиком с тестами | `src/<пакет>/` | по коду |
| Связка хода: `command_bridge`, `command_intent`, `command_parser`, `dialog_v2_ports`, `faq_store`, `media_phrases`, `music_player_state`, `speaker_memory`, `voice_memory`, `tts_voice_registry` | `src/rob_box_voice/rob_box_voice/…` → новое место **внутри ядра** (`rob_box_dialog.host.*`, имя — §7 В3) | по коду |
| Из `rob_box_mcp_tools`: `owner_event`, `voice_request`, `base` | `src/rob_box_mcp_tools/…` → ядро | по коду |
| Адаптеры речи без ROS: `stt_providers/*`, `stt_fallback`, `stt_hang_guard`, `core/yandex_stt_segments`, `tts_engines`, `tts_chunking`, `tts_text_guard` (`providers/minimax_tts` уже в `rob_box_llm`) | `src/rob_box_voice/…` | по коду; STT/TTS MiniMax на колонке — измерено |
| Данные: промпт `master_prompt_compact.txt`, `wake_words.yaml`, миграции памяти `migrations/*.sql`, фразы | `src/rob_box_voice/prompts`, `docker/sound/config`, `migrations/` → `package-data` ядра | измерено (трасса) |
| Стенд и консоль: `scripts/dialog/dry_stand.py`, `dry_marathon.py`, `understanding_variants.py`, `e2e_db.py`, `scripts/dialogue/*` | `scripts/` | по коду |
| Гарды кода (`cc_budget`, `class_budget`, `seam_without_consumer`, `temp_adr0148_check`), `AGENTS.md`-правила, CI тестов 3.10–3.12 | копия из `scripts/lint/` | по коду |

Ядро не импортирует ROS на верхнем уровне (это уже сверяет `test_core_package_4245.py`) и **не читает файлы вне пакета**:
пути к промпту, вейк-словам и миграциям — из `importlib.resources`, хост может подменить их своим каталогом.

### 2.2. `rob_box_project` (робот) — что остаётся

ROS-хосты и владельцы робота: `dialog_node`, `stt_node`, `tts_node`, `audio_node`, музыка (SuperCollider, деки), лицо,
навигация, LED, восприятие, Docker, compose, деплой, марафон на роботе. Ядро ставится в образ `voice-assistant`
(и другие, где его импортируют) через `pip install "rob-box-dialog-core @ git+https://github.com/krikz/rob_box_dialog_core@vX.Y.Z"`.
Каталоги ядра из `src/` удаляются тем же PR, что переключает образ на пакет (ADR правило «две реализации не держать»).

### 2.3. `rob_box_station` (колонка) — что входит

- Хост колонки `station_host.py`: `arecord`/`aplay` (48 кГц, 6 каналов → 16 кГц моно), VAD по энергии, полудуплекс
  (эхоподавления без Алисы нет), STT и TTS через адаптеры ядра, ход через стенд ядра с настоящим владельцем речи.
  Черновик проверен на колонке 07.11 (`--selftest`) — **измерено**.
- Установщик: сборка Питона под armv7 (обрезка python-build-standalone 67 → 28 МБ), колёса armv7 (`pip download --platform
  manylinux*_armv7l`), заливка по SSH, автозапуск хоста, `S99zzyandexoff`.
- Runbook рута (`docs/runbooks/yandex-station-root.md`) и осмотр (`inventory.sh`, `docs/station/`) переезжают сюда.
- Промпт и срез тулов колонки (К3 ADR-0160 §8): без движения, лица и камеры.
- **Первая настройка по Bluetooth** (Шифу 07.11): колонка без сети поднимает BLE-сервис, телефон передаёт имя и пароль
  Wi-Fi, колонка пишет их в `wpa_supplicant.conf` (`/bkupgrade/data/`) и докладывает свой IP. На колонке есть
  `bluetoothd` (BlueZ, запущен), `bluetoothctl`, `gatttool`, `dbus-send`, адаптер `hci0` UP (**измерено** 07.11).
  GATT-сервис регистрируется у `bluetoothd` через D-Bus (`org.bluez.GattManager1`) из Питона — D-Bus-клиент на чистом
  Питоне, протокол — открытый Improv Wi-Fi (его понимают готовые приложения и страница в браузере с Web Bluetooth),
  чтобы не писать своё приложение для телефона. 07.11 сделано на `dbus-next` 0.2.3 (разрешение Шифу): сервис и реклама
  регистрируются у `bluetoothd -E` (**измерено**, лог хоста); с телефона — ещё не проверено.
- **Страница настроек** (Шифу 07.11): веб-страница колонки в локальной сети — ключи провайдеров, промпт, голос,
  провайдеры LLM/STT/TTS, вейк-слово, громкость. Сервер — `http.server` стандартной библиотеки (готового `httpd` на колонке
  нет, **измерено**). Ключи пишутся в файл `0600`, обратно на страницу не отдаются (только «задан / не задан»); вход по
  паролю, который задаётся при настройке по Bluetooth. Сохранение перезапускает хост колонки.

### 2.4. Ядро для всех: библиотека с профилями продуктов (Шифу 07.11)

Шифу 07.11 (чат приложения): решение должно годиться не только роботу и колонке, но и другим, и чтобы им было удобно.
Отсюда граница: **ядро — библиотека с нейтральными умолчаниями; всё, что делает продукт роботом, колонкой или чьим-то
ассистентом, — профиль продукта в его собственном репо.** Ни один файл не живёт в двух местах: у каждого один владелец.

| Что | Владелец | Как читается |
|---|---|---|
| Миграции памяти `migrations/*.sql`, фразы кода `phrases/ru.yaml`, основа системного промпта **без имени продукта** | ядро (`package-data`) | `importlib.resources`; хост их не подменяет — это код ядра (основу промпта можно заменить целиком, как колонка со страницы) |
| Имя и характер, вейк-слова, провайдеры LLM/STT/TTS и голос, язык, набор владельцев | профиль продукта (`assistant.yaml` + файлы рядом) | хост передаёт путь к профилю ядру; нет профиля — нейтральные умолчания ядра |
| Ключи провайдеров | окружение / `.env` продукта | никогда не в профиле и не в репо |
| Таблица вейков робота (`docker/sound/config/wake_words.yaml`) | `rob_box_project` — это профиль робота | монтируется как сейчас; в ядре — только формат и загрузчик |
| Вейк, промпт, голос колонки | `rob_box_station` (страница настроек пишет `settings.json` и `prompts/`) | хост колонки — уже так (07.11, **измерено**) |

**Владельцы и тулы — по профилю.** Порты владельцев (речь, музыка, движение, батарея, восприятие…) — протоколы ядра;
продукт регистрирует только те, что у него есть, и тулы без владельца не попадают в схему модели. 07.11 колонка без
этого отвечала «заряд 87 %» и «никого в кадре» (выдумки стенда консоли) и не знала свой адрес (**измерено**, лог хода);
хост колонки закрыл это подменой инструментов и фактами устройства в промпте — временно, до среза тулов в ядре.

**Удобство для других** (минимум, без которого пакет не взять):
- `pip install "rob-box-dialog-core @ git+…@vX.Y.Z"`; зависимости без ROS (уже сверяет `test_core_package_4245.py`);
- консоль из пакета: `rbx-chat --profile ./my_assistant` (ход текстом, без микрофона) — первая проверка профиля;
- пример профиля `examples/minimal/` (имя, вейк, провайдер, один тул) и README «свой ассистент за 10 минут»;
- сухой стенд (`dry_stand`) для тестов продукта: свои тулы — свои обработчики, без живых провайдеров;
- семвер и `CHANGELOG.md`: ломка порта или формата профиля — мажорная версия.

**Порядок.** Ш1 режется на шаги, каждый — свой PR и проверка: **Ш1а** — данные ядра в `package-data` (миграции, фразы,
основа промпта), робот читает их из пакета; **Ш1б** — профиль продукта: формат `assistant.yaml`, загрузчик, вейки и персона
робота уходят в его профиль; **Ш1в** — тулы по владельцам профиля; **Ш1г** — связка хода в ядро (имя — В3). Ш2 — после Ш1.

**Ш1в (10.11).** Порты владельцев — таблица ядра `rob_box_dialog.owners.TOOL_OWNERS` (у каждого тула командой ровно
один владелец); профиль формата 4 перечисляет, какие из них у продукта есть (`owners`). Хост передаёт их сессии, мосту
команд и разделу инструментов ТАРС; срез агента (`agents.tools_for`) берёт только тулы этих владельцев. Без профиля —
ни одного тула продукта. У робота перечислены все порты: схема команды, правила промпта, срезы тулов трёх агентов на корпусе
реплик понимания и раздел инструментов ТАРС — байт в байт прежние (SHA256 в PR). Что осталось за Ш1в: каталог тулов
(`rob_box_core._tool_catalog_data`, генерируется из `rob_box_mcp_tools`) и таблицы слов групп (`knowledge.TOOL_GROUPS`)
пока в ядре; пути Tier-1 кодом (медиароутер, «стой») зовут тулы без среза — у колонки их закрывает хост.

## 3. Как живут два репо (цикл изменения)

1. Правка ядра — PR в `rob_box_dialog_core`, CI ядра, мёрж, тег `vX.Y.Z` (семвер: ломка порта — мажор).
2. Подъём версии у потребителя — отдельный PR в `rob_box_project` (строка версии в `requirements`/Dockerfile) и/или в
   `rob_box_station`; там же живая проверка на роботе или колонке.
3. Ветка ядра под незавершённую работу робота не держится: если правка нужна обоим, сначала ядро с тестом, потом подъём.

Цена (**догадка**): изменение ядра, видимое на роботе, — два PR и одна сборка образа вместо одного PR. Выигрыш — граница
ядра проверяется вторым потребителем, и колонка не тянет ROS-репо.

## 5. Отвергнутое

- **Сабмодуль** — решение Шифу 30.10: плохо живёт с worktree и воркерами.
- **Пакет только внутри монорепо** (как сейчас, `git+…#subdirectory=`) — дешевле, но Шифу 07.11 решил выносить; колонка тянула бы весь репо робота.
- **Копия ядра в репо колонки** — две реализации разъедутся.
- **Ядро на Расте** — оценка 07.11 в Telegram: ~47 тыс. строк кода и ~55 тыс. строк тестов переписать; Шифу: «давай на питоне в начале пробуем».

## 6. Последствия

- В `rob_box_project` уходят ~47 тыс. строк кода и ~55 тыс. строк тестов ядра (**измерено** `wc -l` 07.11).
- Воркер, чинящий ход, работает в репо ядра; CI робота ядро больше не тестирует, только подъём версии.
- Гарды и `AGENTS.md` ядра — копия; правило правится в обоих местах (**догадка**: стоит вынести гарды в общий пакет позже).
- Сборка образов робота качает ядро с GitHub: для приватного репо нужен токен на чтение в CI и на katana.
