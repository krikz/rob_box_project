# ADR-0077: эмпирический сбор STT-искажений «ТАРС» с микрофона шлема

**Статус:** proposed (issue #2158, follow-up #2135)
**Дата:** 2026-09-08
**Автор:** архитектурное ревью (kanban t_c4cd1f74)
**Заменяет:** — (заполняет «открытый вопрос №1» §14 целевой архитектуры `target-operator-agent-and-dialogue.md`)
**Пересматривает:** ADR-0065 (operator-wake-words SSoT) — не код, а процесс наполнения
**Блок-зависимость:** #2135 (сегментация wake-фразы), влито как PR #2155 / commit 598f6128

---

## 1. Контекст

В namespace `operator` файла `docker/vision/config/wake_words.yaml:49-51`
сейчас два варианта: `тарс`, `tars`. Живой замер на роботе 2026-09-08
показал: STT (Yandex gRPC) на wake-сегменте шлема вернул «**арс** расскажи мне
анекдот», вейк не сработал, робот промолчал.

Целевая архитектура §14.1 прямо предписывает **не придумывать** STT-искажения,
а собирать их по логам e2e, как собирали для «роббокс». Этот ADR фиксирует
процесс сбора и куда положить результат.

Дополнительные факты, которые решают форму ADR:

1. PR #2155 (598f6128) уже влит — wake-поток шлема теперь сегментируется в
   фразы **до** STT (`QuestBridge` → `core/wake_segmenter.py`). Без этого шага
   в STT уходили 20мс кадры и никакого распознавания получить было нельзя.
2. Тест `test_wake_word_sync.py::test_dialogue_text_defaults_cover_all_canonical`
   (`src/rob_box_voice/test/unit/core/`) уже защищает SSoT для personality —
   аналог для operator нужно создать.
3. Тест `test_wake_words_config.py::test_operator_matches_code_default`
   уже блокирует дрейф YAML ↔ Python fallback на уровне байт-в-байт.
4. SSH к `ros2@10.1.1.21` для текущей архитектурной сессии = `Permission
   denied (publickey,password)` — собрать живые логи прямо сейчас невозможно.
5. Инвариант 6a (целевая §11): **микрофоны не пересекаются** — ReSpeaker
   слышит только личность, шлем — только ТАРС. «ТАРС», сказанное в
   ReSpeaker-канал, игнорируется. Любая правка списка wake-слов должна
   пройти проверку «фоновая речь не даёт ложного wake» — иначе риск
   ложных срабатываний растёт экспоненциально от длины списка.

## 2. Решение

### 2.1 Никаких выдуманных слов. Сейчас в `operator` ровно `тарс`, `tars`

До эмпирического сбора список **остаётся** в текущем виде. Добавлять
варианты вроде «тарз», «тас», «target» вслепую запрещено: §14 целевой
архитектуры прямо фиксирует, что они **придумываются**, а не собираются.
Ложные слова в operator namespace ломают инвариант 6a — шлемовый wake
начинает срабатывать на фоновую речь или шум.

### 2.2 Сбор через хук в `stt_node` для wake-сегментов без операторского вейка

Добавляется точка наблюдения в `stt_node.py::quest_wake_audio_callback`
/ `_route_wake_result` / `_handle_rejected_text` (где обрабатывается именно
шлемовый wake-поток, source=`_SRC_WAKE`). Хук пишет **только в файл**
(не в STDOUT, чтобы не утопить обычный лог в выборке):

```
$data/stt_tars_samples.jsonl   (JSON Lines)
{
  "ts_ms":           ...,
  "duration_s":      ...,
  "raw_text":        ...,
  "has_operator_wake": true|false,
  "yandex_attempts": [...],
  "vosk_attempt":    ...|""
}
```

Каждая строка — ровно один wake-сегмент. Поведение робота **не меняется**:
публикация в `/avatar/stt/result`, маршрутизация, инварианты 6a/6 — всё
как сейчас. Файл сбора — это side-channel, для анализа постфактум, не
для продуктивного решения.

Файл попадает в gitignore (`data/` уже в нём). Сборщик запускается
только когда есть переменная `ROBBOX_STT_COLLECT=1` — kill-switch по
умолчанию. Без переменной хук no-op и в файл ничего не пишется.

### 2.3 `Makefile` цель `stt-tars-stats` — сухая сводка

Скрипт `scripts/stt/tars_stats.py`:

```
make stt-tars-stats STT_LOG=data/stt_tars_samples.jsonl
```

Что делает:
* читает JSONL, группирует по `raw_text` (нормализация lower + strip);
* печатает таблицу с частотой, длительностью, распределением yandex-only
  vs yandex+vosk, долей wake-хитов;
* в режиме `--diff` сравнивает с текущим `wake_words.yaml`::operator
  и печатает **только подсказку** «вот слова, которых нет, но они встречаются
  N раз на M сегментов». Ничего не правит.

Это даёт владельцу робота (Шифу) материал для решения о добавлении
в список. Решение принимает **он**, на основе сводки, а не архитектор
вслепую.

### 2.4 Защита от дрейфа YAML ↔ код

Дополнить `test_wake_word_sync.py` параметризованным тестом
`test_operator_canonical_variants_accepted` и каноническим списком
`CANONICAL_OPERATOR_WAKE_WORDS` (сейчас — `тарс`, `tars`). Тест
`test_dialogue_text_defaults_cover_all_canonical` уже требует
`set(CANONICAL_*) <= set(DEFAULT_*)`. Для operator это означает: **любое
добавление в YAML должно идти через DEFAULT_OPERATOR_WAKE_WORDS → YAML,
одним коммитом**. Сейчас для operator списка нет вообще — создаём,
чтобы при первом же эмпирическом добавлении цепочка была уже выстроена.

### 2.5 Защита инварианта 6a (фоноречь → молчание)

Расширить `TestWakeRoute` (`test/test_stt_node_router.py`):
`test_wake_acceptance_with_stt_distortion` — сегмент «**арс** расскажи
анекдот» (или любой другой реалистичный STT-вывод) НЕ должен публиковать
в `/avatar/stt/result`, если слова нет в wake-list. Это страховка
на будущее: когда добавим «тарз» в список — тест зафиксирует базовое
поведение **до** расширения.

Сейчас в тестах уже есть:
* `test_wake_without_operator_wake_is_dropped` — сегмент без операторского
  вейка → drop.
* `test_wake_personality_word_does_not_address_agent` — «робокс» из шлема
  НЕ адресует ТАРС.
* `test_wake_rejection_still_silent_no_unclear_prompt` — на wake-сегменте
  робот не переспрашивает.

Добавляем:
* `test_wake_short_misrecognition_does_not_match` — короткий мусор вроде
  «арс» тоже не должен проходить (тест на fallback-ы вроде is_short_phrase).
* `test_wake_negative_set_rejected_for_known_phonemes` — параметризованный
  тест на наборе слов, которые **точно НЕ должны** срабатывать («арс»,
  «тар», «тара», «дарс», имя оператора). Этот набор — freeze-лист,
  расширяется только решением владельца.

### 2.6 Дочерняя kanban-карточка на эмпирический сбор

Отдельная карточка `t_<new>` с:
* assignee = тот, у кого есть SSH к `ros2@10.1.1.21`;
* body = «включить `ROBBOX_STT_COLLECT=1`, надиктовать «ТАРС» 30 раз
  подряд с трёх разных расстояний до рта (10/30/60 см), выключить
  переменную, приложить `stt_tars_samples.jsonl`, запустить
  `make stt-tars-stats`, приложить сводку, предложить конкретные
  варианты для добавления **с количеством наблюдений на каждом**»;
* Definition of Done:
  - Приложен `stt_tars_samples.jsonl` (размер и sha256).
  - Приложена сводка `make stt-tars-stats` (raw-вывод).
  - **Никаких** изменений в YAML без отдельного решения Шифу — карточка
    только собирает факты.
* Результат архитектурно фиксируется через отдельную правку wake-list
  (одним коммитом: `wake_words.yaml` + `DEFAULT_OPERATOR_WAKE_WORDS` +
  пополнение `CANONICAL_OPERATOR_WAKE_WORDS` в тесте), уже без
  архитектурной карточки, достаточно backend-воркера.

## 3. Альтернативы

**A. Сразу добавить в `operator` «тарз», «тас», «target», «тэрс».**
Отклонено. §14 целевой прямо запрещает; инвариант 6a прямо растёт в
риске от коротких вариантов. Шифу фиксирует в карточке #2158 ровно
эту границу: «не придумываем — собираем».

**B. Собирать статистику из `/voice/dialogue/state` и `/voice/stt/result`**
постфактум. Отклонено. Эти топики не несут wake-сегментов шлема —
они публикуются только при успешном распознавании. Без логирования
**отклонённых** wake-сегментов статистика искажена в пользу гипотез.

**C. Использовать Loki / promtail (упомянуты в §6 целевой как источник
для инструмента `read_logs`).** Рассмотрено, отложено. Loki уже
собирает контейнерные логи, но семантический разбор «`raw_text="арс
расскажи мне анекдот"`, has_operator_wake=false, source=wake» через
LogQL — медленнее и хуже структурирован, чем jsonl. JSONL-файл
создаётся в одном месте, читается одним тулингом. Перевод на
Loki — естественный следующий шаг, **когда** объём выборки станет
настолько большим, что файл перестанет помещаться.

## 4. Чего этот ADR НЕ делает

* **Не прав** wake-words список. Сейчас `тарс`, `tars` — и это всё.
* **Не собирает** данные сам. Это задача отдельной карточки (см. §2.6).
* **Не решает** про PR для добавления вариантов. Когда данные собраны —
  это `developer`-задача на 1 коммит (три файла в одном коммите:
  `wake_words.yaml`, `DEFAULT_OPERATOR_WAKE_WORDS`,
  `CANONICAL_OPERATOR_WAKE_WORDS` в тесте).
