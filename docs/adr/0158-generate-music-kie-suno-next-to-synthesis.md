### 1.2 Что умеет и чего не умеет наш синтез (на 13.10)

Аранжировщик v2 (ADR-0149/0153/0157): пьеса по названию (партитура PDMX / RTTTL-хук), DJ-сет в стилях `club, rave, synthwave, chiptune, breaks, dnb` (+ `lofi` — PR #3586 ждёт Шифу, судья 3/10; `rock` — забракован Шифу, #3597; `jazz` — есть в `STYLES`), мгновенно (≤ 3 с), бесплатно, детерминированно, со стыками на двух деках. Не умеет: **голос и текст** (петь), **живые инструменты** (балалайка, гитара, оркестр — паков нет, ADR-0157 §2.4, исследование #3587), **жанры, где нужен «настоящий» звук** (рок/гранж — забракован, металл, блюз, шансон, акустика).

Генерация (Suno) закрывает ровно эти дыры, но: секунды-десятки секунд ожидания, деньги, сеть, недетерминированность, нельзя «сыграть Токкату Баха» по нотам (генератор не воспроизводит конкретную мелодию по названию). Поэтому путь выбирает **код по структуре запроса**, а не LLM и не «всегда генерация».

## 2. Решение

Общий принцип товарища Шифу (13.10): **«что у нас и так норм играет — пусть играет; всё остальное пробуем в генерацию через Suno плюс кэш; токены на доводку аранжировщика пока не жечь»**. Рок на синтезе признан провальным (судья + Шифу) → рок идёт в генерацию.

Шесть принципов — продолжение ADR-0148/0157.

### 2.1 Генератор — провайдер за интерфейсом, без тихой деградации

```python
class MusicGenProvider(Protocol):
    name: str                                         # "kie_suno"
    def submit(self, job: GenJob) -> GenTicket        # GenUnavailable(reason) — сразу, без звука
    def poll(self, ticket: GenTicket) -> GenStatus    # stage ∈ {queued, text, first, complete, failed}; tracks[] частичные
    def balance(self) -> Credits | None               # GET /api/v1/chat/credit; None — неизвестно
    def cost(self, job: GenJob) -> Credits            # из таблицы GEN_MODELS (сегодня 12 за задачу, §1.3)

@dataclass(frozen=True)
class GenJob:
    kind: Literal["instrumental", "song", "robot_song", "cover"]
    style_key: str            # ключ GEN_STYLES (§3.2), теги Suno — из таблицы, не из LLM
    title: str
    duration_s: int           # 60..360, по умолчанию 150
    lyrics: str = ""          # song / robot_song
    audio_path: str = ""      # robot_song: вокал TTS; cover: наш рендер (загружается в KIE, живёт 24 ч)
    model: str = "V6"         # ключ GEN_MODELS
```

`GenUnavailable.reason` — перечень: `no_key`, `no_credits` (KIE `code=402`), `rate_limited` (429), `provider_down` (455/5xx/таймаут сети), `rejected` (422/400 — контент, параметры), `timeout` (нет `complete` за `GEN_TIMEOUT_S` = 180 с), `budget_exhausted` (наш лимит, §2.6). Первый провайдер — **Suno через KIE** (`kie_suno`); второй встаёт за тот же интерфейс без правки вызывающих. HTTP 200 + `code` ≠ 200 — ошибка (у KIE HTTP-статус всегда 200). Callback не используем (у робота нет публичного адреса) — опрос `record-info` с шагом 2 → 4 с.

**Ранний звук (14.10, `engine/gen/stream.py`).** Замер воркера PR-8 (task `f5aa62a5…`, V6 120 с): на стадии `text` (≈ 32 с) `stream_audio_url` со своим UA отдал весь трек за 6 с, `success` — на 50 с. Для кавера, песни и одиночного инструментала (их держит мост) `pipeline.generate_into_cache(early=True)` пробует по разу на стадии `text` (стрим) и `first` (`audio_url` 1-го варианта): скачивание ≤ 20 с, декод в wav сервера, длина ≥ `duration` ответа (иначе заказанной) − 3 с, у песни ≥ 0.85 длины вокала. Принят — вариант в кэш с готовым wav и сразу мосту; второй вариант, финальный `audio_url`, длину и факт кредитов дописывает фоновый финишёр после `success`, без повторного проигрывания. Не принят — причина в лог, ждём `success` как раньше. Сет (`gen_session`) ранний звук не берёт: заказывает наперёд и ждёт оба варианта.

**Цена V6 и V6_MINI (вопрос Шифу Б2).** По замеру одинаково: 12 кредитов за задачу и у V6 (180 с, `09e64acf…`; `add-instrumental` 82 с, `7e10941d…`), и у V6_MINI (60 с — `f7cff936…`, 120 с — три задачи). Иной цены в прочитанных документах KIE нет (страница прайса рендерится скриптом, Suno-раздел не виден — §0). Разница только во времени: V6_MINI 20–37 с на 120 с, V6 ≈ 51 с на 180 с.

### 2.2 Чойсер пути — выбор среди кандидатов, построенных кодом

Не таблица «стиль → путь», а тот же механизм выбора, что у произведения (ADR-0157 §2.2, PR-3/PR-7): **код собирает контекст и список кандидатов → `Chooser` выбирает один → код исполняет и строит фразу**. Под капотом — то, что уже влито: `DeterministicChooser` (взвешенная сумма признаков), при неоднозначности (разрыв < `CHOOSER_CLEAR_GAP`) — цепочка **Jev → LLM под харнессом → кубик кода** (`engine/chooser_model.py`, `ChainModel`). Модель список кандидатов не расширяет; ответ вне списка, таймаут, ошибка — следующая ступень, в конце — код.

```
фраза ──► грамматика: MediaCommand (слоты ADR-0157 §2.1 + vocal/robot_voice/own/fresh/generated/genre)
       ──► SourceContext (код):
             наш материал:  хуки/партитуры по запросу (кандидаты ADR-0157 §3.2) + стили синтеза с годностью synth_fit
             кэш:           треки библиотеки по request_key / pool_key: id, теги, когда играл, рейтинг, вариант
             деньги:        баланс KIE (кэш balance(), ≤ 1 ч), цена задачи, остаток дневного лимита и лимита сета
             режим:         зачаток, по умолчанию auto; переключения нет (§2.8)
             провайдер:     есть ли ключ, не «мёртв» ли (dead_until, как у TTS)
       ──► кандидаты (код, жёсткие фильтры ДО выбора):
             synth:<style|work>        — если synth_fit ≥ SYNTH_FIT_MIN и запрос не требует голоса;
                                         для пьесы по названию — мост/фолбэк кавера (ниже)
             generate:cover:<work>     — пьеса по названию: НАШ рендер мелодии/партитуры → Suno cover
                                         в стиле/инструменте запроса (§2.9); только при деньгах
             cache:<track_id>          — трек кэша по теме/стилю, не игранный за GEN_FRESH_HOURS, rating ≥ 0
             generate:<kind>:<model>   — ТОЛЬКО если хватает денег (баланс и оба лимита ≥ цены) и провайдер жив
             decline:<reason>          — честный отказ; всегда есть, когда нет ни одного «звучащего» кандидата
       ──► Chooser.choose(question) ──► Route(candidate) ──► исполнение ──► фраза кода по Route + результату
```

**Деньги проверяет код, а не вера в модель**: кандидатов `generate:*`, на которые нет денег или лимита, просто нет в списке — чойсер физически не может их выбрать. То же для режима `synth` (генерация выключена) и для мёртвого провайдера.

Признаки кандидатов (веса — данные `SOURCE_WEIGHTS` в `knowledge`, рядом с `CHOOSER_WEIGHTS`; правит Шифу):

| Признак | Смысл | Знак |
|---|---|---|
| `synth_fit` | «у нас норм играет»: годность стиля/материала синтеза (поле `Style.synth_fit`, §3.2) — **с В13 (14.10) только фильтр допуска синтез-кандидата (`SYNTH_FIT_MIN`), не очки**; в очках синтеза — `fallback` (запас, вес −2) | фильтр |
| `theme_match` | совпадение темы/жанра запроса с тегами кандидата | + |
| `asked_vocal`, `asked_generated`, `asked_fresh` | слоты запроса «спой», «сгенерируй», «новую» | + генерации / − кэшу при `fresh` |
| `fresh` | давность последнего исполнения (`music_history`, ADR-0146) | + |
| `rating` | «нравится / не нравится» по треку кэша | ± |
| `cost` | кредиты кандидата (у кэша и синтеза 0) | − |
| `wait_s` | ожидание до звука: синтез ≤ 3, кэш ≤ 3, генерация 25–60 | − |

Как это ложится на слова Шифу: **пьеса по названию** — основной путь **кавер** (`generate:cover`, §2.9, решение В7): из кэша, если такой кавер уже есть (мгновенно, бесплатно), иначе генерация кавера, а наш синтез этой же пьесы — мост на время ожидания, фолбэк при провале и единственный путь без денег. Наши сильные стили сетов (`club, rave, synthwave, chiptune, breaks, dnb`) получают `synth_fit` ≈ 1, бесплатны и мгновенны — выигрывают у генерации без модели (разрыв велик). Рок (`synth_fit` = 0 после вердикта «не рок, а какой-то калл») и жанры вне `STYLES` (гранж, металл, блюз, шансон, оркестр) синтез-кандидата не имеют → кэш по теме, если есть, иначе генерация, иначе честный отказ. «Спой …» — синтез-кандидатов нет (синтез не поёт). Неоднозначные случаи («что-нибудь повеселее про космос»: synthwave синтезом, свежая генерация или трек из кэша) — их и решает цепочка Jev → LLM → кубик.

> **Заменено решением В13 (13–14.10, §8):** сильные стили синтеза больше не выигрывают у генерации — синтез только запас, когда нет ни кэша по теме/стилю, ни генерации (деньги, лимит, провайдер).

> **Поправка #4079 (решение Шифу 27.10): путь пения — `live:*` рядом с генерацией.** «Спой …» больше не значит «только генерация»: у чойсера есть кандидат **`live:song`** (и `live:rap`) — робот поёт сам (диалог v2 `perform` под синт-подложку `request_music(intent=backing)`): сразу, бесплатно, не сохранится; против `generate:(robot_)song` — 1–3 мин, кредиты, ляжет в библиотеку. Решает код **до основной модели** (`source.choose_sing`, хост `engine/sing_route.py`): маркеры одной таблицы `knowledge.SING_ROUTE_MARKERS` (живьём: «под синт/бит/музыку», «спой сам», «прямо сейчас» и слова движка `MUSIC_ENGINES` — «вживую», «на синтезаторе», «на Ренардо»; генерация: «сгенерируй», «запиши», «нейросетью», «сделай песню», «чтобы сохранилась») сужают кандидатов до одного пути; голое «спой» — чойсер с контекстом (последние реплики, играет ли музыка, здоровье `music_gen`) и перевесом живому (`SOURCE_WEIGHTS.sing_live`; маркер пути в последних репликах — `recent_asked`, разрыв меньше `CHOOSER_CLEAR_GAP`, решает модель чойсера). Исполнение — форма хода диалога (`command.Form.sing`, `rob_box_dialog.knowledge.SING_FORMS`): `live` — `generate_music`/`request_music` вне среза, `perform` обязателен, вид из пути, подложка синт; `generate` — `generate_music` обязателен, песня выступлением — нарушение. Тул музыки, получивший просьбу спеть вживую (чат, v1 — без формы), отвечает путём `live:song` и фразой кода, не генерацией. Кэш-песня в вопросе живое/генерация не участвует: её по-прежнему выбирает путь тула `generate_music` (кандидаты `cache:*` при «спой»).

> **Поправка #4071 (вилка Шифу 27.10): 2×2 и никакого отказа «движок так не играет».** Слова Шифу: «на вилке только два пути: либо на Ренардо поём, либо синтезируем песню; и ещё либо играем без песни на Ренардо, или генерируем трек без песни»; «робот, когда просишь читать рэп, по сути поёт, синхронизируя речь под музыку — это и есть спеть под синт». Клетки: **синт + пение** — `live:song`/`live:rap` (perform под синт-подложку); **синт без пения** — `synth:<стиль>`; **генерация + пение** — `generate:(robot_)song`; **генерация без пения** — `generate:instrumental` (кэш сгенерированного раньше — часть этой клетки). Названный синт («на Ренардо», «на синтезаторе», «вживую», «под синт/бит») с пением — **всегда** живое пение кодом, даже рядом с «сгенерируй/сочини/запиши» («он должен на «Сгенерируй песню на Ренардо» сделать перформ»); без пения — синтез, жанр, который синт не играет («метал на Ренардо»), — ближайшим стилем `GEN_BRIDGE_STYLES` с фразой кода «Метал на синте играю ближайшим стилем — брейкбит.». Причина отказа «названный движок так не играет» удалена из кода; «синтез не поёт» (§2.2 выше) — неверно: синт поёт голосом робота. Отказ остаётся только когда генерации физически нет (ключ, деньги, сервис) — и фраза предлагает другую клетку: песню — «Могу спеть сам вживую под синт.», инструментал — стили своего синтеза. Пение узнаётся узко, словами целиком (глаголы пения `SING_VERBS`; «исполни/сгенерируй/сочини/запиши/сделай» — только с прямым дополнением-песней и без правки громкости/темпа; «без вокала» — инструментал; уточнено кругом 2 ниже), маркеры пути — по приоритету (синт назван → генерация → «спой сам/прямо сейчас»). Жанр, который синт не играет, при голом «спой» — перевес генерации (`SOURCE_WEIGHTS.synth_poor`), разрыв меньше `CHOOSER_CLEAR_GAP`: решает модель чойсера. Живое пение при играющей музыке («под этот бит зачитай рэп») — поверх неё (`SING_FORMS["live_over"]`: подложка `none`, без вопроса о смене).

> **Поправка #4071, круг 2 ревью: пение — глагол и его прямое дополнение.** Просьба спеть — глагол из одной таблицы `knowledge.SING_VERB_RULES` и его **прямое дополнение** (`SING_OBJECTS`: винительный, точные слова — «песню», «песенку», «рэп»; «музыку/музон/трек» — только с голосом: «своим голосом», «с вокалом», «со словами») рядом с глаголом через служебные слова (`SING_OBJECT_FILLERS`, прилагательное-определение), а не любое «песн…» в части фразы. Не пение и не генерация: «запиши название/слова песни», «придумай название для песни», «создай плейлист песен», «напиши текст песни» (дополнение не песня); «сделай свой голос помягче» («голос» не дополнение-песня; «своим голосом» — творительный, только фразой); «мне нравится твой голос в этой песне» (нет глагола); «прочитай статью про рэп», «включи рэп и прочитай новости» (дополнение чтения не рэп); «сделай эту песню на повтор», «запиши песню в избранное», «сделай песню на полную громкость» (звучащая песня `SING_EXISTING_WORDS` и правка/хранение `SING_CREATE_MODIFIERS`); «не пой больше» (отрицание); «я хочу спеть караоке», «расскажи, как спеть» (инфинитив — просьба только со словом просьбы «можешь/попробуй/прошу» и не о себе). «Пой» — глагол пения. Слово движка после «не/без» («сгенерируй песню не на синтезаторе», «а не пой вживую») и после «про/о» («песню про Ренардо») движок не называет — ни в пути пения, ни в пути тула (`ENGINE_NEGATIONS`, `ENGINE_TOPIC_LEADS`): код не делает обратное просьбе. Решения, которые этот круг фиксирует строкой: (1) названный синт играет и в режиме пути `generate` (`ctx.mode`): режим — запрет генерации/синтеза по умолчанию, а не отказ названному движку (прежний отказ «движок так не играет» удалён); (2) любое живое пение при играющей музыке — поверх неё (`live_over`), в том числе «спой на Ренардо» поверх трека кэша: вопроса «выключить и спеть?» нет — если он нужен для явного «на Ренардо» поверх чужого трека, это отдельная карточка; (3) голое «спой метал/блюз/шансон» — перевес генерации `synth_poor` с разрывом меньше `CHOOSER_CLEAR_GAP` (решает модель чойсера; без модели — генерация, при нуле кредитов — фраза тула с предложением спеть вживую).

**Провал генерации (Б3).** Генерация упала после выбора (`timeout`, `rejected`, `provider_down`) → чойсер спрашивается ещё раз **с тем же контекстом без `generate:*`** (баланс/кэш/синтез/отказ) — второго круга генерации нет. Фраза — от кода по паре «что просили → что выбрано»: «сгенерировать не вышло (<причина>) — ставлю из сочинённого раньше «<title>»» / «… — играю своё в стиле club» / «спеть сейчас не могу: <причина>». Тихой подмены нет: если играет не то, что просили, фраза об этом говорит всегда.

### 2.3 Песня голосом робота — текущий голос + пресет пения + Suno `add-instrumental`

Песня поётся **текущим голосом робота** — тем, что выбран `set_voice`/`set_tts_provider` (фактический провайдер — из `/voice/tts/provider_state`, голос — `VoiceStateStore.resolve`), а не только `Russian_ReliableMan` (Б8). Под каждый системный голос — **пресет пения** (данные в одном модуле — рядом с `PROVIDER_VOICES` в `rob_box_voice/tts_voice_registry.py`, где уже живёт каталог голосов):

```python
SING_PRESETS: Mapping[tuple[str, str], SingPreset]   # (provider, voice) → пресет
@dataclass(frozen=True)
class SingPreset:
    speed: float; volume: float; pitch: int     # параметры TTS при чтении текста песни
    emotion: str | None                         # MiniMax emotion; у Yandex — role, если голос поддерживает; у Silero — None
    vocal_gender: Literal["m", "f"]             # для Suno add-instrumental
    audio_weight: float                         # насколько Suno держится за вокал (0.8 одобрено на Reliable Man)
    tags_hint: str                              # подсказка тегам («deep male vocal», «bright female vocal»)
```

Первые значения строятся **кодом из метаданных голоса** (пол/характер из `voice_info_for`, возможности провайдера из `TTSCapabilities`) — без генераций. Доводка на слух — только для голосов, которыми робот реально говорит, по одной генерации на голос (12 кредитов) — по просьбе Шифу «сильно не трать». Проверенный эталон: `minimax / Russian_ReliableMan`, `emotion=angry`, `audio_weight=0.8` — одобрен 13.10.

Пайплайн:

```
слоты (тема, жанр, настроение) ──► LLM: {title, lyrics} строго по JSON-схеме (правила §3.4)
   ──► валидатор кода (длина ≤ 950 симв. ≈ 80 с, строки, язык ru)
   ──► TTS ТЕКУЩЕГО провайдера/голоса в файл с SingPreset ──► vocal.mp3
   ──► KIE file-stream-upload (живёт 24 ч) ──► add-instrumental V6: теги GEN_STYLES[жанр] + tags_hint,
       vocal_gender, audio_weight из пресета ──► 2 варианта ~75 с (~46 с)
   ──► кэш (оба варианта, с provider/voice) ──► дека (§2.4) ──► фраза успеха от кода
```

LLM пишет **только текст** (свой, не перевод чужого — правило скилла; проверить код не может, §9). Название, длительность, голос во фразе — из результата. Клон голоса Suno Voice (validation-phrase) не рассматривается (проверка владельца голоса; синтетикой не проходим). Если текущий провайдер — фолбек (Silero после смерти облаков), песня поётся им, и фраза это говорит («пою запасным голосом»). TTS упал → `GenUnavailable(provider_down)` → §2.2 «провал».

### 2.4 Сгенерированный звук — через деки `PlayerOwner`, а не мимо

Сегодня mp3 играет `sound_node` мимо движка (§1.1). Для сета и для «одного владельца состояния» (ADR-0149 §2.1) это недопустимо: нет блэнда, нет `started/nearly_finished/finished`, громкость своя, занятость устройства — молчаливый пропуск. Решение — **одна реализация воспроизведения музыки**: сгенерированный трек — второй вид артефакта деки.

```python
@dataclass(frozen=True)
class AudioTrack:              # рядом с Track (модель v2), в rob_box_music.model
    track_id: str; path: str; duration_s: float
    bpm_nominal: int | None    # из GEN_STYLES/запроса; бит-сетка не гарантирована
    loudness_lufs: float       # замер при сохранении в кэш (ffmpeg ebur128), выравнивание к цели мастер-шины
    source: Literal["generated"]
```

`render(AudioTrack, deck)` → программа деки, играющая буфер SuperCollider (mp3 → wav на частоте сервера при сохранении в кэш, один раз); события — по клоку, стоп/громкость/«что играет» — тем же путём. Стыки mp3 ↔ mp3 и синтез ↔ mp3 — **кроссфейд** (изначально 8 тактов по `bpm_nominal` с LPF/HPF; с В15 — 1.5 с, без фильтров) (ADR-0149 §3.12, ADR-0157 PR-5), **без** бит-матчинга. После переезда удаляются `/voice/sound/play_file` и `sound_node.play_file_*` (§7). Снять замером до PR-2: память буфера (180 с × 2 кан. × 48 кГц × 4 Б ≈ 69 МБ; моно 16 кГц ≈ 11.5 МБ — выход робота всё равно 16 кГц ReSpeaker), время загрузки на Pi, mp3 в libsndfile.

### 2.5 Кэш — переделанная `/data/music_library`, а не вторая библиотека

Генерация → **всегда** в кэш (оба варианта): KIE удаляет файлы через 14 дней. Библиотека та же (`generated_music_library.py` переезжает в `engine/gen/library.py`, одна схема в коде; `migrations/007` удаляется), новые поля:

| Поле | Зачем |
|---|---|
| `request_key` | `sha256(json{kind, work_id, instrument, style_key, theme_norm, lyrics_sha, provider_tts, voice, gen_provider, model, duration_bucket})` (`work_id`+`instrument`+`style_key` — для кавера: «валькирии на ситаре» ≠ «валькирии оркестром»); `theme_norm` — тема после выделения слотов, нижний регистр, леммы (как `theme_grounding`) |
| `pool_key` | `(kind, style_key, instrumental)` — «любой трек этого стиля» для сетов и мостов |
| `gen_provider`, `model`, `task_id`, `variant` (0/1), `credits` | учёт, повторяемость |
| `tts_provider`, `voice` | песня спета этим голосом |
| `work_id`, `instrument`, `source_audio_sha` | кавер: какая пьеса, каким инструментом, с какого нашего рендера |
| `bpm_nominal`, `loudness_lufs` | стыки и выравнивание (§2.4) |
| `last_played_at`, `play_count`, `rating` (−1/0/+1) | признаки `fresh` и `rating` чойсера |

Кэш — не отдельная ветка логики, а **кандидаты чойсера** (§2.2): совпал `request_key` и вариант свежий → кандидат `cache:` с `cost=0`, `wait_s≈0` выигрывает у генерации, если не сказано «новую» (`asked_fresh` штрафует кэш). Второй вариант задачи — «в запас»: в сете не соседом (§1.4), в следующий раз по тому же ключу играет он. История — общая с синтезом (`music_history`, `HistoryKey("gen_v1")`). Диск: ≈ 2.7 МБ/120 с, ≈ 4.2 МБ/180 с → 1 ГБ ≈ 240–380 треков; квота `GEN_LIBRARY_MAX_MB` (предложение 2048) с вытеснением «давно не играли, `rating ≤ 0`, есть второй вариант». Место на `/data` Pi — замерить в PR-1.

### 2.6 Деньги — счётчик кодом, лимиты — вход чойсера

Таблица `gen_ledger(task_id, ts, credits, kind, request_key)` в той же `index.db`; `creditsConsumed` пишется из ответа (не оценка). Лимиты — **дневной** `daily_credits` и **на сет** `set_credits` (константы `engine.gen.budget`, по умолчанию 120 и 120: 10 задач сета по Б5); баланс — `balance()` раз в час, после каждой задачи и при `402`. Всё это — часть `SourceContext`: исчерпано → кандидатов `generate:*` нет → чойсер выбирает кэш или синтез (Б6), фраза кода называет причину («на сегодня лимит генерации вышел — дальше своё»). Баланс и траты дня — в снимке `/voice/music/state.gen` («сколько осталось» — без LLM). На 13.10 баланс пополнен на $5 (≈ 1000 кредитов по цене брифа) — **до PR-1 генерации не тратим**.

### 2.7 Сет: кэш сначала, первый трек быстро, остальные качественно

Решения Шифу Б2/Б4/Б5:

- **План сета** — 10 треков. Сначала код набирает треки **из кэша** по `pool_key`/теме (свежие, `rating ≥ 0`, варианты одной задачи не соседями); **генерируются только недостающие** — не больше 10 задач на сет и в пределах `set_credits`.
- **Первый трек** (если кэш не закрыл) — **V6_MINI** (быстрее: 20–37 с на 120 с). **Остальные** — **V6** (качество), заказ N+1 на `started(N)`: трек 150 с, генерация ≤ 52 с → запас ≥ 100 с. Не готов к `nearly_finished(N)` → кроссфейд на второй вариант той же задачи (та же тональность/темп, §1.4) или мост (ниже).
- **Мост, пока ждём генерацию (Б4)**: есть в кэше по теме → играем его как мост; нет → мост синтезом ближайшим сильным стилем. Сверху — фраза-развлечение: факты («что сейчас играет», «через сколько будет новый», название) **строит код**, LLM только окрашивает одну фразу с дедлайном (как реплики диджея ADR-0149 §2.4: опоздала — звучит голая фраза кода). Пример: код → `{bridge: "synthwave · космос", eta_s: 40, next: "гранж про батарейку"}`, LLM → «Пока я дописываю гранж про батарейку — вот вам синтвейв про космос, секунд сорок».
- **Стрим до `success`** (~21 с у V6 против ~38 с полного mp3) — не доказан (§0); первая задача PR-8, ≤ 12 кредитов.
- **Цена**: 10 задач × 12 = 120 кредитов ≈ $0.60 на полностью новый сет (20 вариантов, 10 — в кэш); повторный сет на ту же тему — частично или полностью из кэша.

### 2.8 Режим источника — зачаток, по умолчанию `auto`; путь выбирает чойсер (решение Шифу 13.10)

Первая редакция предлагала включать генерацию «как TTS-провайдер»: тул `set_music_source`, топик `/voice/music/set_source`, файл состояния. **Отменено** (Шифу, 13.10: «нахрена параметры городить, чойсер должен сам выбирать»; уточнение: «оставь зачаток, по дефолту автомат, другие режимы пока не делаем»). Режим — зачаток: `SourceContext.mode` (`auto` по умолчанию; `synth`/`generate` и причина `mode_synth` в коде есть и покрыты тестом `test_source_path`, но **ничто их не включает**). Тула переключения, топика, файла состояния и поля `source` в снимке нет и пока не делаем. Путь выбирает чойсер §2.2 среди кандидатов кода; жёсткие фильтры кода — деньги (баланс, `daily_credits`, `set_credits`), готовность исполнителя, ключ, жив ли провайдер, голос и годность стиля.

Параметр ноды `mcp_server.music_chooser` (`deterministic`/`jev`/`chain`, #3606) — **не** второй переключатель режима, а выбор ступеней модели чойсера (Jev → LLM → код); остаётся как есть. Отладочная тень `MUSIC_CHOOSER_SHADOW` — тоже про модель, не про путь.

Лимиты `daily_credits`/`set_credits` — константы `engine.gen.budget` (600/180, см. В12), единственное место; остаток дня `source_route.day_left` считает из `gen_ledger`.

### 2.9 Кавер пьесы по названию — основной путь (решение В7)

Проба 13.10 (§1.3) принята Шифу на слух. Путь «сыграй <пьесу> [на <инструменте>] [в <стиле>]»:

```
MediaCommand(PLAY_NAMED, work, instrument, style) ──► кандидаты произведения (ADR-0157 §3.2: партитуры/RTTTL, годность)
   ──► кэш: есть кавер с тем же request_key (work_id + instrument + style)? ──► играть (≤ 3 с, 0 кредитов)
   ──► иначе, при деньгах: наш NRT-рендер мелодии (RTTTL-хук или партитура, 20–40 с, wav) ──► KIE upload (24 ч)
       ──► upload-and-cover-audio V6: style = COVER_STYLES[instrument|style] (EN-теги), audio_weight ≈ 0.65
       ──► 2 варианта (~89 с на 20.8 с исходника, ≈ 43 с) ──► кэш (оба) ──► дека
   ──► пока ждём: МОСТ — наш синтез этой же пьесы (тот же путь, что сегодня) + фраза кода «играю свою версию, через ~40 с будет живая»
   ──► без денег / провал: наш синтез — и фраза кода, что живой версии не будет (причина)
```

- **Инструмент → стиль кавера.** Слот инструмента уже выделяет грамматика (ADR-0157 §2.4, `knowledge.INSTRUMENTS`, с #3595 — и ситар). Для кавера пак не нужен: `COVER_STYLES` — данные в `knowledge` рядом с `INSTRUMENTS` (ключ инструмента → EN-теги Suno: `sitar` → «indian sitar, tabla, raga flavour», `balalaika` → «russian balalaika folk ensemble», …); стиль (`rock`, `orchestral`, `jazz`) — из `GEN_STYLES`. «Валькирии на ситаре» → кавер с ситаром; фразу «для балалайки нет пака» (ADR-0157 §2.4) кавер-кандидат делает ненужной, пока есть деньги, — без денег она остаётся.
- **Без инструмента и стиля** — стиль кавера по характеру пьесы из реестра (`works.py`: оркестровая классика → «orchestral»), иначе «orchestral» по умолчанию (как проба).
- **Исходник — наш**: мелодия из нашего каталога (RTTTL/партитура), поэтому узнаваемость держится (Шифу: «обыграл»). Длина исходника 20–40 с; Suno продлевает до ~90 с (проба: 20.8 → 89 с); полная длина пьесы — не цель.
- **Гейт кавера — «есть наш материал», а не «общественное достояние» (решение В14, 14.10).** Шифу: «если у нас есть материал то идем через ветку кавер»; «чойсер пусть решает кавер или нет в зависимости от пользовательского запроса… желательно чтоб это было узнаваемо, поэтому кавер в приоритете». Кандидат `generate:cover` строится, когда лид пьесы собрался из нашего материала (`CoverWork.material` — id мелодии RTTTL/партитуры, прошедшей поиск по названию и `score_song` с порогом узнаваемости `CLASSIC_REF_MATCH_MIN`), и есть деньги/лимит; лида нет — причина `no_material`, фраза молчит. Мелодия кавера — та же, что у моста, без подмены пьесы «записью общественного достояния» (`piece_cover.source`/`public_domain_pick` удалены). Флаг `public_domain` реестра и его таблицы (`PUBLIC_DOMAIN_WORK_TYPES`, `COMPOSERS_IN_COPYRIGHT`) удалены — потребителей не осталось; `LICENSE_STOP_LIST` остаётся: его потребитель — флаг `stop_listed` реестра и отчёт связей партитур (ADR-0155 В1), не путь музыки. Проба координатора 14.10: PDMX «STAR WARS» arr. S. Hermand → `score_song(references=RTTTL starwars_6/7/9)` (мотив с такта 15, совпадение 0.88) → кавер V6 orchestral, задача `f2f0a117519398cda475a16749342502`, 12 кр., 43 с; Шифу на слух: «супер».
- **Тематический сет (В14):** у темы есть материалы (`[dj_set] тема … материалы=[…]`) — код проверяет первые `SET_COVER_MATERIALS` партитур темы тем же `score_song` с RTTTL-эталонами темы (`piece_cover.theme_covers`; эталонов нет — узнаваемость не доказать, каверов нет). Годные — кандидат каждого трека `generate:cover` по материалу темы в стиле трека (`source.set_candidates`; `cover_style_key` по жанру трека, электронные стили без акустических негативов, `COVER_ELECTRONIC_STYLES`). Узнаваемость в приоритете: когда кавер возможен (кэш того же кавера или деньги), инструментал по тегам — новый и из кэша — не кандидат трека, остаётся синтез-запас. Произведения и их чередование — В16 ниже; мост первого трека — наш синтез. Исполнитель — тот же `CoverMaker.make` (`gen_session.SetCovers`, оба варианта, лимит сета). Без материала или без исполнителя кавера — как раньше (инструментал по тегам).
- **Разные произведения темы в треках сета (В16, 14.10).** Шифу: «такое ощущение что он одни и те же треки ставит» — сет `gen79125`: 7 треков, по сути главная тема ×7 (каверы «STAR WARS» и «Supreme Star Wars Medley» оба режутся с такта главного мотива — эталоны темы брались все сразу, лучший — главная тема), 4 из 7 — те же файлы кэша, что час назад. Теперь: хуки поиска по словам темы (`ThemeProfile.found`; нет — хуки строки таблицы) группируются в произведения **по мелодии** (`hook.tune_groups`/`same_tune`: начало одной RTTTL во всей другой ≥ `PIECE_SAME_TUNE_MIN` = 0.8; замер на роботе — версии главной темы и Имперского марша между собой 1.00, разные пьесы 0.29–0.58; по названию «Start 1» и «Star Wars (Theme)» не склеить), первым — произведение с ранним хуком строки таблицы (главная тема), не больше `SET_COVER_PIECES` = 4 (`piece_cover.theme_pieces`). У каждого — свой эталон: мелодия кавера — партитура из первых `SET_COVER_MATERIALS` темы, где `score_song` нашёл мотив ЭТОГО эталона, иначе сама RTTTL (`classic.pick_record`, путь пробы Валькирий); лог `[cover] тема … произведения «…» ← pdmx:… 0.88 [хуки]; «…» ← rtttl:…`. Трек сета берёт произведение, реже всех сыгранное в сете (ничья — порядок темы), не соседа (`SetLedger.work_for`); ключ слота — `cover|<стиль>|<пьеса>` (`source.cover_slot`), поэтому второй вариант задачи закрывает трек того же произведения на другом месте сета (A B C A B C A при трёх). Кэш, игранный ближе `GEN_FRESH_HOURS`, при возможном новом заказе — не кандидат трека сета (`source._not_replayed`): признак `fresh` весом 0.5 не перебивал `theme_match` 1.5 у кэша кавера, поэтому кэш шёл первым всегда; без денег сыгранное остаётся (лучше синтеза).

### 3.3 Тулы

- `generate_music(kind: enum[instrumental, song, robot_song], style: enum[GEN_STYLES ∪ STYLES], theme: str ≤ 60, fresh: bool)` — узкий, `llm_visible=True`, асинхронный (`job_id` сразу, звук — по событию `started`). Это **просьба**, а не приказ: она становится слотом `asked_generated` и проходит тот же чойсер (денег нет — кандидатов генерации нет). Текст песни и теги Suno от LLM не принимаются: текст — отдельный структурный вызов в `song.py`, теги — из таблицы.
- Тула переключения режима нет (§2.8).
- Списки «музыкальных тулов» (§1.1, 4 места) → одна константа в `rob_box_core.tool_catalog` (флаг `starts_music` уже есть у `MCPTool`).

### 3.4 Правила текста песни (скилл `song.txt`, коротко)

Свой текст на русском; 2 куплета + припев ×2, 8–12 слогов в строке; тема из слота; от первого лица робота; без цитат и перевода чужих песен; ≤ 950 символов; ответ — JSON `{title ≤ 40, lyrics}`. Невалидное — один повтор; второй отказ → фраза «текст не сложился» (ADR-0148: без синтетических ретраев сверх одного).

### 3.5 Ошибки KIE → причины

| KIE `code` | Причина | Повтор | Провайдер |
|---|---|---|---|
| 401 | `no_key` | нет | мёртв до смены ключа |
| 402 | `no_credits` | нет | баланс := 0 до `balance()` |
| 429 | `rate_limited` | 1 раз через 10 с | — |
| 455, 500, 5xx, сеть | `provider_down` | нет | `dead_until` = +10 мин |
| 400, 422, `state=fail` | `rejected` (`failMsg` — в лог) | нет | — |
| нет `complete` за 180 с | `timeout` | нет (доиграет — результат в кэш, кредиты учтены) | — |

### 3.6 Кавер — см. §2.9

Решение В7 (13.10) — кавер стал основным путём пьесы по названию, детали — §2.9. Проба: «Ride Of The Valkyries», 20.8 с → 2 × 89 с, ≈ 43 с, 12 кредитов.
