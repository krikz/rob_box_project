## 1. Проблема

Аранжировщик v2 умеет один стиль — клубный house/techno 128–138: окно темпа `GENRE_WINDOWS` (`knowledge.py:92-94`), бочка `four_on_floor` (`:71-77`, `LOOKS :401-405`), бас в оффбит (`arrange/bass.py:24-30`), пэд 16-ми под сайдчейн (`arrange/compose.py:113-121`), трезвучия (`arrange/harmony.py:28-31`), восемь прогрессий (`:15-18`), форма build/drop (`compose.py:56-69`), нормы микса (`ROLE_LEVEL_DB :365-380`, `DUCK_ROLES :387`), приёмка A9 «низ 0.5–0.8» — всё это **клубные константы, зашитые как единственные**. Песенная форма (`arrange/song.py`, `engine/classic.py`) — второй путь («поставь Калинку»), с аккомпанементом из старого `harmonize`, без понятия стиля.

ADR-0152 расширяет палитру **внутри** клубного стиля (пэды, бочки, формы, окна `deep`/`breaks`). Джаз, рок, рэйв — другой уровень: меняются не значения в пулах, а **правила** генераторов (свинг-сетка, walking-бас, септаккорды, пауэр-аккорды, отсутствие сайдчейна). Если делать это `if genre == "jazz"` в каждом генераторе — через три стиля получим `club_arranger` v1 заново (ADR-0149 §1: 3295 строк пайплайна).

## 2. Решение: стиль — запись в одной таблице знания, генераторы — функции от стиля

### 2.1 Что такое `Style`

`knowledge.STYLES: Mapping[str, Style]` — frozen dataclass, **все** стилевые константы v2 переезжают в него из модуля (клуб становится первой записью `club`, побайтно равной сегодняшним таблицам — тест). Поля сгруппированы по тому, какой генератор их читает:

| Группа | Поля `Style` | Кто читает сегодня (клубные константы) |
|---|---|---|
| Время | `bpm: (lo, hi)`; `meter: (beats, steps)` — сегодня только `(4, 16)` (`model.py:18-19`); `swing: (lo, hi)` доля восьмой (`GenreWindow.swing :87-88`); `swing_steps` — какие шаги качает (клуб: гоуст-16-е `rhythm.py:20`; джаз: все оффбит-восьмые 2/6/10/14 на ≈ 1/3 восьмой — триоль через `offset_ms`) | `set_plan.seeded_plan :88-92`, `rhythm.swing_offset_ms :46-48` |
| Ритм-секция | `drum_kit: str` — пак/набор символов и сэмплов (`club` → `X:12` + `- * o` дефолтного пака; `jazz` → щётки/райд; `rock` → рок-кит; `rave` → жёсткая бочка; `dnb` → амен-брейк нарезкой); `kick_patterns`, `looks` (энергия → рисунок + глубина насоса), `kits` (каркасы хэтов/перкуссии), `backbeat` (клэп 2/4, малый 2/4, райд…) | `KICK_PATTERNS :71-77`, `LOOKS :401-405`, `DRUM_KITS :219-225`, `rhythm.BACKBEAT_STEPS :18` |
| Роли и тембры | `roles: tuple[Role]` (у джаза нет `pad` 16-ми, есть `comp`; у рока `guitar` вместо `pad`) — **имена ролей остаются из `ROLES :37`**, новые роли добавляются в `ROLES` и в слоты дек (`DECK_SLOTS :202-205`: 9 слотов, 8 заняты — у новой роли должен быть слот или она делит слот с несовместимой в стиле, валидатор); `timbres: {семья → {роль → синты}}` (ADR-0152 §3.2–3.3), `registers` (у джазового контрабаса `(28, 50)` ниже клубного `(36, 52)` — коридор на стиль, валидатор `model.py:287-293` читает из стиля) | `TIMBRES :452-457`, `REGISTERS :42` |
| Фигуры | `bass_figures`, `pad_figures`, `lead_figures` — ключи генераторов (§2.2): `offbeat`/`rolling8`/`walking`/`riff`; `pumped16`/`held`/`stabs`/`comping`/`power_chords`; `hook`/`solo`/`call_response` | `compose._bass/_pad/_lead :113-141` |
| Гармония | `chord_size` (3 — трезвучия; 4 — септаккорды; 2 — пауэр `(0, 7)`), `progressions` (ступени), `modes` (лады), `cadence` (напряжение перед дропом/припевом: V/sus4 у клуба, ii–V–I у джаза, bVII–I у рока), `voice_leading: bool` | `harmony.PROGRESSIONS :15-18`, `triad_pcs :28-31`, `pad_chords :53-70`, `GenreWindow.scales` |
| Форма | `forms: {шаблон → секции}` с именами секций стиля (`head/solo/head`, `verse/chorus/bridge`, `build/drop`), `energy_templates`, развитие хука по секциям (`DEVELOPMENT :238` — таблица стиля), сэмплы по секциям (`samples.SECTIONS :38-40`) | `compose.SECTIONS :56-69`, `hook.DEVELOPMENT`, `SECTION_TRIM_DB :442-445`, `SECTION_LPF :415-417` |
| Микс | `role_level_db`, `duck_roles` (пусто у джаза/рока), `sidechain_shape`, `lpf_roles/section_lpf`, `stereo` (`ROLE_STEREO :504-512`), `a9_low: (lo, hi)` — норма низа **стиля** (клуб 0.5–0.8; джаз ≈ 0.3–0.5 — гипотеза до эталона; rave 0.6–0.85), `crest: (lo, hi)` | `ROLE_LEVEL_DB`, `DUCK_ROLES`, `SIDECHAIN_SHAPE :385`, приёмка A9/A10 |
| Приёмка | `reference: str | None` — путь к эталонной записи стиля (§5) | `ref_dj_16k.wav` только у клуба |

Правило ADR-0149 §2.1 «одна таблица знания» сохраняется: `STYLES` живёт в `knowledge` (при росте — пакет `knowledge/` с модулем на стиль и `__init__` как единственным импортом; ADR-0145: таблицы, не классы). Клубные имена `GENRE_WINDOWS`/`GENRE_KICKS`/`TIMBRES`/… остаются как **вид** `STYLES["club"].…` до переноса всех читателей, потом удаляются (память проекта: не держать две реализации).

### 2.2 Как аранжировщик берёт стиль

`compose(plan, no, …)` (`compose.py:224-268`) получает `style = kn.STYLES[plan.style]` и передаёт его **параметром** в генераторы; генератор — функция `(style, key, chords, …) -> Part`, выбираемая по ключу фигуры из таблицы, а не `if`:

```python
BASS_GENERATORS = {"offbeat": bass.offbeat_bass, "rolling8": bass.rolling8, "walking": bass.walking, "riff": bass.riff}
part = BASS_GENERATORS[plan.track(no).timbre.bass_figure](style, key, chords, history_rng)
```

| Генератор | Новый / есть | Что делает | Стили |
|---|---|---|---|
| `bass.offbeat_bass` | есть (`bass.py:24-30`) | ноты на «и» каждой доли | club, rave, synthwave |
| `bass.rolling8` | новый (ADR-0152 §3.3, S) | тоника на восьмые | club/deep, synthwave |
| `bass.walking` | **новый (M)** | четверти: аккордовые тоны + хроматический подход на 4-й доле; подход — целая доля, поэтому `APPROACH_MAX_BEATS` (`model.py:23`) становится полем стиля (`approach_max_beats: 1.0` у джаза) | jazz, blues/swing |
| `bass.riff` | **новый (M)** | рифф 1–2 такта из тоники/квинты/b7 с ритмом из таблицы, повтор по форме с вариацией в бридже; транспонируется по аккорду (пауэр-аккорды) | rock, rave («рифф» на `rave`/`hoover`), dnb (сабовый) |
| `harmony.pad_chords` | есть (`harmony.py:53-70`) | голосоведение по обращениям | все — с `chord_size` из стиля (`voicings :34-46` работают с любым числом pitch class) |
| `harmony.chord_pcs(style, key, degree)` | расширение `triad_pcs` (`:28-31`) | трезвучие / септаккорд (терции лада ×3) / пауэр (0, 7) | — |
| `harmony.fit_progression` | есть (`:73-90`) | прогрессия под хук со штрафом | все — пул из стиля; `cadence` подменяет последний аккорд пред-дропа/перед припевом |
| `compose._pad` → `pad.pumped16/held/stabs` | есть + ADR-0152 §3.2 | аккорд на сетке | club, rave (stabs на `hoover`/`rave`), synthwave (held) |
| `pad.comping` | **новый (M)** | синкопированные аккорды 2–3 на такт по таблице ритмов «Charleston»-типа, септаккорды, `rhpiano`/`epiano`; не играет, когда звучит хук/соло в сильной доле (комплементарность как у лида ADR-0149 §3.4) | jazz, lo-fi |
| `pad.power_chords` | **новый (S)** | `(0, 7, 12)` на восьмые/четверти в регистре `(40, 64)` на перегруз-синте, палм-мьют = короткий `sus` | rock |
| `hook.from_rtttl` + `develop` | есть (`hook.py:156-196, 238-247`) | хук темы и развитие по секциям | все — таблица `DEVELOPMENT` у стиля: у джаза `head` = мотив целиком, `solo` = нет хука; у рока `chorus` = хук, `verse` = первые 2 такта |
| `lead.motif` | есть (`lead.py`) | вопрос/ответ из 4 нот | club, synthwave, chiptune |
| `lead.solo` | **новый (L)** | импровизация над сменами: по аккорду пул тонов (аккордовые + проходящие лада), ритм из таблицы фраз 2 такта + пауза, контур с ограничением скачка; детерминирован сидом | jazz, rock (гитарное соло в бридже) |
| `rhythm.hats_grid/kick_grid/clap_*` | есть (`rhythm.py:39-87`) | сетки по рисункам | все — рисунки и символы из `drum_kit` стиля |
| `rhythm.swing` | есть частично (`swing_offset_ms :46-48`, `pattern_grid :55-61` качает только `g` на нечётных) | свинг как `offset_ms` | джаз: `swing_steps` стиля = оффбит-восьмые, величина до 1/3 восьмой (≈ 83 мс при 120 BPM); рендер уже пишет `delay=[...]` (`render/renardo.py:195-197`) |
| `samples.loop_part` (`chop`) | есть (`samples.py:88-92`, `render :214-221`) | луп нарезкой на восьмые с перезапуском на доле | dnb/breaks: **амен-брейк** нарезкой — тот же механизм (`array_perc_break` уже роль `loop`); новое — перестановка кусков по сиду (`breakbeat_chop`, S) |
| `song.song_track` | есть (`arrange/song.py`) | куплеты по мелодии целиком | не-DJ «поставь джаз/рок» → песенная форма стиля (§4.3) |

Что **не** меняется: `Track`/`Part`/`Grid` (`model.py`), одна функция `render` (`render/renardo.py:356-376`) — стиль не знает о Renardo, он данные модели. Валидатор получает стиль как контекст (регистры, подход, роли секций, бюджет нагрузки).

### 2.3 Стиль и оси разнообразия ADR-0152

Стиль **задаёт пулы**, разнообразие **выбирает внутри** них (`weighted_pick` + история): `Style.timbres/forms/kick_patterns/progressions/*_figures` — это те же `TIMBRES`/`FORMS`/`GENRE_KICKS`/`PROGRESSIONS`/`PAD_FIGURES` ADR-0152, только по ключу стиля. `TrackPlan.timbre/template/kick` (ADR-0152 §2.2) не меняются; `SetPlan.genre` → `SetPlan.style`. `music_history` получает колонку `style` — она уже есть (`diversity.py:60`, пишется `"club_v2"` `:276`) — пишется ключ стиля; штраф между сетами по стилю — ось A16b.

Сквозные дыры платформы:

1. **Ударные не-электронных стилей** — единственное, чего нет вообще: DJ_Dave — электроника; дефолтный пак Renardo не инвентаризирован в `knowledge`. Нужен ресурсный пак (ADR-0125/0126, как `dj-dave-samples`): рок-кит, джазовые щётки/райд/томы, 3–4 амен-брейка, 2–3 хардкор-бочки. Источник и лицензия — решение Шифу (В3): свободные паки (CC0) или запись/покупка. Замер `peak_db/mean_db` каждого файла — как у DJ_Dave (`SampleInfo :240-256`).
2. **Перегруз на 16 кГц** — свой SynthDef с фильтром до нелинейности (пересборка образа); замер по ADR-0152 §3.1.
3. **Размер не 4/4** (вальс, 6/8) — `BEATS_PER_BAR`/`STEPS_PER_BAR` константы модели (`model.py:18-19`) и свёртки рендера (`_fold :272-286`, период — степень двойки `:166-183`); отложено, отдельное решение после первых стилей.
4. **Слоты дек** — 9 на деку (`DECK_SLOTS :202-205`), 8 заняты; роли `guitar`/`comp`/`ride` делят слоты с ролями, которых в стиле нет (`pad`↔`comp`, `clap`↔`snare` как символ `o` того же `play`-слота) — проверка валидатора «две роли в одном слоте» (`render :351-352`) остаётся.
5. **CPU** — джаз/рок/lo-fi дешевле клуба по событиям (нет аккордов на каждой 16-й × 2 голоса); dnb дороже темпом; `LOAD_BUDGET` ADR-0152 §3.6 — на стиль.

## 4. Выбор стиля (ADR-0148: код решает, LLM — из перечня)

### 4.1 Из фразы — грамматика роутера

`media_command_grammar.py` уже знает жанровые слова (`рок`, `джаз`, `блюз`, `техно`, `хаус`, `транс`, `лоуфай`, `драм`/`бейс`, `фонк`… — список `:495-508`, сейчас как «слова, которые не название»). Добавляется таблица `knowledge.STYLE_WORDS: {основа → ключ стиля}` (одна таблица, роутер импортирует) и поле `style` у `MediaIntent.DJ`/`REQUEST_MUSIC` (`:42-44`): «сыграй джаз» → `request_music(style=jazz)`; «рок-сет», «рейв на тему X» → `dj_set(start, style=rock|rave, theme=X)`. Параметр `genre` тулов (`tools_v2.py:269-270`: `auto|club|classical|folk`) заменяется перечислением ключей `STYLES` + `auto` (схема тулов генерируется из `knowledge`, ADR-0149 §5.1). `classical`/`folk` остаются ключами стилей песенной формы (их сегодняшний путь `engine/classic.py`).

### 4.2 Из темы — код; уточнение — LLM из перечня

`ThemeProfile.genre` (`theme.py:31`) → `style`: строка `THEMES` (`:115-133`) получает `style` (cyber → rave/synthwave, kids → chiptune/club, slavic → club, …); тема без строки — `auto` = клуб. Ризонер: `genre` в схеме (ADR-0152 §5) → `style: enum(STYLES)`, валидатор как там: применяется к ещё не отрендеренным трекам, темп сета не меняет (I7); если окно стиля не содержит текущий `bpm` — `PlanInvalid("style")`. LLM **не** называет синты, рисунки, формы — только ключ стиля и семью тембров.

### 4.3 DJ-сет и не-DJ

- **DJ-сет: один стиль на сет** (темп один, I7; блэнд требует общий `phrase_bars/bass_swap_bar` и «одна бочка, один бас» — `model.blend_bars :421-442`; джаз и клуб в одном блэнде не сведёт и живой диджей — темп и свинг разные). Смена стиля = «давай тему X» (#3412): новый сет с outro текущего. Переходы между **близкими** стилями одного окна темпа (club ↔ rave 138–140, breaks ↔ dnb half-time) — через `Style.blend_with: tuple[str]` и общий `phrase_bars`; первая версия — только внутри стиля.
- **Не-DJ** («поставь джаз», «сыграй рок про котов»): песенная форма стиля — `song_track` (`arrange/song.py`) с хуком-мелодией из RTTTL по теме и аккомпанементом **из генераторов стиля** (`walking`/`comping`/`riff`), а не из `harmonize`. Это второй шаг: сегодня песня = `harmonize` (ADR-0149 §8.1: 10+ вшитых фиксов), первый шаг — `song` со стилевыми тембрами и ритм-секцией при прежнем `harmonize`-аккомпанементе.

## 9. Что не проверено

- Звучание синтов прелоада в ролях стилей (`fuzz`/`dirt` как перегруз, `rhpiano` как rhodes, `bass` как контрабас) — гипотезы по именам.
- Инвентарь дефолтного пака Renardo (щётки, райд, томы) — не снят; PR-S0.
- Числа `a9_low`/crest по стилям — гипотезы до эталонов.
- Свинг через `offset_ms`/`delay=` до 83 мс на оффбит-восьмых — рендер пишет `delay` (`render/renardo.py:195-197`), но на роботе величины > 10 % восьмой не проверялись.
- Лицензии сэмпл-паков.
