# music_bench — офлайн-стенд замера микса

Issue #2977, план P3 из `docs/analysis/2026-08-30-music-quality-audit.md`.
Отвечает на вопрос из #2963 «микс перегружен» числом, а не «на слух»
(AGENTS.md/ADR-0018: честный результат требует чисел).

## Что это и чего это НЕ заменяет

- Это **Python-модель**, а не рендер в реальном `scsynth`. На рабочей
  машине воркера SuperCollider не устанавливается (Windows), а робота и
  katana трогать нельзя (AGENTS.md) — поэтому вместо офлайн NRT-рендера
  выбрана чистая Python-модель мастер-цепочки поверх реально
  отрендеренных нот. Обоснование выбора — docstring `tools/music_bench/
  __init__.py`.
- Мастер-цепочка (`tools/music_bench/master_chain.py`) численно повторяет
  `docker/vision/voice_assistant/custom_synthdefs/masterfilter.scd`: HPF
  35 Гц → LPF `min(7000, nyquist*0.55)` → `tanh(sig*drive)` → `gain`.
  Фильтры — 2-полюсный Баттерворт (`scipy.signal.butter`), не байт-в-байт
  тот же UGen, что в SuperCollider — для целевых метрик (клиппинг/пик/
  крест-фактор/центроид) разница не меняет вывод (см. docstring файла).
- Тембры слоёв — РОЛЕВЫЕ архетипы (`tools/music_bench/note_extract.py::
  ROLE_WAVEFORM`): бас — синус, пэд — сумма мягких гармоник, лид/
  контрголос — наивная (без oversampling) пила/треугольник на 16 kHz.
  Наивная пила — намеренный выбор: она алиасит так же, как реальные
  `saw`/`varsaw`/`supersawlead` (RC5 аудита), не притворяясь конкретным
  SynthDef конкретного трека.
- Ноты берутся из `core.arranger.CompositionSpec` — того же объекта,
  что уходит в `arranger.render()` для настоящего Renardo-кода — а не
  парсингом сгенерированного текста. `Pvar`-трансформации мотива лида
  (транспозиция/инверсия/ретроград) не симулируются — используется
  исходный паттерн темы, циклически повторённый; громкость и плотность
  по секциям — да, через те же функции огибающей, что и в
  `arranger._amp_envelope`/`_dur_var`. Подробности и обоснование —
  docstring `tools/music_bench/note_extract.py`.
- Стенд покрывает только путь «известная тема» (`core.harmonize.
  Harmonization`, RTTTL-архив) — бас/пэд/лид/контрголос там уже
  абсолютный MIDI, конвертировать ступени лада не нужно. Путь «сочинено
  с нуля» (`Layer.degrees`) в эту версию не включён — выборка архива
  ровно про темы из RTTTL-библиотеки, это и есть то, что просит план P3.

## Как запустить

```bash
python -m tools.music_bench.run_bench --count 50 --out report.csv --out-json report.json
```

- `--count N` — сколько тем архива (10460 записей,
  `src/rob_box_mcp_tools/rob_box_mcp_tools/data/rtttl_melodies.jsonl.gz`),
  каждая прогоняется через 3 комбо (`tools/music_bench/sampler.py::COMBOS`):
  `default`, `counter_on` (форсированный второй голос), `max_stack`
  (второй голос + удвоение лида октавой — худший случай состава слоёв).
  Итого `N * 3` рендеров.
- `--seed N` — воспроизводимость выборки (тот же seed = та же выборка тем).
- Первый запуск мигрирует архив в одноразовый SQLite-файл во временном
  каталоге (не в боевой `/data/voice_memory.db` — см. память
  `robot-data-is-shared-with-live-people`).
- Зависимости: `numpy`, `scipy` (обе уже используются в репо/CI).

## Как читать метрики

| Колонка | Смысл | Как читать |
|---|---|---|
| `pre_tanh_peak` | максимум `\|sum(слоёв)\|` ДО `tanh` | > 1.0 значит хоть раз сумма ушла в насыщение (RC1/#2963) |
| `pct_time_over_1` | доля времени с `\|сумма\| > 1` до `tanh` | прямой ответ на вопрос #2963 — 0% = чисто, любое значение > 0 значит трек звучит с искажением часть времени |
| `true_peak` | пик ПОСЛЕ мастер-цепочки, приближённо (4x линейный оверсэмплинг, НЕ полный ITU-R BS.1770) | сравнение между конфигурациями, не эталонная абсолютная цифра |
| `crest_factor_db` | 20·log10(peak/RMS) финального сигнала | ниже — площе/более сжато (насыщение `tanh` само по себе снижает crest); слишком низкий crest на фоне высокого `pct_time_over_1` — звук уже не «громкий», а «плоский» |
| `max_simultaneous_layers` | максимум одновременно звучащих ролей по секциям формы | считается по фактическим событиям (с учётом пауз паттерна), не по номинальному составу |
| `centroid_<role>_hz` | спектральный центроид буфера роли (до суммирования) | ожидаемо: bass ниже pad/lead ниже hats; резкий сдвиг вверх у бас/пэд — признак, что роль звучит не в своём регистре |

Пороги-гейты этим PR **не вводятся** (ADR-0013: сначала данные, инкремент
минимальный) — числа собираются для решения, что делать дальше (P1/P2 из
плана аудита), не для автоматического провала CI.

## Ограничения (честно, без "вроде работает")

- Не проверено на реальном роботе/scsynth — числа этого стенда НЕ
  заменяют живой прогон, только дают воспроизводимую оценку тенденции.
- Наивная синтезация — не тот же тембр, что настоящие `wobblebass`/
  `wideblip`/`imperialbrass` и т.д.; абсолютные значения `true_peak`/
  `crest_factor_db` не сопоставимы с живой записью один в один.
- `true_peak` — приближение, не сертифицированный алгоритм.
- HPF/LPF — Баттерворт 2-го порядка, не байт-в-байт тот же фильтр
  SuperCollider.
- Только путь «известная тема» (RTTTL); «сочинено с нуля» не покрыт.
- Свист из `investigation-music-and-whistle-2026-08-18.md` §1.2
  (открытый вопрос аудита про `sound_node`/loopback) стендом не
  затрагивается — он про отдельный источник сигнала, не про
  `compose_music`.
