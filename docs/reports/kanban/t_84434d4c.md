## Замечания

### Что НЕ сделано (намеренно)

1. **AGENTS.md не правил.** Файл protected (требует override от Шифу через single-query mode). Контракт зафиксирован в ADR-0077 и README — воркеры увидят при чтении ADR-ссылок или через ретро/обзор.
2. **hermes CLI не патчил.** Cross-profile запрет + architectural scope. Контракт воркера, не ядра (ADR §3.5).
3. **Не блокирую `kanban_complete`.** Over-engineering (5-мин мелочи легитимны). PR-комментарий воркеру достаточно (ADR §3.3).
4. **Не добавил cron-job.** Helper — это worker-invoked tool, не no-agent job. Опционально — отдельная карточка по желанию Шифу.

### Caveats / что осталось для следующих карточек

- **AGENTS.md override** — если Шифу одобрит контракт, отдельной карточкой добавлю секцию «Контракт отчёта воркера» в AGENTS.md (3 строки, ADR §6).
- **Догфудинг всех старых t_* карточек** — задним числом отчёты не нужны (постфактум); новый контракт работает с момента merge.
- **`hermes kanban show` без подключённого board** — в worktree без `~/.hermes/kanban.db` возвращает пусто. Это **нормально** для helper'а: title/assignee становятся пустыми, воркер дополняет руками (как здесь).
- **`gh pr list` без GH_CONFIG_DIR** — скрипт использует `HERMES_HOME/gh` для credential; на dev-машине работает, на CI worktree без credentials — best-effort, секция `n/a`.

### Lessons learned (для будущих воркеров)

1. **shellcheck SC2016 — backticks в single quotes.** У нас markdown с inline backticks (`Branch`), printf интерпретирует ошибочно. Workaround: `printf '%s\n' "...с backticks..."`. Не блокер (CI lint pass).
2. **`origin/develop` может не существовать в fresh-init worktree.** Сначала проверяем `git rev-parse --verify origin/develop` — иначе diff/log падает с exit 128.
3. **`printf '- %s\n'` без `--` падает** если следующий arg начинается с `-`. Всегда `printf -- '- %s\n' "$x"` для safety.
4. **heredoc + `$(...)` конфликтует** в однострочнике. Лучше вынести python-скрипт в файл или отдельный шаг.
