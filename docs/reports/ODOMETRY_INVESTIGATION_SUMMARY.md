## 📊 Что было исследовано

### Анализ кода

1. ✅ Конвертация ERPM → механические RPM через `pole_pairs`
2. ✅ hw_velocities_ в рад/с (правильно для diff_drive_controller)
3. ✅ cmd_velocities_ конвертируется в м/с (правильно для sendSpeed)

### Ключевое открытие

`diff_drive_controller` принимает параметр `wheel_radius` в конфигурации:

```yaml
diff_drive_controller:
  wheel_radius: 0.115  # ← Для конвертации рад/с → м/с
```

**Вывод**: Контроллер сам делает конвертацию! Hardware interface должна отдавать рад/с.

## 🎯 Настоящие проблемы

### 1. Калибровка параметров

Могут быть неточными:
- `wheel_radius: 0.115 м` - нужно измерить под нагрузкой
- `poles: 30` - проверить в datasheet
- `wheel_separation: 0.380 м` - измерить точно

### 2. Duty cycle control

Проблемы:
- Нет обратной связи по скорости
- `max_linear_speed = 1.0 м/с` захардкожено
- Зависит от батареи/нагрузки/поверхности
- Проскальзывание колёс

## 🔧 Рекомендации

### Шаг 1: Калибровка (обязательно)

1. Измерить wheel_radius линейкой
2. Проверить poles в документации
3. Обновить конфигурацию
4. Протестировать: проехать 1м, сверить

### Шаг 2: RPM control (опционально)

Если ошибка > 10% после калибровки:
- Переход на RPM control
- Точная скорость независимо от батареи
- Лучшая одометрия
