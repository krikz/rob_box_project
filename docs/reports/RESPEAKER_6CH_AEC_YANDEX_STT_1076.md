# 🔇 Issue 1076 — ReSpeaker 6-канальный RAW + AEC-референс + Yandex STT (yandex:empty)

**Date:** 2026-08-09
**Status:** ✅ Реализовано (mixer fix п.1) + e2e-прогон (после PR)
**Affected:** `audio_node` (src/rob_box_voice), `stt_node` (телеметрия)
**Related:** issue #1076, kanban t_89eaf282

---

## TL;DR

- `yandex:empty` в проде — **не** конфиг STT и не механика стрима, а **грязный
  аудио-сигнал на входе**: `audio_node` усреднял ВСЕ 6 каналов ReSpeaker,
  включая **Ch5-6 = playback-референс** (AEC-референс — то, что играет робот).
- Когда робот говорит (TTS) или играет музыку — его собственный голос/музыка
  **смешивались в STT-сигнал** → Yandex возвращал `empty`, vosk галлюцинировал
  («рыбок» вместо «робот», «герметика» вместо «енутика»).
- **Решение (п.1 — минимальный фикс):** перейти на 6-канальный RAW-режим и
  усреднять ТОЛЬКО микрофонные каналы `Ch1-4` (`mix_channels: [0,1,2,3]`),
  исключив playback-референс `Ch5-6` из моно-микса.

## Почему 16 kHz — потолок (аппаратный лимит)

| Проверка | Результат |
|---|---|
| `arecord -D hw:1,0 -r 16000` | ✅ ok |
| `arecord -D hw:1,0 -r 32000` | ⚠️ открывается на 16000 (hw_params: 16000) |
| `arecord -D hw:1,0 -r 44100` | ⚠️ 16000 |
| `arecord -D hw:1,0 -r 48000` | ⚠️ 16000 |
| `/proc/asound/card1/stream0` | `Rates: 16000, 16000, 16000` |

**Вывод:** 44.1/48 kHz нативно недоступны (UAC1.0 full-speed + прошивка).
`plughw` делает только интерполяцию — качества не добавляет. **16 kHz — жёсткий
потолок ReSpeaker**, Yandex STT v3 и vosk работают на 16 kHz штатно.

## Каналы и AEC-референс (эксперимент: тон 440 Гц через ReSpeaker playback)

| Канал | RMS | dB | Что это |
|---|---|---|---|
| Ch1 | 288 | 49 | Микрофон 1 (тон через воздух, слабо) |
| Ch2 | 4514 | 73 | Микрофон 2 |
| Ch3 | 10622 | 80 | Микрофон 3 |
| Ch4 | 9969 | 80 | Микрофон 4 |
| **Ch5** | **11550** | **81** | **Playback reference — прямой эхо-референс** |
| **Ch6** | **11550** | **81** | **Playback reference (клон)** |

**Вывод:** в 6-канальном RAW-режиме аппаратный AEC к данным **НЕ применяется** —
отдаются сырые микрофоны + playback-референс. Референс ДОСТУПЕН (Ch5-6), но его
нельзя усреднять в STT-сигнал.

## Принятое решение (миксер каналов)

Выбран **п.1 — минимальный фикс** (вместо п.2 «программный AEC вычитанием»):

1. `audio_node` получил параметр `mix_channels` (0-based список каналов для
   усреднения в моно). Пустой список = все каналы (legacy-поведение).
2. В проде задан `channels: 6` + `mix_channels: [0, 1, 2, 3]` — усредняются
   только микрофоны Ch1-4, playback-референс Ch5-6 **исключён** из сигнала.
3. Почему не п.2 (вычитание Ch5/Ch6 из микса): вычитание цифрового референса
   из аналогового микрофонного сигнала требует точной синхронизации по фазе и
   усилению (adaptive filtering). Наивное вычитание может **ухудшить** сигнал.
   п.2 остаётся кандидатом на будущее (полноценный программный AEC), референс
   уже доступен на Ch5-6.

## Телеметрия: честный «замолчал → акцепт»

Раньше `T_accept` считался от «Получена фраза» (уже ПОСЛЕ 3с паузы
`speech_continuation`), т.е. честный «замолчал → акцепт» занижался на
`speech_continuation` (замер: 8.2-8.3с = 3.0с VAD-продолжение + ~5.2с STT).

Теперь в лог пишутся две parseable-строки:

```
# audio_node (включает speech_continuation)
📊 [telemetry] silence_to_phrase_s=3.50 (speech_continuation=3.0)

# stt_node (STT-часть)
📊 [telemetry] phrase_to_accept_ms=1234 (text='робок привет')
```

Полный «замолчал → акцепт» = `silence_to_phrase_s` + `phrase_to_accept_ms/1000`.
Это то, что e2e-процесс должен парсить из `docker logs voice-assistant`.

## Фирмварь (решение задокументировано)

- **Текущий режим: 6-канальный RAW (фабричный)** — аппаратный AEC не
  применяется, но доступен playback-референс для программного AEC (будущее).
- **Альтернатива: 1-канальный firmware** (обработанный чипом, с AEC) — на
  роботе менять прошивку рискованно и теряется raw-доступ. НЕ выбран сейчас;
  решение по прошивке остаётся за ops при следующем обслуживании железа.
