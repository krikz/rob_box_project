# Студия канала @robbox_project — бриф для агента на отдельной машине

> Этот файл — задание целиком. Его отдают агенту (на машине Шифу работает hermes), который **сам себя настраивает**
> и по расписанию готовит материал для канала. Правила ведения канала — [telegram-channel.md](telegram-channel.md),
> общие правила репо — [AGENTS.md](../../AGENTS.md). Карточка — issue #4492.

## Цель

Раз в сутки агент запускает сессию анализа: что изменилось в проекте, какие есть артефакты прогонов, есть ли что
показать. Из этого он готовит **черновик поста** (текст + медиа) и присылает его Шифу в Telegram с кнопками
«Опубликовать» / «Отклонить». Публикует только одобренное, в слоты канала. Ничего не придумывает.

## Что нужно от Шифу перед стартом (секреты — только в `.env` на этой машине)

| Переменная | Что это | Где взять |
|---|---|---|
| `TG_STUDIO_BOT_TOKEN` | токен **отдельного** бота студии | @BotFather → /newbot; бота сделать админом @robbox_project с правом публиковать |
| `TG_SHIFU_CHAT_ID` | чат для черновиков с кнопками | `495039871` (личка Шифу) |
| `TG_CHANNEL_ID` | канал | `-1004323185327` |
| `MINIMAX_API_KEY` | текст (MiniMax-M3) и фоны (image-01) | ключ MiniMax |
| `GH_TOKEN` | чтение GitHub (repo, actions) | fine-grained, **только чтение**: krikz/rob_box_project, krikz/ros2leds, krikz/vesc_nexus |

**Почему отдельный бот:** у одного бота в Telegram может быть только один получатель апдейтов. Токен `@krobbox_bot`
читает робот (`telegram_node`). Если студия будет ловить кнопки тем же ботом, сломается пульт робота.

## Настройка (агент делает сам)

1. `git clone https://github.com/krikz/rob_box_project` (только чтение; изменения — PR в `develop`, мёржит координатор).
2. Python 3.10+, `pip install pillow pyyaml requests`, системный `ffmpeg`.
3. Проверить вхолостую: `python -X utf8 scripts/telegram/channel_post.py --preview-all`,
   `python -X utf8 scripts/telegram/infographic.py --help`.
4. **Первая доработка (PR):** сейчас `channel_post.py` / `channel_setup.py` шлют только через контейнер робота
   (`RobotTransport`, ssh на Sound Pi). Студии робот недоступен — добавить `DirectTransport`: прямые вызовы Bot API
   с токеном из `TG_STUDIO_BOT_TOKEN`, выбор транспорта флагом `--transport direct|robot` (по умолчанию `robot`, как
   сейчас). Тесты с замоканной сетью. Плюс обработчик кнопок (`getUpdates` long-poll только этого бота).
5. Cron (время Шифу GMT+1): анализ `0 3 * * *`; публикатор `0 11 * * 2,4,6` (`channel_post.py --transport direct`).

## Сессия анализа (каждый день)

1. **Что изменилось** с прошлой сессии (метка — в локальном `state.json`):
   - влитые в `develop` PR (`gh pr list --state merged --search "merged:>=<дата>"`): заголовок, тело, изменённые пути;
   - закрытые issue с комментариями-доказательствами (raw, run_id);
   - новые записи в `docs/shifu-decisions.md`, новые ADR в `docs/adr/`;
   - прогоны Actions: `L-E2E Voice Test` (марафон: итог по актам из логов `E2E_SUMMARY`), `L: Build All Services`,
     `L: Deploy and Verify`; артефакты (`gh run download`) — только итоговые цифры, не персональные данные;
   - новые медиа в репо: `docs/assets/hil/`, `docs/assets/animations/`, `docs/channel/media/`, ролики HIL.
2. **Есть ли что показать** — решает код по правилам: видимые изменения (навигация, лицо и LED, защита, музыка,
   голос, симуляция) или новая цифра с источником. Нечего — сессия пишет «материала нет» в лог и заканчивается.
3. **Факты** — список `{утверждение, число?, источник}`; источник обязателен (PR, issue, run_id, файл:строка).
4. **Текст** — MiniMax-M3 получает **только** факты + `telegram-channel.md` (тон, теги, лимиты, приватность) и
   возвращает строго `{"title", "body_html", "tags": [...], "media_ref"}`. Thinking выключен
   (`"thinking": {"type": "disabled"}`), иначе в ответ попадёт `<think>…`.
5. **Проверка кодом** (ADR-0148, модель не решает): каждое число и имя собственное в тексте есть среди фактов;
   `channel_lib.validate` (лимиты, HTML, теги из словаря); ни одного лица человека, внутреннего IP, ключа.
   Не прошло — один повтор с причиной, потом черновик отбрасывается с записью в лог.
6. **Медиа**: цифры → `scripts/telegram/infographic.py` (фон — `channel_bg.py`, MiniMax image-01, кэш); готовые GIF/MP4
   из репо как есть. Сгенерированные картинки — **только фон**, без «фото робота».
7. **Черновик Шифу**: пост целиком в личку с кнопками «Опубликовать» / «Отклонить». Одобренный — в локальную очередь
   со статусом `approved` и ближайшим слотом; отклонённый — в архив с причиной.

## Публикация

`channel_post.py --transport direct`: один одобренный пост за слот (вт/чт/сб 11:00 GMT+1), не чаще раза в 48 ч.
После публикации — `message_id` в `state.json`; раз в неделю PR в репо со статусами (`docs/channel/queue/`), чтобы
история канала жила в репо.

## Чего не делать

- Не публиковать без кнопки Шифу. Не править закреп и оформление канала без отдельного «да».
- Не трогать робота (ssh, HIL, деплой) — у студии нет доступа и не должно быть. Ролики HIL и живые съёмки — этап 2
  (#4492), только по отдельному решению.
- Не придумывать факты, не округлять красное в зелёное. Красный тест называем красным.
- Не публиковать людей мастерской (лица, голоса, имена), внутренние адреса, ключи, номера карточек с персональными данными.
- Ключи не печатать в логи.

## Проверка, что всё работает

1. `--dry-run` сессии анализа на прошлой неделе даёт ≥ 1 черновик, у каждого числа есть источник.
2. Черновик приходит Шифу с кнопками; «Отклонить» — пост не публикуется; «Опубликовать» — пост выходит в ближайший слот.
3. Логи сессий: дата, что найдено, сколько черновиков, причины отказов.
