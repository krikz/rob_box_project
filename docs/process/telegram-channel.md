# Telegram-канал @robbox_project — как вести

Канал: https://t.me/robbox_project, chat_id `-1004323185327`. Администратор — бот робота `@krobbox_bot`
(права: смена данных канала, публикация, правка и удаление сообщений). Владелец и финальный арбитр — товарищ Шифу.
Это дневник проекта для внешних читателей, а не пульт оператора (пульт — личный чат бота, `scripts/robot_dev/tgsend.sh`).

## Голос и тон

- Говорим просто, как мастер, показывающий мастерскую: короткие абзацы, глагол впереди, без канцелярита и рекламы.
- «Мы» и «РОББОКС». Не «наш революционный робот», не восклицательные знаки подряд, не «скоро будет уметь всё».
- Школьный дух допустим, но в меру: Шифу называем «Шифу», иероглифы не вставляем.
- Пост — один тезис. Длина: подпись ≤ 1024 знаков (лимит Telegram для медиа), текст без медиа ≤ 4096; цель 400–700.
- Язык — русский, технические имена (Nav2, RTAB-Map, ADR-0148) как есть.

## Чего в посте не пишем (решение Шифу 07.11.2026)

Канал — про поведение робота. Внутренняя кухня проекта в постах не пишется:

- **номера PR и issue** (`PR #4503`, `#4495`, ссылки на `github.com/…/pull/…`);
- **имена веток** (`develop`, `z-architect/…`) и слова «ветка develop»;
- **типы коммитов** (`fix(dialog)`, `feat(nav):`) — это заголовок коммита, не слово для читателя;
- **файлы и пути репозитория** (`patch_rtabmap_launch.py`, `rtabmap.ini`,
  `docs/…`, `scripts/…`).

Проверяет код: `channel_lib.POST_FORBIDDEN` (приватность + `FORBIDDEN_INTERNAL`) — студия не даст
модели это написать, публикатор не пропустит. Ответы студии Шифу в личке номера PR называть могут.
Свои правила к постам Шифу пишет студии словами («в постах не пиши про …») — их хранит код
(`studio_rules`, `state.rules`) и кладёт в задание каждого текста поста. Пишем о том, что изменилось для робота и
для читателя: «робот перестал говорить „приехал“, когда потерял опору», а не
«в `develop` влили PR #4502».

## Требования Telegram (проверено 06.11.2026, Bot API 10.3)

Источники: [Bot API](https://core.telegram.org/bots/api), [changelog](https://core.telegram.org/bots/api-changelog),
раздел «Formatting options» там же. Страницы [telegram.org/tips/channels](https://telegram.org/tips/channels)
совет по каналам не дали (в тексте — только общие ссылки), `faq_channels` и [api/entities](https://core.telegram.org/api/entities) не сверялись:
**не проверено**, поэтому на них правил не строим.

**Знаем, но не берём (и почему):**

- `show_caption_above_media` (sendPhoto/editMessageCaption) — поддержан в `StudioBot.send_media(above=True)`, но
  по умолчанию выключен: подпись под картинкой привычнее для ленты канала.
- `message_effect_id` — «for private chats only»: в канале не работает, в личке Шифу эффект не нужен.
- `style` у кнопок (`danger`/`success`/`primary`, 9.4) и `disabled` (10.3) — не проверяли вживую в клиенте Шифу, не берём.
- `tg-emoji` (custom emoji) — по документации только боты с купленным на Fragment именем или в личке, если у
  владельца бота Premium. У бота студии этого нет.
- `<tg-time>` / сущность `date_time` (9.5) — валидатор канала (`channel_lib.ALLOWED_TAGS`) этот тег пока не знает;
  добавлять — отдельной правкой с тестом.
- `sendMessageDraft` (стрим черновика, 9.5+; «temporary 30-second preview», только личный чат) — индикатор должен
  оставаться в чате как журнал шагов, поэтому берём обычное сообщение с правкой.
- `sendRichMessage` / `InputRichMessage` (10.1–10.3) — новый блочный формат. Публикатор канала и валидатор работают
  с HTML; переход — отдельное решение, в этом PR не делается.
- `sendMediaGroup` — используется публикатором для постов с `extra_media`; у черновика студии одно медиа: альбом
  нельзя снабдить inline-кнопками.
- Ephemeral messages и Communities (10.2–10.3) — про группы, к каналу и личке не относятся.

## Отложенные посты

В Bot API **нет отложенной отправки**: в `sendMessage`, `sendPhoto`, `sendAnimation` (10.3) нет `schedule_date`, а в changelog
слово «scheduled» встречается только у розыгрышей и перекодирования видео. Встроенные отложенные посты есть у пользовательских
аккаунтов (приложение, MTProto). Входить в аккаунт Шифу (userbot) нельзя, поэтому два пути:

1. **Наш планировщик** `channel_post.py` — по `not_before` и интервалу 48 ч (по умолчанию).
2. **Заготовка для Шифу**: `channel_post.py --send-draft N` присылает в личку Шифу пост N целиком (тот же текст в той же
   разметке и тот же файл), а Шифу пересылает его в канал со скрытым именем отправителя и ставит время: долгий тап по кнопке
   отправки → «Отправить позже». Путь не проверялся в приложении; координатор после «поставил» меняет статус на `posted`.

## Частота

Не чаще 3 постов в неделю: вторник, четверг, суббота в 11:00 по GMT+1 (в файле очереди `not_before` — 10:00 UTC).
Между публикациями не меньше 48 часов (проверяет `channel_post.py`). Нет материала — пропускаем слот, пустой пост не делаем.

## Хэштеги

В конце поста от 2 до 4 тегов, только из словаря ниже. Теги поста перечислены в `hashtags` front matter и должны совпадать
с последней строкой текста. `channel_lib.validate` проверяет: тег есть в словаре, число 2–4, в тексте нет лишних тегов.
Новый тег — сначала сюда и в `TAG_DICTIONARY` в `scripts/telegram/channel_lib.py`.

**Тематические** (о чём): `#роббокс` (бренд, в закрепе), `#навигация`, `#симуляция`, `#железо`, `#светодиоды`, `#голос`,
`#музыка`, `#безопасность`, `#тесты`, `#opensource`, `#ros2`, `#raspberrypi`, `#люди`.

**Рубрики** (как читать, по ним удобно листать ленту): `#дневник` (что делали и что вышло), `#какэтоработает`
(устройство без воды), `#цифры` (замеры с источником), `#честность` (красное, оговорки, отказ от красивого счёта).
Одной рубрики на пост достаточно.

## Правило честности

Продолжение «Честный FAIL лучше красивого PASS» (AGENTS.md, ADR-0018).

1. Публикуем только то, что проверено и лежит в репо: влитой PR, ADR, запись в `docs/shifu-decisions.md`, замер с выводом.
2. Красное называем красным. Упал марафон, откатили фикс, проверка на роботе не сделана — пишем так.
3. Помечаем, откуда цифра: симулятор или настоящий робот. Результат в симуляторе не выдаём за результат на роботе.
4. План не выдаём за факт. «В плане», «кода нет», «ещё не гоняли» — нормальные слова.
5. Не пишем числа «N из M» без источника: файл репо, карточка или run_id. Пример: счёт марафона «120/132» не подтвердился в карточках #4478–#4481, поэтому в посте 008 — только описание сценария и честный статус «красный».
6. Иллюстрацию называем иллюстрацией (например, анимация набора 381 светодиода — не запись панелей).
7. В карточке поста, при сомнении, — ссылка на ADR или файл в репо.

## Приватность

- Никаких людей: ни фото, ни лиц, ни скриншотов с лицами, ни имён и голосов, ни записей с микрофона. Клички и профили реальных людей не публикуем,
  даже без фото.
- Никаких внутренних адресов и ключей: IP сети робота (`10.1.1.*`, `192.168.*`), токены, пароли, chat_id личных чатов,
  имена хостов. `channel_lib.validate` блокирует IP и токены, но глаза тоже включаем.
- Номера карточек и PR в посте не пишем (решение Шифу 07.11, раздел «Чего в посте не пишем»). Логи и скриншоты чистим до публикации.
- Аватар, обложки и GIF — только из репо (собственные материалы проекта).

## Процесс: черновик → одобрение Шифу → очередь → публикация

1. **Черновик.** Шиди или координатор пишет `docs/channel/queue/NNN-slug.md` со `status: draft` в PR.
   Front matter: `status`, `media` (путь от корня репо или пусто), `not_before` (ISO, UTC), `message_id`, `posted_at`, `hashtags`.
   Проверка: `python -X utf8 scripts/telegram/channel_post.py --preview-all` печатает все посты как они уйдут.
2. **Одобрение.** Шифу читает текст и смотрит медиа. Одобрил — координатор ставит `status: approved` (и при необходимости
   двигает `not_before`). Без «да» Шифу пост остаётся `draft`.
3. **Очередь.** Планировщик берёт первый по номеру `approved`-пост, у которого `not_before` наступил, если с прошлой
   публикации прошло ≥ 48 ч.
4. **Публикация.** `python -X utf8 scripts/telegram/channel_post.py` (`--dry-run` — только показать). Скрипт шлёт
   через контейнер `telegram-bot` на Sound Pi (токен остаётся в контейнере), записывает `status: posted`, `message_id`,
   `posted_at`. Правку файла координатор коммитит PR-ом. Проверка живьём: открыть пост в канале, убедиться, что медиа и разметка целы.
   **Разовое наполнение пустого канала:** `channel_post.py --backfill` (`--dry-run` — показать) публикует все `approved` подряд
   по номеру (от знакомства к свежему) с паузой 20 с, без правила 48 ч и без `not_before`. Сначала проверяются все посты:
   хоть один с проблемой — не уходит ничего. Закреп (001) публикует `channel_setup.py`, поэтому его запускают до `--backfill`
   (пост 001 после этого `posted` и в наполнение не попадает). Для обычной жизни канала `--backfill` не нужен: после него
   `posted_at` стоит «сейчас», и обычный планировщик ждёт 48 ч.
5. **Сторис для воронки (для важного поста, например HIL-ролика).** После публикации подготовить набор для личной сторис Шифу:
   `python -X utf8 scripts/telegram/make_story.py --out docs/channel/media/stories --video ролик.mp4 --start N --duration 20`
   даёт `story.mp4` 1080×1920 (15–30 с) и `story-static.png`; внизу ~420 px свободны под стикер-ссылку. Ссылка в стикере —
   `https://t.me/robbox_project/<message_id>` (номер из front matter поста; до публикации — ссылка на канал).
   Видео тяжелее ~15 МБ в репо не кладём. Публикует сам Шифу из своего аккаунта, бот сторис не трогает. Подсказка и подпись — `docs/channel/media/stories/story-kit.md`.
6. **Ошибка в опубликованном.** Правим пост (`editMessageText`/`editMessageCaption`) или удаляем и публикуем заново; факт правки пишем в PR.

## Подготовка материала — каждый день (ADR-0170, #4700)

Студия готовит материал **каждый день, пока есть логи**. Ограничение 48 ч —
это про **доставку** черновика Шифу и про **выход в канал**, а не про подготовку:

- **Подготовка** (`studio_session.sh`, ежедневно в 02:00): собирает факты
  (влитые PR, закрытые issue, прогоны, новые файлы), готовит черновик.
  Фильтра «не чаще 48 ч» перед сбором фактов больше нет — раньше он стоял
  именно там, и студия молчала с 09.11 (сессии 10, 11 и 12.11 вышли, не
  собрав ни одного факта).
- **Доставка** Шифу — не чаще раза в 48 ч (метка `last_delivery` в `state.json`),
  чтобы личный чат не превращался в ленту.
- **Выход в канал** — не чаще раза в 48 ч (`channel_lib.MIN_GAP`). Это правило
  публикатора, оно не связано с подготовкой.

### Молчание — не отказ

Черновик без ответа живёт 48 ч (`studio_state.DRAFT_TTL_HOURS`). Потом он
становится `expired`, его факт возвращается в `pending`, и следующая сессия
собирает по нему свежий черновик.

- **Отказ** — только явный: кнопка «Мимо» (`mark_rejected`). Отклонённый факт
  больше не предлагается.
- **Игнор** (товарищ Шифу не ответил) — не отказ: событие возвращается в ленту.
  Раньше три показа считались отказом, и факт `pr:4555` потерялся.
- Нажатие на кнопку протухшего черновика даёт понятный ответ («протух,
  материал вернулся в очередь»), а не ошибку.

Факт, потерянный вместе с черновиком, восстанавливается из GitHub
(`studio_facts.refetch_fact_by_key`).

**Решение Шифа от 06.11 сохранено:** публикация — только после кнопки.
Одобрение остаётся единственным путём в очередь канала.

## Единый стиль картинок и инфографика

Все картинки канала (аватар, обложки, карточки, инфографика) рисуются в одном стиле — по аватару:

- **Подложка:** тёмный фон `#0A0A0F`, поверх скруглённая панель `#181A21` (радиус 28 px, поля 40 px).
- **Светодиодная полоска** над заголовком: точки 14 px через 27 px, цикл радуги из аватара
  (`#A800FF #FF008C #FF4614 #FFC800 #78FF00 #00E6C8 #145AFF`), каждая третья погашена.
- **Цвета:** акцент и «хорошо» — зелёный `#4ADE80`, схемы — голубой `#22D3EE`, «красное» — `#F87171`,
  основной текст `#EBEEF5`, второстепенный `#78808C`.
- **Шрифт:** PT Sans Bold из репо (`assets/fonts/PTSans-Bold.ttf`, SIL OFL, лицензия рядом; системные Segoe/Arial/DejaVu — только при `CHANNEL_SYSTEM_FONT=1`). Заголовок 40 px, крупные числа 68–92 px, подписи 22–24 px.
- **Подвал:** слева «Источник: …» (файл или issue, 17 px), справа зелёное «РОББОКС».
- **Размеры:** `card` 1000×560 (по умолчанию), `wide` 1280×720; GIF ≤ 2 МБ. Аватар 640×640 с безопасной зоной в круге.
- Анимация (подход vizavi-motion: собственный таймлайн, без внешних движков): элементы появляются по очереди, последний кадр держится 2–2.5 с.

Генератор: `scripts/telegram/infographic.py <данные.json|yaml> <выход.png> [--size wide] [--gif]`. Примеры данных —
`docs/channel/infographics/`. Шаблоны (`template` в данных):

| template | Что | Данные |
|---|---|---|
| `numbers` | 2–4 крупных числа с подписями | `items: [{value, label, source}]` |
| `table` | таблица результатов, до 7 строк | `columns`, `rows` (ячейка — строка или `{text, status: ok/fail}`), `source` |
| `nodes` | схема узлов (3 Pi и что на каком) | `nodes: [{name, role, items}]`, `source` |
| `before_after` | было → стало или цель → факт | `pairs: [{label, before, after, status, note, source}]` |
| `timeline` | таймлайн недели (влитые фичи) | `events: [{date, text, source}]` |

Общие поля: `title`, `subtitle`. **У каждой цифры есть `source`** (файл репо с разделом или issue); без него генератор
отказывается рисовать (`SpecError`). Источник печатается в подвале картинки. Числа берём из репо и прогонов, на память не вписываем:
источник может быть и карточкой: «57–64 → 25 сообщений/с» и «CPU 25–28 %» для лица взяты из комментариев issue #3733 (с оговоркой оттуда же о разбросе между днями).

### Подложки MiniMax (сгенерированные иллюстрации, только фон)

Поле `background: {slug, prompt, seed?}` в JSON инфографики (и `CARD_BACKGROUNDS` у карточек) даёт подложку под тему поста.
MiniMax `image-01` (`POST https://api.minimax.io/v1/image_generation`, `aspect_ratio` 16:9, prompt ≤ 1500 знаков, 0.0035 $ за
картинку; документация platform.minimax.io, проверено 06.11.2026). Вызов идёт из контейнера `telegram-bot` на Sound Pi
(`image_exec.py`), ключ `MINIMAX_API_KEY` остаётся в окружении контейнера. Код: `scripts/telegram/channel_bg.py`.

- **Сгенерированная иллюстрация только фон.** Абстракция или тема (склад, светодиоды, карта, звук, двери). Никакого
  фотореалистичного «нашего робота»: он вводил бы в заблуждение. Если робот в кадре, то стилизованный и явно рисунок.
- В запрос добавляется «no text, no letters, no logos»; после генерации смотрим глазами, если буквы всё же появились, перегенерируем (другой `seed`).
- Подложка размывается и затемняется (средняя яркость ≤ 52 из 255), текст и цифры поверх рисует код.
- Кэш: `docs/channel/media/bg/<slug>.jpg`, ≤ 300 КБ. Есть файл: API не зовётся. Новая подложка: новый `slug` или удалить файл.

## Оформление канала

Название, описание, аватар и закреп — `docs/channel/profile.md` и пост 001. Применяет `scripts/telegram/channel_setup.py`
(`--dry-run` — показать; боевой запуск только с `--shifu-approved` после «да» Шифу). Аватар 640×640, содержимое вписано в круг.
Менять оформление без одобрения Шифу нельзя.
