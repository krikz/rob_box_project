## 2. Как попасть на робота

Прямой SSH на `10.1.1.21` то работает, то нет. Надёжный путь — через катану:

```
paramiko → ros2@ros2-katana-gf66-11ud (пароль open)
  → sshpass -p open ssh ros2@10.1.1.21
```

Готовые скрипты (`k.py` + `v.sh`) лежат в scratchpad-каталогах сессий; проще
написать заново, они на десять строк.

**Обязательно `PYTHONIOENCODING=utf-8`.** Без него всё молча ломается: в логах
робота есть эмодзи, они не лезут в cp1252, скрипт падает — и запрос выглядит
как «пустой ответ». Я на этом потерял час, считая, что команда не отработала.

Контейнеры: `voice-assistant` (sclang, mcp_server, диалог) и `supercollider`
(jackd + scsynth). Это ДВА РАЗНЫХ контейнера, и половина сложностей отсюда.

## 3. Главный метод: спрашивать сервер, а не логи

Почти все ложные следы в этом расследовании возникли из-за доверия к логам.
Контейнеры `healthy`, инструмент рапортует «выполнено успешно», в логе лежит
корректный код композиции — и тишина.

Работает только прямой опрос scsynth по OSC на `127.0.0.1:57110`:

* **`/status`** → `numUGens`, `numSynths`, `numGroups`, `numSynthDefs`, CPU.
  «Играет ли музыка» определяется отсюда, а не по логам. Один синт при
  «играющей» аранжировке из пяти слоёв — это диагноз.
* **`/g_dumpTree 0 1`** → дерево нод с значениями контролов, печатается в лог
  контейнера `supercollider`. Видно порядок нод и реальные параметры.
* **`/s_new <имя>`** в группу 0 → проверка, есть ли SynthDef на сервере.
* **`CheckBadValues`** в тестовом SynthDef → ловит NaN на шине.
* **Измеритель уровня** (`SendReply` + `Amplitude`) → объективный ответ на
  «слышно или нет», без ушей. Стоит собрать заново, если понадобится: он
  один раз прекратил многочасовой спор за минуту.

### Ловушка OSC, на которой я обжёгся

Строка OSC обязана иметь **минимум один нулевой терминатор** и длину, кратную
четырём. Наивное `(4 - len(b) % 4) % 4` даёт **ноль** добивки для строк длиной
4, 8, 12 — сообщение уходит без терминатора и разбирается со сдвигом.

```python
def osc_string(s):
    b = s.encode() + b"\x00"
    while len(b) % 4:
        b += b"\x00"
    return b
```

Симптом: `/n_set` с тегом `,isf` приезжает как `Node 1065353216 not found` —
это float 1.0, прочитанный как int32. Из-за этого бага один мой эксперимент
по перебору ступеней лимитера дал полностью недействительный результат, и я
почти сделал на его основе вывод.

## 5. Музыкальные факты, добытые опытом

* **`-` — это ЗВУЧАЩИЙ сэмпл** (hyphen, каталог `samples/*/_/hyphen`), а не
  пауза. Пауза — `.`, каталога для неё нет ни в одном паке. На этом ошиблись
  дважды: агент добивал рисунок дефисами, и отдельно `_prewarm_sample_buffers`
  пропускал `-` как «паузу» (#1815).
* **scsynth работает на 16 кГц**, Найквист 8 кГц. Высокие октавы и дисторшн
  дают алиасинг — тот самый «свист». Потолок октав в `_cap_amp` **связан** с
  наличием анти-алиасингового фильтра на мастер-шине: снимете фильтр —
  опускайте потолок, иначе робот засвистит.
* **Звучат только `d1`–`d3` и `p1`–`p3`.** Остальное создаётся молча и не
  играет.
* **Renardo шлёт OSC fire-and-forget** и ответы не читает (в `OSCClient` есть
  только `sendall`). Поэтому отказы сервера исторически были невидимы.
* **Длина барабанного рисунка задаёт его период.** Не делит такт — слои
  расходятся по фазе на каждом повторе. Модель символы не считает и не
  научится, это работа кода.
* **Регистры важнее числа слоёв.** Если бас, пэд и мелодия сходятся в одну
  октаву, микс слышится как одна дорожка, сколько бы слоёв в нём ни было.
  Развитие материала должно это уважать: транспозиция и инверсия — приёмы для
  темы, а не для баса и аккордовой подкладки.
