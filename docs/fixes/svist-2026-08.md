## 3. Корень проблемы (гипотеза)

После `a8d9ab9a` (06.08 15:44) `MusicManager.execute_code` (и `stop_all`) **рубят sustained-ноты через hard `/g_freeAll` без ramp-down**. Цепочка:

```
dialogue_node.__init__ → создаёт publisher /mcp/music_cleanup
                  ↓
первый wake-word → was_idle=True → _publish_music_cleanup(reason="new_dialogue")
                  ↓
mcp_server получает /mcp/music_cleanup → stop_all() в MusicManager
                  ↓
 1. exec("d1.stop() ... d9.stop()")        — Renardo Player.stop() OK
 2. exec("Clock.clear()")                   — Renardo Clock.clear() OK
 3. time.sleep(0.05)                        — release ADSR
 4. /g_freeAll 1                            — scsynth убивает все ноды в Group 1
                                              ⚠️ НО: orphan-синты в Group 0 не тронуты
                                              ⚠️ sustained-ноты с sus=inf — играют вечно
                  ↓
 5. /g_new 1 0 0                            — пересоздание Group 1
                  ↓
В окне между (4) и (5) Renardo Player шлёт /s_new с target_id=1
                  ↓
synth попадает в фантомную группу / не имеет владельца
                  ↓
synth продолжает играть (JACK connection jack:out_1 → dmix_respeaker → speaker)
                  ↓
свист
```

**Гипотеза orphan-сценария**: даже после `/g_freeAll 1` sustained-синт (drone, pad), у которого ADSR `sus=inf`, **не глушится** — `gate` остаётся `1`. `Clock.clear()` в Renardo не посылает `/n_set gate=0` в scsynth (это известно из raw кода `music.py:903-904`).

**Гипотеза фантомного `/s_new`**: даже при `-l 32` на 32-м подключении (для клиента renardo) может быть race, когда `/s_new` прилетает в окно между `/g_freeAll` и `/g_new`. Синт создаётся в default group, не имеет parent — неуправляем.

**Гипотеза JACK sustained**: hard `/g_freeAll` без `gate=0` — это как «рубить провод под напряжением». Физические модели (MdaPiano, rhpiano) оставляют короткий ВЧ-всплеск, который JACK воспринимает как постоянный сигнал (jack_port не отключается даже если node умер — audio thread продолжает читать буфер).

## 5. Фикс — `f9f9057b`-smooth-stop восстановлен через OSC `/n_set`

### 5.1. Принцип

Использовать **OSC** `/n_set gate 0 -1 0` напрямую в scsynth, **минуя** Renardo `Player.__setattr__` (который оборачивает в `asStream()` и ломает).

OSC-пакет:

```
/n_set\x00\x00    ← address (8 байт, padded)
/n_set            ← ASCII command
,isf\x00\x00      ← type tag: int, string, float (padded)
-1                ← node ID -1 = все ноды
gate\x00\x00\x00\x00  ← parameter name (8 байт)
0.0               ← value = 0 → release ADSR
```

### 5.2. Изменения в коде

**Файл:** `src/rob_box_mcp_tools/rob_box_mcp_tools/tools/music.py`

1. Добавить helper `MusicManager._send_gate_zero_all(self)` — отправляет OSC `/n_set gate 0 -1 0` через `_send_osc_raw`-подобный сокет.

2. **Восстановить в `execute_code`** (между `exec(code)` и `/g_freeAll`) **gate=0 ramp**, **ПЕРЕД** sleep+freeAll:

   ```python
   if has_clock_clear:
       # Плавный gate=0 ramp (issue #1363 follow-up): без этого sustained-ноты
       # (drone/pad) не глушатся → orphan-синты в JACK → свист.
       try:
           self._send_gate_zero_all()
       except Exception:
           pass
       try:
           self._send_osc_raw("/g_freeAll", 1)
       except Exception:
           pass
       try:
           time.sleep(0.05)
       except Exception:
           pass
       try:
           self._send_osc_raw("/g_new", 1, 0, 0)
       except Exception:
           pass
   ```

3. **Восстановить в `stop_all`** gate=0 ramp **ПЕРЕД** sleep:

   ```python
   # Шаг 3.5: gate=0 на все ноды через OSC (issue #1363 follow-up).
   # Не через Player.amp = 0 — это ломает Renardo Player.__setattr__
   # (KeyError 'amp' от PGroup-обёртки, см. a8d9ab9a).
   try:
       self._send_gate_zero_all()
   except Exception:
       pass
   try:
       time.sleep(0.05)
   except Exception:
       pass
   try:
       self._send_osc_raw("/g_freeAll", 1)
   except Exception:
       pass
   ```

### 5.3. Почему это правильно

- **gate=0 — стандартный SC-параметр**, есть во всех SynthDef-ах renardo (иначе они бы не играли долгие ноты).
- **OSC `/n_set` не проходит через Renardo Python-API** — `Player.__setattr__` нас не касается.
- **ADSR release делает всю работу**: `gate=0` запускает release-фазу, синт затухает за ~50ms естественно, без кликов и без «рубки провода».
- **Совместимо с Renardo Player.stop()**: Renardo Player при `stop()` шлёт `/n_set gate=0` сам для своих нод. OSC-broadcast на `-1` добивает чужие ноды (например, созданные через raw `/s_new`).
- **`-l 32` остаётся** — это правильно, но **недостаточно**. smooth-stop закрывает оставшиеся сценарии.

### 5.4. Альтернативы (отклонены)

| Вариант | Почему отклонён |
|---|---|
| Только `-l 32` | Не убирает orphan-синты, свист остаётся |
| `Player.amp = 0` через try/except | Не работает: Renardo `__setattr__` ломает до того, как Renardo-обёртка запускается |
| `/g_freeAll 0` (default group) | Убивает всё, включая эффекты (reverb/volume) — нет decay, сухой сигнал |
| Использовать Renardo `Player.stop()` для всех | Не добивает «чужие» ноды (от raw `/s_new`, от DJ-сессий) |
