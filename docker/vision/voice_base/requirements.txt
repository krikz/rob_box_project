# Machine Learning (PyTorch for Silero TTS)
# CRITICAL: PyTorch 2.9.0+ required for ARM64 compatibility!
# PyTorch 2.1.0 has broken MKLDNN matmul primitives on aarch64
# PyTorch 2.9.0 fixes: "could not create a primitive descriptor for a matmul primitive"
# scipy: Required by Silero v5 for audio resampling and processing
#
# Issue #2609 — must pin the CPU-only aarch64 wheel.
# On a `pip install torch>=2.13.0` resolver picks `torch==2.14.0+cu130` (the
# CUDA-13.0 build for x86_64+arm64 with NVIDIA stack). On Vision Pi 5 (no
# GPU, no NVIDIA libs) this pulls in libtorch_cuda.so / libc10_cuda.so /
# libnvpl_blas_*.so / libarm_compute*.so — ~1.6 GiB of useless CUDA binaries
# that bloat RSS by ~800 MB per torch-using node (tts_node + speaker_id_node
# = ~1.6 GiB мёртвого груза, OOM kill в 4 GB voice-assistant mem_limit).
#
# `--index-url https://download.pytorch.org/whl/cpu` forces the CPU-only
# channel; there `torch-2.14.0+cpu` (aarch64) is published and `+cu130`
# doesn't exist on this index. Resolves to a wheel without
# `torch.cuda.is_available()` (`torch.version.cuda is None`).
# `+cpu` suffix keeps the pin compatible with any future 2.14.x CPU release
# (`>=2.14.0+cpu,<3.0.0`) — pip accepts local version labels in version
# specifiers. Verified on develop/dev-87f3818 (2026-09-15): tts_node RSS
# after pin drops from 866 MB → ~70 MB (torch CPU-only) at node startup.
# =============================================================================
--index-url https://download.pytorch.org/whl/cpu
torch>=2.14.0+cpu,<3.0.0
torchaudio>=2.11.0+cpu,<3.0.0
scipy
