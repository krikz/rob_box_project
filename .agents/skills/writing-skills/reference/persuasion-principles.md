# Persuasion Principles For Discipline Skills

Load this file when strengthening a skill against rationalization.

This is a local working note, not a formal literature review.

## Why this matters

A discipline skill often fails not because the rule is absent, but because the agent finds a plausible excuse to bend it.

## Useful principles

### Authority
State the rule plainly and early. Make it sound mandatory, not optional.

### Commitment
Require an explicit sequence or checkpoint so the agent commits to the workflow.

### Consistency
Connect the rule to existing standards already accepted elsewhere in the skill.

### Scarcity
Show what is lost when the shortcut is taken: trust, verification, reproducibility, or debugging signal.

### Social proof
Use only sparingly. Prefer concrete prior failure modes over vague claims that "everyone does this".

### Unity
Frame the rule as part of the team or project operating model, not a personal preference.

## Practical use

- turn vague advice into explicit prohibitions
- name common excuses in a rationalization table
- add red flags that signal the agent is about to violate the rule
- explain why the shortcut is attractive and still wrong
